# 控制器视图

基础控制器通过 `Assign`、`View` 和 `Fetch` 管理当前控制器实例的视图数据。模板根目录、模板函数和路径安全由[模板章节](../模板/README.md)文档负责。

## Assign

```go
func (c *User) Page() string {
	c.Assign("title", "用户列表")
	c.Assign("count", 10)
	return c.Fetch("user/index")
}
```

`Assign` 把值写入当前控制器实例的视图数据 map。框架按请求创建控制器并在首次赋值时初始化该 map，数据不会跨请求共享。

控制器实例还可以通过 `c.RequestCache()` 获取绑定当前请求 Debug collector 的缓存 facade。它共享底层 store 生命周期，但不会把缓存记录写入其它请求；不要把该 facade 或当前请求对象保存到控制器包级变量。

## View 与 Fetch

`Fetch` 是 `View` 的别名，两者都可以传入一个局部数据 map：

```go
return c.View("user/detail", map[string]interface{}{
	"name": "张三",
})
```

渲染时先复制控制器通过 `Assign` 写入的数据，再合并局部 map；同名局部值覆盖控制器值。调用方的 map 不会被框架合并过程改写。

## 渲染失败

控制器方法返回字符串，因此可以直接把视图内容作为动作响应。模板驱动未配置、模板不存在、模板路径非法或执行失败时，`View` 会把详细错误写入应用日志，并返回固定的通用错误文本，不会向客户端暴露模板路径和内部错误。

需要区分渲染错误时，应通过 `c.App.View()` 直接使用 `Render` 或 `Fetch` 并处理返回的 `error`；控制器便捷方法本身不会返回错误。

需要把模板加载记录归入当前请求 Trace 时，使用 `c.App.View()` 调用 `RenderWithDebug` 或 `FetchWithDebug`，显式传入请求 collector；不要依赖共享 View 上的全局 Debug 状态。

## 多语言模板函数

应用初始化时会向默认 Go 模板驱动注册 `lang` 函数：

```html
<h1>{{ lang "auth.login_success" }}</h1>
```

该默认函数调用 `c.App.Lang().Get(key, nil, "")`，使用语言管理器的当前语言，不接收请求对象。需要严格按当前请求语言翻译时，应在控制器中使用 `c.Lang`，或显式把翻译结果放入模板数据。
