# 控制器动作

动作是控制器上供路由调用的导出方法。显式路由处理器使用 ThinkPHP 的 `controller/action` 写法；自动路由是否启用由路由配置控制，具体规则见[路由章节](../路由/README.md)。

## 参数签名

动作除接收者外只能有以下两种签名：

```go
func (c *User) Index() string

func (c *User) Detail(req *context.Request) *context.Response
```

动作不能是可变参数，不能接收其它请求参数，也不能超过两个返回值。HTTP 内核在调用前检查签名，非法签名返回 500，不会把反射 panic 暴露给客户端。

## 返回值转换

动作返回值会转换为 `*context.Response`：

| 动作返回形式 | 转换结果 |
|---|---|
| 无返回值 | 空的 200 响应 |
| `*context.Response` | 原样使用；`nil` 指针转换为空的 200 响应 |
| `context.Response` | 取地址后使用 |
| `string` | 文本响应 |
| 其它值 | JSON 响应 |
| 单个 `error` | `nil` 为空的 200 响应，非 `nil` 为内部错误 |
| `(value, error)` | 错误为空时转换 `value`，错误非空时为内部错误 |

```go
func (c *User) Detail(req *context.Request) *context.Response {
	return c.Success(map[string]interface{}{
		"id": req.ParamInt64("id", 0),
	})
}

func (c *User) Save(req *context.Request) (*context.Response, error) {
	if !req.Has("name") {
		return nil, errors.New(c.Lang("validate.default.required", map[string]interface{}{"field": "name"}))
	}
	return c.Success(nil), nil
}
```

动作返回结构化数据时，HTTP 内核调用 `Response.Json`；序列化失败由响应对象记录并转换为 500。动作自身不应直接向响应写入底层 `http.ResponseWriter`。

## 调用顺序与缓存

控制器动作的执行顺序是：

1. 从容器创建控制器实例。
2. 在内核内部注入当前 App 与 Request。
3. 校验并执行 `Initialize`。
4. 解析控制器级中间件。
5. 执行动作。
6. 将动作结果转换为响应。

控制器动作的反射签名计划会按处理器名称缓存；控制器类型变化时会重新生成。缓存只保存方法元数据，不保存控制器实例或请求数据。

## 错误与自动路由边界

生产环境遇到控制器解析失败、`Initialize` 签名错误、动作错误或返回值签名错误时，客户端只得到通用 500，详细错误写入应用日志。开启 debug 时才会在响应中显示内部错误信息。

自动路由不会把嵌入基础控制器的 `Initialize`、`View`、`Fetch`、`Success`、`Error`、`Result`、`Redirect`、`Validate`、`Assign`、`SetMiddleware`、`GetMiddleware` 等方法作为端点；显式路由仍应只指向业务动作。业务控制器自己声明的 `Init` 只是普通动作，不承担框架注入职责。
