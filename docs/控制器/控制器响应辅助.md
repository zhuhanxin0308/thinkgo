# 控制器响应辅助

`framework.Controller` 提供四个用于生成统一响应的便捷方法。它们只构造 `*context.Response`，最终发送仍由 HTTP 内核完成。

## Success

```go
return c.Success(data)
return c.Success(data, "保存成功")
```

`Success` 固定使用 `code=0`。未提供消息时使用英文字符串 `success`，只读取第一个可选消息参数。

## Error

```go
return c.Error("参数错误")
return c.Error("参数错误", 422)
```

`Error` 的 `data` 固定为 `nil`，默认 `code=1`；提供状态码参数时只读取第一个值。这个 `code` 是业务 JSON 字段，不是 HTTP 状态码。需要设置 HTTP 状态时，应继续对返回响应调用 `Code`，或使用应用层统一错误响应。

## Result

```go
return c.Result(data, 0, "success")
```

`Result` 生成以下 JSON 结构：

```json
{
    "code": 0,
    "msg": "success",
    "data": {}
}
```

三个字段均由调用方传入。`data` 可以是 `nil`、结构体、切片或 map，实际序列化规则由 `context.Response.Json` 执行。

## Redirect

```go
return c.Redirect("/login")
return c.Redirect("/login", 303)
```

默认状态码是 302，也可以传一个 301、302、303、307 或 308。目标为空、包含控制字符、状态码非法或传入多个状态码时，响应记录 `ErrInvalidRedirect` 并安全降级为 500。目标来自用户输入时，业务仍需防范开放重定向，详见[响应](../请求响应/响应.md)。

## 与动作返回值配合

这些方法可以直接作为动作返回值，也可以作为 `(value, error)` 的 `value`：

```go
func (c *User) Update(req *context.Request) (*context.Response, error) {
	if !req.Has("name") {
		return c.Error(c.Lang("validate.default.required", map[string]interface{}{"field": "name"}), 422), nil
	}
	return c.Success(map[string]interface{}{"updated": true}), nil
}
```
