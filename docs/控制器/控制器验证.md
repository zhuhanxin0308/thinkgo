# 控制器验证

`Controller.Validate` 是面向简单请求的便捷 API。它使用 `validate.ValidateRules` 按传入规则执行无场景验证；成功的规则快照会进入有界进程级缓存，但每次调用仍返回独立的 `validate.Result`。该入口不自动安装自定义消息、场景或语言实例；需要这些能力时，应使用应用内专用 `validate.Validator` 并显式调用 `SetMessages`、`SetScenes` 或 `SetLang`。

## 基本用法

```go
func (c *User) Create(req *context.Request) *context.Response {
	result, err := c.Validate(req.All(), map[string]string{
		"name":  "required|length:2,20",
		"email": "required|email",
	})
	if err != nil {
		return c.Error("验证配置错误", 500)
	}
	if !result.Valid() {
		return c.Error(result.FirstError(), 422)
	}
	return c.Success(nil)
}
```

## 错误边界

- 用户输入不符合规则时，`err` 为 `nil`，违规保存在 `validate.Result` 中。
- 未知规则、非法参数、重复字段等配置错误通过 `err` 返回，`Result` 保持有效且不伪装成用户违规。
- `FirstError`、`Errors` 和 `Violations` 的读取方式见[验证结果](../验证/验证结果.md)。

验证失败的 HTTP 状态、业务错误码和消息格式由应用控制器决定；框架不会自动把 `Result` 变成 422 响应。

## 控制器与服务边界

控制器应在调用服务前验证所有外部输入，包括 JSON 或表单请求体、查询参数和路由参数。复杂接口应在 `app/<应用名>/validate` 定义带场景的专用验证器，验证通过后再把明确的请求对象传给服务门面：

```go
result, err := c.Validate(req.All(), rules)
if err != nil {
    return c.Error("验证配置错误", 500)
}
if !result.Valid() {
    return c.Error(result.FirstError(), 422)
}
return c.Success(nil)
```

管理员控制器还可以使用应用提供的 `decodeAndValidate` 辅助完成严格 JSON 绑定和场景验证。无论使用哪种入口，控制器都不应持有数据库连接、构造模型或执行查询、插入、更新、删除。数据库访问由服务和仓储层负责，控制器只负责输入边界、请求上下文、服务调用和响应映射。带资源标识的动作也必须先使用资源标识验证器，再把标识传给服务。

## 复杂验证

需要自定义消息、场景、批量错误、多语言或复用规则时，应在所属应用的 `app/<应用名>/validate` 下定义专用验证器：

```go
type UserValidate struct {
	validate.Validator
}

func NewUserValidate() *UserValidate {
	result := &UserValidate{}
	result.SetRules(map[string]string{
		"name":  "required|length:2,20",
		"email": "required|email",
	})
	return result
}
```

专用验证器的配置、场景和规则见[验证器](../验证/验证器.md)及其子章节。

## 便捷验证的缓存边界

`validate.ValidateRules` 只缓存规则快照和已编译计划，不缓存请求数据、验证结果或语言状态。缓存有固定容量，动态规则超过键长度上限时会自动回退到一次性验证器；因此不会改变规则配置错误、数据违规和并发调用的错误边界。需要长期复用复杂配置时，仍应在应用启动阶段创建专用验证器。
