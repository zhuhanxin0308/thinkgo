# 控制器验证

`Controller.Validate` 对应 ThinkPHP `BaseController::validate`。验证成功返回 `true`；数据不符合规则时抛出 `ValidateException`，由 HTTP 异常生命周期统一渲染，不需要控制器逐个判断结果。

## 规则验证

```go
func (controller *User) Save(request *framework.Request) *framework.Response {
	controller.Validate(request.All(), map[string]string{
		"name":  "required|length:2,20",
		"email": "required|email",
	})

	return controller.Success(nil)
}
```

规则配置错误同样会抛出异常并进入统一异常处理，不能被当作普通用户输入错误。

## 自定义消息与批量验证

`Validate` 的第三个参数是自定义消息，第四个参数控制是否收集全部错误：

```go
controller.Validate(
	request.All(),
	rules,
	map[string]string{
		"email.email": "邮箱格式错误",
	},
	true,
)
```

也可以先调用 `controller.SetBatchValidate()`，让后续验证默认收集全部错误。

## 验证器与场景

复杂规则放在 `app/<应用名>/validate`，通过 ThinkPHP 风格的 `验证器.场景` 名称调用：

```go
controller.Validate(request.All(), "User.create")
```

通过 `make:validate` 创建的验证器会自动进入应用装配入口：

```bash
go run ./cmd/think make:validate User
```

验证器可以自定义规则、消息、场景和多语言。控制器应在调用当前 `app/<应用名>/service` 中的业务服务前完成所有外部输入验证。

## 显式结果 API

确实需要自行组织错误响应时，使用扩展 API `ValidateResult`：

```go
result, err := controller.ValidateResult(request.All(), rules)
if err != nil {
	return controller.Error("验证配置错误", 500)
}
if !result.Valid() {
	return controller.Error(result.FirstError(), 422)
}
```

`ValidateResult` 返回 `(validate.Result, error)`；不要把这一扩展行为误认为 ThinkPHP 默认 `Validate` 的返回方式。
