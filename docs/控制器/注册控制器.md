# 控制器发现

业务控制器放在 `app/<应用名>/controller`。开发者不需要调用 `RegisterController`，也不需要创建 `application.go` 或 `internal` 注册表。

## 通过命令创建

```bash
go run ./cmd/think make:controller User
```

命令创建控制器后会立即刷新 `app/autoload_generated.go`。该文件只解决 Go 静态编译的类型引用，由工具维护，不承载业务逻辑。

手工新增、重命名或删除控制器源码后，执行：

```bash
go run ./cmd/think service:discover
```

## 名称与路由

导出的控制器结构体名就是路由中的控制器名：

```go
package controller

type User struct{}

func (*User) Index() string {
	return "User List"
}
```

路由使用 ThinkPHP 的 `controller/action` 写法：

```go
Route.Get("users", "user/index")
Route.Get("users/:id", "user/read")
```

名称比较遵循路由配置中的控制器、动作后缀规则。控制器或动作不存在时，请求进入统一异常处理。

## 实例生命周期

发现文件只保存控制器类型。HTTP 内核在每个请求作用域中创建新的控制器指针实例，再注入当前 App、Request 和动作依赖，因此不同请求不会共享控制器字段。

需要请求级状态时嵌入 `BaseController`；不要把请求对象、用户身份或验证结果存入包级变量。

## 底层扩展

`App.RegisterController` 保留给框架扩展和嵌入式宿主。普通项目使用标准目录和生成命令即可，不应直接依赖该底层注册 API。
