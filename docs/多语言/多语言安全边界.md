# 多语言安全边界

多语言实现把文件解析、路径访问、变量格式化和共享状态都限制在明确边界内。

## 原子提交

`Load` 先完整解析单文件，再在锁内合并；`LoadAll` 先解析目录中的全部 JSON，全部成功后才替换语言表。损坏文件不会留下部分语言或污染已有翻译。

## 文件路径

`LoadAll` 会解析目录根的真实路径，再对每个 JSON 文件解析符号链接目标。目标逃逸真实根目录时返回 `ErrUnsafeLanguagePath`。文件必须是普通文件，非 JSON 文件会被忽略。

## 输入限制

语言标识、配置变量、翻译键、嵌套深度、条目数、文件大小、`Accept-Language` 长度和候选数量都有上限。应用不应通过动态生成无限语言文件或把外部输入直接当作语言文件路径来绕过这些边界。

## 并发状态

`Lang` 使用读写锁保护翻译表、当前语言、默认语言和检测配置；`DetectionConfig` 返回切片副本。翻译读取不会返回内部 map，目录加载在提交时复制翻译数据。

请求语言存放在请求对象中，适合并发请求。`SetLang` 改的是共享的当前语言，只适用于启动或兼容性场景，不要在请求处理协程中调用。

## 变量安全

翻译变量只接受有限的基础标量，不执行任意格式化方法或模板代码。无法安全转换的值会保留原占位符，不会把内部类型、panic 或错误堆栈写入用户消息。
