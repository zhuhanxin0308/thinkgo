# 请求语言检测

应用初始化时注册 `app.LoadLangPack()`。中间件为每个请求选择语言，并把结果写入 `framework.LangRequestKey` 对应的请求数据。

## 来源优先级

默认检测顺序是：

1. 查询参数 `lang`。
2. Cookie `think_lang`。
3. 请求头 `think-lang`。
4. `Accept-Language`。
5. 默认语言。

名称可以通过[多语言配置](多语言配置.md)修改。每个显式来源的值都必须通过 `MatchLanguage`；不支持的值不会终止检测，会继续尝试下一来源。

```text
GET /users?lang=en-us
Cookie: think_lang=zh-cn
think-lang: ja-jp
Accept-Language: en-US,en;q=0.9,zh-CN;q=0.8
```

上例中合法查询参数会优先于其它来源。

## Accept-Language

浏览器检测由 `auto_detect_browser` 控制。开启时，框架会：

- 最多读取 8192 字节请求头。
- 最多处理 32 个逗号分隔候选。
- 按 `q` 权重从高到低排序。
- 忽略 `q=0`、非法、重复 `q`、NaN、Inf、负数和大于 1 的候选。
- 相同权重保持请求头原始顺序。
- 支持 `*`，它会尝试默认语言。

```text
Accept-Language: en-US;q=0, zh-CN;q=0.5, ja-JP;q=1
```

此请求会先尝试 `ja-jp`，不会选择 `en-us`。完整标签命中失败时仍会按主语言前缀匹配。

## 请求上下文

```go
locale := req.Route(framework.LangRequestKey)
value := req.GetData(framework.LangRequestKey)
```

控制器应使用 `c.GetLang()` 或 `c.Lang()` 读取，不要调用共享语言服务的 `SetLang` 模拟请求切换。语言中间件会继续调用下游处理器；下游为空时返回通用 500。

语言匹配规则和允许列表在初始化后以不可变快照读取，请求只把选中的语言写入 `_lang` 请求数据。检测器不会保存全局“当前请求语言”，也不会因为并发请求修改共享语言管理器；`Accept-Language` 的 `q` 只用于当前请求候选排序，不改变其它来源的优先级。

## 关闭浏览器检测

当 `auto_detect_browser=false` 时，`Accept-Language` 完全不参与选择。显式查询参数、Cookie 和自定义请求头仍按配置启用；如果这些来源都无效，就回退默认语言。
