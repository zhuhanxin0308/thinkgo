# 路由错误与安全

底层路由注册和请求匹配采用显式错误，不会把非法定义降级成宽松匹配。业务 `*framework.Route` facade 会把注册期错误转换为路由加载失败，使 `route/app.go` 保持 ThinkPHP 的链式写法。常用错误包括：

| 错误 | 含义 |
|---|---|
| `ErrRouterFrozen` | 路由器已进入只读阶段 |
| `ErrInvalidRoute` | 方法、路径或名称定义非法 |
| `ErrDuplicateRoute` | 路由身份重复 |
| `ErrDuplicateRouteName` | 路由名称重复 |
| `ErrInvalidRouteHandler` | 控制器动作或闭包签名非法 |
| `ErrInvalidRouteMiddleware` | 中间件为空、缺失或无法唯一识别 |
| `ErrInvalidRoutePattern` | 参数正则非法 |
| `ErrInvalidRouteDomain` | 域名约束非法 |
| `ErrRouteTooComplex` | 路径段或可选段超过上限 |
| `ErrInvalidRequestPath` | 请求路径包含危险或非法段 |
| `ErrInvalidRouteParameter` | 命名 URL 的参数类型、值或约束非法 |

重要上限如下：

```text
路径长度：2048 字节
路径段数：64
可选参数段：8
参数正则：512 字节
路由名称：128 字节
扩展名：32 字符
```

路径匹配会拒绝反斜线、连续斜线、点段、控制字符、非法百分号编码和越界路径。重定向目标同样拒绝 CR/LF，避免响应头注入。

自动路由遵循 ThinkPHP 默认的 `url_route_must=false`；需要强制显式路由时由项目配置为 `true`。域名路由是精确匹配而不是用户输入的通配表达式；命名 URL 不调用任意对象的 `String()`。这些边界应保留在注册期和入口层，不要在控制器中重新实现一套宽松解析。
