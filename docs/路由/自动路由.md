# 自动路由

ThinkGo 默认关闭自动路由、开启强制路由：`url_route_must=true`。这是一项安全默认值选择，不再以兼容 ThinkPHP 的默认控制器调度为目标。没有命中显式路由的请求不会自动调用控制器。

新项目的 `config/route.json` 明确写入：

```json
{
    "url_route_must": true
}
```

缺少整个路由配置、配置为空，或仅设置其它路由选项时，仍保持强制路由。要主动启用下面的自动调度规则，必须显式设置 `"url_route_must": false`，或在注册期调用并检查 `router.EnableAutoRoute(true)` 的返回错误。旧项目已经显式设置的 `false` 不会被覆盖。

## 显式启用后的解析规则

```text
/                  -> Index/index
/user              -> user/index
/user/edit         -> user/edit
/admin/user/edit   -> admin/user/edit
```

单段路径作为控制器并使用默认动作；多段路径把最后一段作为动作，前面的段作为控制器及其分层。请求中的分层和动作名称会保持原始大小写写入 `Request.Layer()`、`Request.Controller()` 和 `Request.Action()`，实例化 Go 控制器时才转换为可导出名称。

根路径使用 `SetDefaultController` 和 `SetDefaultAction` 的默认值，默认值分别为 `Index` 和 `index`。

## 方法与安全边界

显式启用的自动 URL 调度不按 HTTP 方法裁剪控制器动作。GET、HEAD、POST、PUT、PATCH、DELETE 等方法在没有命中当前方法的显式规则时，都会继续按 URL 查找控制器；需要限制方法时使用显式路由或把 `url_route_must` 设为 `true`。未命中显式 OPTIONS 或 MISS 时，默认 URL 调度返回 204，并设置 `Allow: GET, POST, PUT, DELETE`。

路径段必须能映射为 Go 标识符：首字符是字母或下划线，后续只能是字母、数字或下划线。包含点号扩展名、连字符、空段、`..` 或非法解码内容的请求不会解析为自动路由。框架也会屏蔽基础控制器导出的内置方法，但业务控制器的导出动作（包括有副作用的动作）仍可能被暴露，因此生产环境应保持显式路由。

## 配置边界

`App.applyRouteConfig` 会严格读取并应用以下字段；类型错误或非法值会形成启动错误：

| 字段 | 运行时语义 |
|---|---|
| `url_route_must` | 默认 `true`，只允许显式路由；显式 `false` 时允许自动路由 |
| `url_case_sensitive` | 控制静态路由和字面量路径段是否区分大小写 |
| `route_complete_match` | `true` 时必须完整消费请求路径；`false` 时允许前缀匹配 |
| `default_controller` | 自动路由缺省控制器 |
| `default_action` | 自动路由缺省动作 |
| `controller_layer` | 自动路由查找控制器时使用的层级前缀 |
| `url_html_suffix` | 全局可选 URL 后缀；路由显式声明的后缀约束仍优先 |
| `remove_slash` | 是否忽略请求路径与注册路径末尾斜杠的差异 |

路由在首次加载后被冻结，上述配置不能在请求处理中动态修改。`url_route_must` 决定是否允许未匹配后的自动调度，`route_complete_match` 决定显式规则能否前缀匹配，两者不是同一个开关；本次不改变后者的默认值。

默认模式下，注册为 POST 的规则不会因同名控制器存在而被 GET/HEAD 调用；未匹配保持既有 404 语义，不生成自动 OPTIONS。显式 Any、MISS 和 OPTIONS 规则仍有效；全局 CORS 预检和 public 静态资源保留各自职责。强制路由不是权限检查，认证、授权、CSRF 和安全方法不能修改状态的约束仍须单独实施。
