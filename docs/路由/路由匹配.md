# 路由匹配

`Router.Match` 会先确保路由器已冻结，再在按方法构建的只读索引中匹配：

```go
matched, params, err := router.Match(request)
if err != nil {
	return err
}
if matched == nil {
	return context.NewResponse().Code(404)
}
```

空请求返回 `ErrNilRequest`。未命中且没有 MISS 路由时，匹配结果为 `nil, nil, nil`。

## 索引与优先级

冻结时静态路径进入“方法 + 路径段”索引，动态路径进入按方法、域名和路径段组织的只读 Trie；扩展名候选保留有序回退。索引只负责缩小候选集合，候选最终仍由现有正则、参数、域名和扩展名匹配器校验，因此不会改变边界语义。动态路由按稳定优先级排序，注册顺序在优先级相同时保持不变。

匹配顺序为：

1. 当前请求方法的静态路由。
2. 当前请求方法的动态路由。
3. `HEAD` 请求回落到 `GET`。
4. `Any` 通配方法。
5. 路径和域名都存在但方法不匹配时返回 405。
6. 显式路由未命中后，才尝试自动路由、MISS 路由。

索引构建发生在 `Freeze` 阶段，匹配热路径只读取不可变快照，不获取注册锁，也不复制整张动态候选表。索引未建立时仍保留旧的线性候选回退，用于兼容未冻结或内部测试场景。

同一路径存在精确域名和无域名版本时，精确域名优先。域名约束不匹配的路由不会污染其它主机的匹配。

## HEAD、OPTIONS 和 405

注册 GET 后，HEAD 会自动回落到同一 GET 处理器；显式注册 HEAD 时优先使用显式路由。

路径存在但方法不允许时，框架返回 `*MethodNotAllowedError`，其 `Allowed` 集合稳定排序，并自动包含：

- 存在 GET 时的 HEAD；
- 未显式注册时的 OPTIONS。

未注册 OPTIONS 时，OPTIONS 会生成 204 响应并设置 `Allow` 头。显式 OPTIONS 路由会优先于自动响应。路由中存在 `Any` 时不会生成受限的 Allow 集合，因为该路径允许任意合法 HTTP 方法。

## 参数结果

静态路由返回 nil 参数 map；动态路由返回解码后的参数。可选参数没有请求值时会以空字符串进入参数 map。正则约束失败视为该路由不匹配，不会退化为无约束路由。
