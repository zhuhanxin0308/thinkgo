# 路由匹配

`Router.Match` 会先确保路由器已冻结，再在按方法构建的只读索引中匹配：

```go
matched, params, err := router.Match(request)
if err != nil {
	return err
}
if matched == nil {
	return context.NewResponse().Code(404)
}
```

空请求返回 `ErrNilRequest`。未命中且没有 MISS 路由时，匹配结果为 `nil, nil, nil`。

## 索引与优先级

冻结时静态路径进入“方法 + 路径段”索引，动态路径进入按方法、域名和路径段组织的只读 Trie；扩展名候选保留有序回退。索引只负责缩小候选集合，候选最终仍由现有正则、参数、域名和扩展名匹配器校验，因此不会改变边界语义。动态路由按稳定优先级排序，注册顺序在优先级相同时保持不变。

匹配顺序为：

1. 当前请求方法的静态路由。
2. 当前请求方法的动态路由。
3. `Any` 通配方法的静态和动态路由。
4. 当前方法专用 MISS，其次是通用 MISS。
5. OPTIONS 在允许默认 URL 调度时返回自动 204。
6. 其它方法在 `url_route_must=false` 时继续默认 URL 调度；强制路由时保持未命中。

索引构建发生在 `Freeze` 阶段，匹配热路径只读取不可变快照，不获取注册锁，也不复制整张动态候选表。索引未建立时仍保留旧的线性候选回退，用于兼容未冻结或内部测试场景。

同一路径存在精确域名和无域名版本时，精确域名优先。域名约束不匹配的路由不会污染其它主机的匹配。

## HEAD、OPTIONS 和方法未命中

HEAD 只匹配显式 HEAD 或 Any 规则，不会隐式复用 GET。没有匹配规则时，它与其它方法一样按 `url_route_must` 决定是否继续默认 URL 调度。

方法不匹配不生成 405，也不会根据其它方法的路由合成 `Allow`。这与 ThinkPHP `Route::check` 的行为一致：默认继续 URL 调度，开启强制路由时作为普通未命中处理。

显式 OPTIONS、Any 或 MISS 会按正常顺序优先匹配。没有匹配且 `url_route_must=false` 时，OPTIONS 返回 204，并设置 ThinkPHP 默认的 `Allow: GET, POST, PUT, DELETE`；强制路由时不生成自动 OPTIONS。自动响应不继承其它方法路由的参数或中间件。

## 参数结果

静态路由返回 nil 参数 map；动态路由返回解码后的参数。可选参数没有请求值时会以空字符串进入参数 map。正则约束失败视为该路由不匹配，不会退化为无约束路由。
