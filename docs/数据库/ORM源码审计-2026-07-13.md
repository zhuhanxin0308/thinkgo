### T2-01 — P1 — 逻辑/生命周期：事务 context 自动回滚后框架状态和连接租约不终结

- **准确位置**：`framework/db/transaction.go:35-65,105-145`；关闭等待点 `framework/db/db.go:269-285`。
- **触发条件**：`DB.BeginTx(ctx, ...)` 成功后 `ctx` 取消或超时，`database/sql` 自动回滚底层事务，但调用方没有再显式调用框架 `Commit`/`Rollback`。
- **影响**：`Tx.state` 仍为 active、release 未执行，`DB.Close`/`Manager.Close` 可无限等待；取消后的调用还可能返回 `sql.ErrTxDone` 而非稳定的框架终态错误。
- **受影响驱动**：全部通过 `SQLConnection` 使用事务的 MySQL、PostgreSQL、SQLite、SQL Server、Oracle。
- **证据**：源码中租约只由 `Tx.complete` 释放；自定义 `database/sql/driver` 复现中，context 自动回滚后 Close 持续阻塞，显式 wrapper Rollback 后才返回。
- **修复方向**：用同一个 exactly-once 状态机监听 `ctx.Done()`、确认回滚、设置终态并释放租约；正常终结需停止 watcher，并增加“取消后无需二次清理即可 Close”的回归测试。

**修复状态（2026-07-14）**：源码已修复。
- **修复提交**：`15e562f`
- **回归测试**：`TestBeginTxContextCancellationReleasesLease`、`TestCommitAndCancellationFinalizeOnce`
- **真实驱动边界**：状态机与租约由框架统一管理，并已通过自定义 `database/sql/driver` 和 race detector 验证；五种 SQL connector 复用同一实现，无需依赖服务端主动清理。

### NQ-01 — P1 — 跨后端契约：NoSQL 插入数量被上层当作最后插入 ID

- **准确位置**：统一接口 `framework/db/connection.go:5-19`；Mongo `framework/db/mongo_connection.go:190-203`；Neo4j `framework/db/neo4j_connection.go:194-218`；上层 `framework/db/query_execute.go:181-198`、`framework/db/model_query.go:142-160`、`framework/db/model.go:737-745`。

### T3-06 — P3 — Contract hardening：MySQL 低层 `LockClause` 不做模式白名单

## 已检查但未发现问题的边界

### 生命周期、查询、模型与资源

- `DB.acquireConnection` 在读锁内完成 closed 检查和 WaitGroup Add；Close 先置 closed 再 Wait，因此 ORM 内部租约不会在等待后新增。内部 Query/Execute/CRUD 均 defer release，BeginTx 失败分支也释放；缺口仅是 T2-01 的标准库自动回滚终态和 T2-03 的裸连接 API。
- 同一个 DB wrapper 的并发重复 Close、Manager 同一 wrapper 多别名关闭一次、重复名称显式拒绝、关闭错误 `errors.Join` 均有源码/测试覆盖。
- SQLConnection 全部 context 路径传给 `database/sql` 的 Context API；Mongo/Neo4j 从父 context 派生有界 timeout。旧自定义 Connection 的无 context fallback 是已文档化兼容边界。
- 显式 Commit/Rollback exactly-once、panic 回滚、callback error 与 rollback error 聚合、完成后查询拒绝均已覆盖；未发现额外事务确认问题。
- `scanRows` 检查重复列、`rows.Err`、合并 Close 错误并 clone `[]byte`；Count/aggregate 数值 parser 拒绝负数、溢出、小数、NaN/Inf 和非法文本。
- Query 默认 Where/Having、identifier、operator、JOIN、Inc/Dec 和 values 均经结构化校验/绑定；显式 Raw API 仍由调用方负责。InsertAll 校验字段集、bind budget、affected overflow，并在多批时自动事务回滚。
- 模型 update/delete/force-delete/restore 要求业务 predicate；soft-delete scopes 基于 clone；关系键拒绝 nil/非有限浮点/重复唯一键；eager loading 每关系批量查询，未发现按父行 N+1。
- Mongo filter 限定 operator 和 scalar、拒绝多余/不足参数及空条件 mutation；collection/field/order 经标识符校验；cursor/close 均有界。Neo4j label/property/alias/order 经白名单/引用，值参数化，read/write mode 分离，结果完全消费。
