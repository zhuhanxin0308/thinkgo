# 错误与安全

数据库层把配置、查询、写入、事务、模型和结果映射错误区分为稳定的 sentinel error。业务代码应使用 `errors.Is` 判断类别，同时保留原始错误上下文。

## 常用错误

| 错误 | 典型场景 |
|---|---|
| `ErrInvalidDatabaseConfig` | 连接类型、地址、前缀、连接池或时间戳配置非法 |
| `ErrDatabaseUnavailable` / `ErrDatabaseClosed` | 连接为空、底层连接不可用或已关闭 |
| `ErrInvalidQuery` | 查询器、条件、上下文或原生 SQL 参数非法 |
| `ErrUnsafeFullTableMutation` | 更新或删除缺少业务 WHERE |
| `ErrInvalidPagination` | 页码、页大小、偏移或整数溢出 |
| `ErrInvalidAggregateValue` | Count 或聚合结果无法精确解析 |
| `ErrInvalidTransaction` / `ErrTransactionDone` | 事务依赖、回调或已结束事务操作非法 |
| `ErrInvalidModel` | 模型依赖、字段映射、回调或结构体输入非法 |
| `ErrInvalidRelation` | 关联定义、键类型、预加载或关联结果非法 |
| `ErrInvalidDatabaseRow` | 缺列、重复列、游标或结果 map 无法安全构造 |

示例：

```go
database := app.DB()
affected, err := database.Name("users").Update(data)
if errors.Is(err, db.ErrUnsafeFullTableMutation) {
	return ErrMissingFilter
}
if err != nil {
	return err
}
```

事务闭包同时返回业务错误和回滚错误时，框架使用 `errors.Join` 保留两者，仍可用 `errors.Is` 分别判断。

## 标识符校验

表名、字段名、别名、排序、分组、操作符和 JOIN 条件都经过结构化校验：

- 标识符只允许字母、数字、下划线和点分层级。
- 排序只允许字段加 `ASC` 或 `DESC`。
- JOIN 只允许字段与字段比较，并支持 `AND`。
- `WhereExp` 只允许受限表达式和函数白名单。
- 动态表名、列名和排序方向必须在服务层从固定白名单中选择。

校验只保护框架安全入口；`WhereRaw`、`HavingRaw` 和 `DB.Query` 的原生 SQL 片段仍由调用方负责。

## 全表写保护

结构化 ORM 的 `Update`、`Delete`、模型更新和模型删除都拒绝无业务 WHERE。软删除自动增加的 `delete_time IS NULL` 不算调用方过滤条件，因此不能通过启用软删除绕过保护。

事务内的 `tx.Execute` 进一步只允许单条参数化 INSERT/UPSERT，事务中的 UPDATE 和 DELETE 必须使用结构化查询，以保留同一保护。

## 参数化和日志

所有值都应通过占位符绑定，禁止把密码、令牌、用户输入或 JSON 片段直接拼进 SQL。框架会严格检查原生 SQL 的占位符数量，并按方言重绑定。

数据库错误日志只记录 SQL 结构、字段名、表名和参数数量，不记录参数值；字符串字面量、注释和敏感赋值会脱敏。业务日志仍需避免主动记录敏感字段。

## 生命周期和上下文

- 请求数据库操作使用 `WithContext`，让取消和超时传递到驱动。
- 关闭数据库后不再接受新租约，并等待已开始的操作释放资源。
- 事务必须提交或回滚；手动事务的所有错误路径都要释放事务。
- 控制器先验证请求，再调用服务；服务层才负责模型、ORM、事务和错误转换。
