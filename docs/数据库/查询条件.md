# 查询条件

查询条件默认走结构化、参数化入口。字段名和操作符来自受限白名单，值始终作为绑定参数传递。

## 基础条件

```go
database, err := framework.ResolveServiceAs[*db.DB](app, framework.ServiceDB)
if err != nil {
	return err
}
q := database.Name("users").
	WhereField("status", "=", 1).
	WhereField("age", ">=", 18)
```

`WhereField(field, operator, value)` 适合明确的字段比较。允许的操作符为 `=`、`!=`、`<>`、`>`、`>=`、`<`、`<=`、`LIKE`、`NOT LIKE`、`IS` 和 `IS NOT`。

`Where` 为兼容 ThinkPHP 风格，支持以下形式：

```go
q.Where("id = ?", 1)
q.Where("status", 1)
q.Where("age", ">=", 18)
q.Where(map[string]interface{}{"status": 1, "enabled": true})
q.Where([][]interface{}{{"age", ">=", 18}, {"status", "=", 1}})
```

字符串形式只允许受限谓词和正确数量的 `?`；三元组的字段和操作符仍会校验。Map 条件按字段名排序后生成 SQL，保证 SQL 和参数顺序稳定；空 map、空三元组或不支持的条件类型会报错。

## AND、OR 和条件组

连续 `Where` 默认按 AND 连接，`WhereOr` 添加 OR 条件：

```go
q := database.Name("users").
	WhereField("status", "=", 1).
	WhereOr("status = ?", 2)
```

需要控制括号时使用闭包条件组：

```go
q := database.Name("users").Where(func(group *db.ConditionGroup) {
	group.Where("status = ?", 1).
		WhereOr("status = ?", 2)
}).WhereField("tenant_id", "=", tenantID)
```

条件组不能为空。括号不平衡、空分支和占位符数量不一致都会在终端执行时返回 `ErrInvalidQuery`。

## 字段比较与表达式

`WhereColumn` 比较两个字段，不把右侧字段当作值：

```go
q.WhereColumn("users.updated_at", ">", "users.created_at")
```

`WhereExp` 用于受限表达式：

```go
q.WhereExp("score", ">", "ABS(?)", -10)
```

表达式只允许标识符、数字、算术符、括号、占位符和函数白名单。禁止字符串字面量、分号、注释、子查询、语句关键字以及 `OR`、`AND` 等组合关键字；复杂表达式应使用 `WhereRaw` 并自行承担安全责任。

## 时间条件

`WhereTime` 会对时间参数做统一校验和参数化：

```go
q.WhereTime("created_at", ">=", startAt)
q.WhereTime("created_at", "BETWEEN", startAt, endAt)
```

`WhereTime` 默认使用当前数据库连接的 `timestamp_value_type` 转换 `time.Time`：`unix` 生成 Unix 秒，`datetime`/`timestamp` 生成应用时区下的 `YYYY-MM-DD HH:mm:ss`，`date` 生成 `YYYY-MM-DD`，`native` 传递应用时区下的原生 `time.Time`。字段类型与数据库默认时间戳类型不同时，必须显式指定：

```go
q.WhereTimeAs("published_at", db.TimestampValueTypeNative, "between", startAt, endAt)
```

日历条件使用 `[start, end)` 半开区间，能够覆盖小数秒并正确处理夏令时跨日。零时间、空值、NaN、正负无穷等无效时间输入会返回查询错误。时间字段本身仍需是安全标识符。

## 集合与范围

```go
q.WhereIn("id", []interface{}{1, 2, 3})
q.WhereNotIn("status", []interface{}{0, 9})
q.WhereBetween("age", 18, 60)
```

`WhereIn` 和 `WhereNotIn` 会展开为绑定参数，不把集合值拼入 SQL。空集合的行为有意不同：

- `WhereIn` 生成恒假条件，避免空集合退化为无过滤查询。
- `WhereNotIn` 不追加条件，表示“没有排除项”；调用方如需恒假逻辑应显式添加条件。

查询绑定参数受当前 SQL 方言的单语句预算约束，`Where`、`WhereIn`、`WhereRaw`、`Having` 等入口会共享同一预算；超出时返回 `ErrQueryArgumentsTooMany`，并且不会继续生成占位符或写入超限条件。当前保守预算为：SQLite/Oracle 999 个、SQL Server 2100 个、MySQL/PostgreSQL 65535 个；无具体方言的自定义连接使用 65535 个回退上限。需要处理大集合时应按批次拆分查询，写入场景优先使用会按方言自动分批的 `InsertAll`，不要把整批 ID 一次性展开到 `IN` 条件中。

## 模糊和 NULL

```go
q.WhereLike("name", "%go%")
q.WhereNull("deleted_at")
q.WhereNotNull("email_verified_at")
```

`WhereLike` 的模式作为绑定参数传递；`WhereNull` 和 `WhereNotNull` 不需要额外参数。字段名、点分表字段和操作符均经过校验。

## 原生条件

```go
q.WhereRaw("JSON_EXTRACT(profile, '$.role') = ?", "admin")
q.HavingRaw("COUNT(*) > ?", 10)
```

`WhereRaw` 和 `HavingRaw` 是明确的原生 SQL 逃生入口。框架仍会检查非空 SQL、NUL 字节和占位符数量，但不会替调用方验证原生片段的业务安全性。用户输入只能作为绑定参数，不能拼接进 Raw 字符串。

## 标识符规则

安全标识符由字母、数字、下划线组成，允许用点表示表字段，例如 `orders.user_id`。不允许空格、引号、反引号、分号、注释、表达式或用户输入直接形成的动态列名。表名、字段名、排序和分组动态化时必须先从服务层白名单选择。
