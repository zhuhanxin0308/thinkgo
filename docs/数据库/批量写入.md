# 批量写入

`InsertAll` 用于将多行 map 批量插入同一张表：

```go
database := app.DB()
affected, err := database.Name("users").InsertAll([]map[string]interface{}{
	{"name": "张三", "status": 1},
	{"name": "李四", "status": 1},
})
```

## 输入约束

- 输入切片为空时返回 `0, nil`；非空输入的每一行必须包含至少一个字段。
- 每一行必须包含至少一个字段。
- 所有行的字段集合必须完全一致，字段顺序可以不同。
- 字段名必须通过标识符校验。
- 框架会复制每一行 map，不会改变调用方数据。

字段集合不一致时立即返回错误，避免批量参数错位或某些行意外写入默认值。

## 自动分批

框架同时根据当前 SQL 方言的绑定参数上限和可选的协议包字节预算计算每批行数。总占位符数量或保守估算的单条语句大小超过预算时自动拆成多个批次；调用方不需要手动计算数据库参数限制。

MySQL 连接器会把 `maxAllowedPacket` 传给批量分批器。默认使用驱动的 64 MiB 预算；配置 `maxAllowedPacket=0` 时由 MySQL 驱动按每条连接从服务端读取，框架层不预先固定字节预算。框架的字节估算会为协议包头、参数类型和长度额外预留空间，最终限制仍以驱动和数据库服务端校验为准。

如果单行数据已经超过有效包预算，`InsertAll` 返回 `ErrBatchStatementTooLarge`，不会发送一条确定会失败的超大 SQL。

Oracle 使用 `INSERT ALL` 形式；其它 SQL 方言使用相应的多行插入构建器。占位符统一先按 `?` 构造，再由方言在执行前重绑定。

## 原子性

多批写入且当前不在事务中时，无论是绑定参数上限还是包大小预算触发分批，框架都会自动开启事务包裹全部批次。任意批次执行失败、影响行数读取失败或提交失败，都会使整体操作失败并回滚。

如果已经在 `db.Tx` 中调用 `InsertAll`，批量写入复用当前事务，由外层闭包或手动事务决定提交和回滚：

```go
err := database.Transaction(func(tx *db.Tx) error {
	_, err := tx.Name("users").InsertAll(rows)
	return err
})
```

## 模型批量写入

模型查询器支持 `InsertAll`，但模型层的单行 `Insert` 才会完整执行模型修改器、插入前后事件和主键回填语义。批量导入如果需要同样的业务转换，应在服务层显式准备数据，或逐行调用模型写入并自行评估性能与事务成本。

## 与事务配合

批量导入通常由服务层控制：先在验证器或服务层校验字段集合和业务上限，再在事务中调用 ORM。不要为了绕过批量参数限制而把用户输入拼接成原生 SQL。
