# 连接数据库

本章只说明数据库连接器、配置、环境变量和 SQL 连接池。默认连接、多连接、启动生命周期和关闭顺序见[连接管理](连接管理.md)；查询和模型能力见[数据库章节索引](README.md)。

## 连接层结构

| 层 | 类型 | 作用 |
|---|---|---|
| 连接器注册表 | `db.RegisterConnector` / `db.GetConnector` | 按数据库类型查找连接器，拒绝非法名称和重复注册 |
| 连接器 | `db.Connector` | 将 `db.Config` 转换为具体连接 |
| 统一连接 | `db.Connection` | 提供查询、插入、更新、删除、计数和关闭能力 |
| SQL 连接 | `db.SQLConnection` | 额外提供方言构建器、原生 SQL 和 context |
| 连接句柄 | `*db.DB` | 保存底层连接、表前缀、时间戳配置和日志器 |

应用入口需要空导入 `_ "thinkgo/framework/db/connector"`，触发内置连接器注册。自定义连接器必须处理注册错误：

```go
if err := db.RegisterConnector("custom", connector); err != nil {
	return err
}
```

## 数据库可选启动

`config/database.json` 可以完全缺失。缺失时框架只创建无连接的 `*db.Manager` 服务，不会读取默认连接、创建连接池或发起 Ping；路由、缓存、模板、日志、Session 和非数据库 HTTP 请求仍可正常使用。业务在无数据库模式下解析 `framework.ServiceDB` 或调用查询 API 时，应处理明确的“连接不存在/驱动未配置”错误。

文件一旦存在，就必须同时提供合法的 `default` 和非空 `connections`。未知字段、类型错误或默认连接未声明属于显式配置错误，会保留在应用启动状态并阻止宿主进入监听。连接器 Ping 失败仍按兼容行为记录 warning，不把数据库不可达误判为整个框架初始化失败；需要数据库的请求会在访问点失败。

应用生命周期不使用数据库锁、Redis 锁或其他分布式锁来完成启动、路由冻结和关闭。跨进程数据一致性属于具体数据库/缓存能力，不能从框架启动契约推导出来。

## 支持的数据库

| `type` | 数据库 | 主要要求或差异 |
|---|---|---|
| `mysql` | MySQL / MariaDB | 默认 TLS、`utf8mb4`、`parseTime=True` 和连接存活检查 |
| `pgsql` | PostgreSQL | 默认 `sslmode=require`；使用 `RETURNING` 回传主键 |
| `sqlsrv` | SQL Server | 默认 `encrypt=true`；分页使用 `OFFSET ... FETCH` |
| `oracle` | Oracle | 需要 `oracle` build tag、godror 和 Oracle 客户端环境 |
| `sqlite` | SQLite | 需要 CGO；数据库为普通文件路径或 `:memory:` |
| `mongo` | MongoDB | 默认 `tls=true`，数据库名和 URI 参数严格校验 |
| `neo4j` | Neo4j | 默认 `neo4j+s`；数据库名可省略使用服务端默认库 |

SQLite 文件会启用外键、5000 毫秒 busy timeout 和文件库 WAL；路径必须是普通文件，拒绝符号链接及带 URI 参数的路径。`:memory:` 只能使用一个池连接。MongoDB 与 Neo4j 的条件和写入语义见独立章节。

## 配置文件

配置文件是 `config/database.json`，`default` 必须引用 `connections` 中已声明的连接：

```json
{
    "default": "mysql",
    "connections": {
        "mysql": {
            "type": "mysql",
            "hostname": "127.0.0.1",
            "hostport": "3306",
            "database": "thinkgo",
            "username": "root",
            "password": "",
            "charset": "utf8mb4",
            "prefix": "tg_",
            "debug": false,
            "auto_timestamp": true,
            "create_time_field": "created_at",
            "update_time_field": "updated_at",
            "timestamp_value_type": "unix",
            "max_open_conns": 25,
            "max_idle_conns": 10,
            "conn_max_lifetime_seconds": 300,
            "conn_max_idle_time_seconds": 120,
            "params": {
                "timeout": "5s"
            }
        }
    }
}
```

## 配置项

| JSON 键 | 对应字段 | 规则 |
|---|---|---|
| `type` | `Config.Type` | 必须是已注册的安全连接器名称 |
| `hostname` | `Config.Hostname` | 网络连接必填，不允许空白、控制字符或 NUL |
| `hostport` | `Config.Hostport` | 可空；提供时必须是 `1-65535` 的十进制端口 |
| `database` | `Config.Database` | SQL 和 MongoDB 必填；Neo4j 可省略；SQLite 为文件路径 |
| `username` / `password` | `Config.Username` / `Password` | 凭据由连接器安全转义；Neo4j/MongoDB 有额外凭据规则 |
| `charset` | `Config.Charset` | SQL 连接字符集 |
| `prefix` | `Config.Prefix` | 表前缀，必须是安全标识符 |
| `debug` | `Config.Debug` | 是否启用数据库调试行为 |
| `auto_timestamp` | `Config.AutoTimestamp` | 是否自动补齐模型/查询时间戳 |
| `create_time_field` | `Config.CreateTimeField` | 创建时间字段，默认 `create_time` |
| `update_time_field` | `Config.UpdateTimeField` | 更新时间字段，默认 `update_time` |
| `timestamp_value_type` | `Config.TimestampValueType` | `unix`、`datetime`、`timestamp`、`date` 或 `native` |
| `max_open_conns` | `Config.MaxOpenConns` | SQL 最大打开连接数，`0` 使用默认值 |
| `max_idle_conns` | `Config.MaxIdleConns` | SQL 最大空闲连接数，不能超过最大打开数 |
| `conn_max_lifetime_seconds` | `Config.ConnMaxLifetimeSeconds` | SQL 连接最大生命周期，`0` 使用默认值 |
| `conn_max_idle_time_seconds` | `Config.ConnMaxIdleTimeSeconds` | SQL 连接最大空闲时长，`0` 使用默认值 |
| `params` | `Config.Params` | 额外参数，键和值必须是字符串；MySQL 的 TLS 模式使用 `params.tls` |

配置严格解析：未知字段、类型错误、负数、小数、数值溢出、非法标识符或无效地址会阻止启动，不会静默截断或创建半可用连接。`params` 不会把数字和布尔值隐式转换成字符串；MongoDB 拒绝大小写重复参数和同时配置 `tls`/`ssl`，Neo4j 只允许受限连接参数。

MySQL 默认将 `params.tls` 设为 `true` 并校验证书；受信任的开发环境如需跳过证书校验，必须显式设置字符串 `"params": {"tls": "skip-verify"}`。`tls_verify` 不是框架配置字段，使用该键会按未知字段拒绝启动；生产环境不得使用 `skip-verify`。

数据库连接建立后，ORM 业务时钟继承应用的 `app.default_timezone`。应用时区未显式配置为 `Local` 时，框架会为内置 SQL 驱动补齐连接级时区参数：MySQL 使用 `loc` 和 `time_zone`，PostgreSQL 使用 `TimeZone`，SQLite 使用 `_loc`，SQL Server 与 Oracle 使用 `timezone`；调用方显式配置的参数优先。ORM 的显式 `time.Time` 写入（包括事务、批量和嵌套值）会先统一到应用时区但保持绝对时刻不变。MongoDB 和 Neo4j 的原生时间参数由连接对象携带应用时区，查询结果中的时间值也会归一化到该时区。原生 SQL 仍应优先绑定应用生成的时间参数，不要混用未配置 Session 时区的数据库默认时间函数。

## 环境变量

环境变量只覆盖默认连接的桥接字段：

| 环境变量 | 字段 |
|---|---|
| `DB_TYPE` | `type` |
| `DB_HOST` | `hostname` |
| `DB_PORT` | `hostport` |
| `DB_USER` | `username` |
| `DB_PASS` | `password` |
| `DB_NAME` | `database` |
| `DB_MAX_OPEN_CONNS` | `max_open_conns` |
| `DB_MAX_IDLE_CONNS` | `max_idle_conns` |
| `DB_CONN_MAX_LIFETIME_SECONDS` | `conn_max_lifetime_seconds` |
| `DB_CONN_MAX_IDLE_TIME_SECONDS` | `conn_max_idle_time_seconds` |
| `DB_TIMESTAMP_VALUE_TYPE` | `timestamp_value_type` |

优先级从高到低为：真实系统环境变量、`.env`、`config/database.json`、框架默认值。`.env` 只写入框架内部存储，不调用 `os.Setenv`；环境变量数值必须是非负整数，非法覆盖会阻止启动，覆盖过程不会留下部分结果。非默认连接的差异配置写在 JSON 中。

## SQL 连接池

SQL 连接器的默认值为：

| 参数 | 默认值 |
|---|---:|
| 最大打开连接数 | 25 |
| 最大空闲连接数 | 10 |
| 最大生命周期 | 5 分钟 |
| 最大空闲时长 | 2 分钟 |
| 建立连接 Ping 超时 | 5 秒 |

`max_idle_conns` 不能超过 `max_open_conns`。所有 SQL 连接在返回前都会执行有界 `PingContext`；失败时关闭已创建的连接池并保留探测与关闭错误。多个连接配置在应用初始化时使用最多 4 个 worker 并行建立，结果仍按连接名稳定安装；单个连接失败只记录已脱敏的 warning，不阻断无数据库或非数据库模块启动。

内置连接器创建的 SQL 连接会缓存最多 128 条重复 SQL 的服务端 Prepared Statement，并在连接关闭或缓存淘汰时释放语句；动态 SQL 按先进先出淘汰，避免无限占用连接资源。事务内查询不复用连接级语句，始终通过当前事务执行器运行。

## 驱动安全默认值

- MySQL 默认 TLS、证书校验、`utf8mb4`、`parseTime=True`、`loc=Local` 和连接存活检查；`params.tls=skip-verify` 只适合受信任的开发环境。高风险的 `multiStatements`、`allowAllFiles`、`allowCleartextPasswords` 和 `allowFallbackToPlaintext` 开关不能设为 `true`。
- PostgreSQL 默认 `sslmode=require`；需要开发环境降级时必须显式配置连接参数。
- SQL Server 默认 `encrypt=true`。
- SQLite 默认外键、busy timeout 和 WAL，普通文件使用私有权限。
- MongoDB 默认 `tls=true`，明文连接必须显式配置 `tls=false`。
- Neo4j 默认使用 `neo4j+s`，只接受明确允许的协议。

完整的连接对象生命周期、`Manager`、启动失败行为和关闭顺序见[连接管理](连接管理.md)。
MySQL、PostgreSQL、文件 SQLite、SQL Server 和 Oracle 统一应用以下连接池默认值与配置规则：

| 参数 | 默认值 | 配置为 `0` / 负数时 |
|---|---|---|
| `MaxOpenConns` | 25 | 使用默认 / 返回配置错误 |
| `MaxIdleConns` | 10 | 使用默认 / 返回配置错误 |
| `ConnMaxLifetime` | 5 分钟 | 使用默认 / 返回配置错误 |
| `ConnMaxIdleTime` | 2 分钟 | 使用默认 / 返回配置错误 |

每个 SQL 连接在返回前都会使用 5 秒有界上下文执行 `PingContext`；失败时同时关闭连接池并保留探测与关闭错误。

MySQL 使用 `go-sql-driver/mysql` 的 typed Config 构造 DSN，默认设置 `charset=utf8mb4`、`parseTime=true`、`loc=Local`、连接存活检查和 `tls=true`。如本地环境确需明文连接，必须在受信配置中显式设置 `params.tls=false`。参数键按大小写归一后不得重复，也不能包含 DSN 结构字符；用户名包含冒号会在连接前返回 `ErrInvalidDatabaseConfig`，避免凭据文本往返改变账号。

以下 MySQL 高风险开关不允许启用，驱动接受的所有真值写法（包括 `1` 和大小写变体）都会被拒绝：`multiStatements`、`allowAllFiles`、`allowCleartextPasswords`、`allowFallbackToPlaintext`、`allowOldPasswords`。显式 `false` 只表示保持安全默认值。

SQLite 默认启用外键、5 秒忙等待和文件库 WAL。普通数据库文件会以私有权限创建或收紧为 `0600`（Windows 除外），符号链接、特殊文件和携带 URI 参数的路径会被拒绝；新建文件若连接失败会被清理。`:memory:` 固定使用 `MaxOpenConns=1`、`MaxIdleConns=1`、`ConnMaxLifetime=0`、`ConnMaxIdleTime=0`，避免多连接隔离或唯一连接过期后丢失整个内存库；配置中的过期时长不会覆盖该安全生命周期。

## 6. 获取连接

### 默认连接

```go
database, err := framework.ResolveServiceAs[*db.DB](app, framework.ServiceDB)
if err != nil {
	return err
}

// 默认连接（config 中 default 指向的那个）
user, err := database.Name("users").WhereField("id", "=", 1).Find()
```

### 命名连接（多库）

```go
manager, err := framework.ResolveServiceAs[*db.Manager](app, framework.ServiceDBManager)
if err != nil {
	return err
}

// 取指定名称的连接；不存在时返回 error
read, err := manager.Connection("read")
if err != nil {
    return c.Error("数据库连接不存在", 500)
}
rows, err := read.Name("users").Select()

// 取默认连接；缺失或管理器已关闭时返回 error
def, err := manager.Default()
if err != nil {
    return c.Error("默认数据库不可用", 500)
}
```

初始化成功时，`ServiceDB` 与 `ServiceDBManager.Default()` 返回同一个默认连接实例。需要受控访问底层连接时使用 `WithConnection`；租约覆盖整个 callback，callback 返回或 panic 后都会释放，禁止把 `connection` 保存到 callback 外部：

```go
err := database.WithConnection(func(connection db.Connection) error {
    // 在此作用域内调用类型化 Connection API。
    return nil
})
```

旧的裸连接 `GetConnection` 已移除，因为它无法在返回后继续保护连接生命周期。

自定义连接实现使用 `context.Context + SelectRequest/InsertRequest/UpdateRequest/DeleteRequest/CountRequest`，写操作返回 `InsertResult/UpdateResult/DeleteResult`。旧的 `where []string`、`ContextualConnection` 和 `InsertContextWithPrimaryKey` 已移除；request getter 返回防御性副本，驱动能力通过 `CapabilityProvider` 声明。

## 7. 多数据库连接

在 `connections` 下声明多个连接，`default` 指定默认连接名：

```json
{
    "default": "mysql",
    "connections": {
        "mysql": {
            "type": "mysql",
            "hostname": "127.0.0.1",
            "hostport": "3306",
            "database": "app_main",
            "username": "root",
            "password": ""
        },
        "read": {
            "type": "mysql",
            "hostname": "10.0.0.21",
            "hostport": "3306",
            "database": "app_main",
            "username": "reader",
            "password": ""
        },
        "log": {
            "type": "pgsql",
            "hostname": "127.0.0.1",
            "hostport": "5432",
            "database": "app_log",
            "username": "postgres",
            "password": ""
        }
    }
}
```

启动时框架按连接名称排序后逐个建立 `connections`，并以连接名注册到 `ServiceDBManager`；`default` 对应的连接同时注册为 `ServiceDB`。连接名称非法、重复注册或默认连接缺失都会形成启动错误，不会覆盖已有实例。

## 8. 程序内手动连接

需要在框架托管之外建立连接（如脚本、测试、临时任务）时，直接使用 `db.Connect`：

```go
import "thinkgo/framework/db"

database, err := db.Connect(db.Config{
    Type:     "mysql",
    Hostname: "127.0.0.1",
    Hostport: "3306",
    Database: "thinkgo",
    Username: "root",
    Password: "secret",
    Charset:  "utf8mb4",
    Prefix:   "tg_",
    // 手动连接同样支持注入额外 DSN 参数。
    Params: map[string]string{
        "timeout":      "5s",
        "readTimeout":  "5s",
        "writeTimeout": "5s",
    },
    MaxOpenConns: 50,
})
if err != nil {
    log.Fatal(err)
}
defer database.Close()
```

`db.Connect` 会先复制并校验配置，再按 `Type` 查连接器、建立连接、验证可达性，最后应用前缀和自动时间戳策略。未注册类型、空连接或连接器错误都会原样返回，不会产生半可用 `*db.DB`。

## 9. 启动期连接行为

应用初始化（`App.Initialize`）阶段处理数据库连接，关键行为：

1. 严格读取 `database.default` 与非空 `database.connections`，验证默认名称确实存在。
2. 按名称排序后逐个 `db.Connect`，按名注册到 `ServiceDBManager`；默认连接注册为 `ServiceDB`。
3. **配置、覆盖或注册失败**：记录错误并设置内部 `startupErr`；不会创建隐式回退连接，也不会把非默认连接提升为默认连接。
4. **连接不可达**：保留已脱敏的 readiness warning，不设置 `startupErr`；应用仍可启动，但访问依赖该连接的功能会返回明确错误。

所有内置 SQL、MongoDB 和 Neo4j 连接器都会在连接阶段执行有界可达性检查；检查失败时会关闭已创建的驱动资源并聚合关闭错误。

启动错误在不同入口的处理不同：

| 入口 | 行为 |
|---|---|
| `go run main.go`（`ApplicationManager.Run`） | 结构性配置、安全或注册错误导致 `startupErr` 非空时**中止启动**；单个连接不可达仅告警并继续启动 |
| `think run`（开发用命令） | 与宿主生命周期一致；连接不可达仅告警，便于数据库未就绪时调试非数据库路由 |
| 其它命令行命令（`version`/`list`/`make:*` 等） | 使用 `framework.BuildConsoleApp` **跳过数据库连接**；解析 `ServiceDB` 返回明确错误 |

> 因此：编写控制台命令时不要假设 `ServiceDB` 可用，需要数据库的自定义命令应自行处理解析错误或单独建立连接。

## 10. 关闭连接

长期运行服务退出前应关闭连接释放连接池。`app.Run()` 会调用幂等的 `app.Close()`；数据库 Provider 会关闭 `ServiceDBManager` 管理的全部命名连接并去重，并把 Provider、缓存、数据库与日志关闭错误聚合返回。

`DB.Close()` 会先冻结新操作，再等待正在执行的查询和事务释放租约后关闭底层连接；并发或重复关闭会得到同一个稳定结果。每个 `Connection` 提供稳定的 `ConnectionID`，多个 `DB` wrapper 共享同一底层身份时由 managed handle 保证只关闭一次。`DBManager.Close()` 关闭后不再允许添加或获取连接。

手动建立的连接由调用方负责 `defer database.Close()`。

## 11. 开发约束规范

- **不要硬编码凭据**：账号、密码、主机等通过 `config/database.json` 或环境变量提供；敏感值（密码）优先用环境变量，不要提交进仓库的 `.env`/JSON。
- **生产连接信息用环境变量注入**：利用「系统环境变量 > `.env`」的优先级，在容器/CI 中覆盖默认配置，不改文件。
- **非默认连接不受 `DB_*` 环境变量影响**：多库场景中只有默认连接能被环境变量覆盖，其余连接的差异化配置必须写入 JSON。
- **控制台命令不得假设 `ServiceDB` 存在**：非 `run` 命令默认跳过连库。
- **连接类型必须是已注册类型**：`type` 取值限于 §2 列表，否则启动报 `connector not found`。
- **SQLite 的 `database` 是普通文件路径或 `:memory:`**，不得夹带 `file:`、`?`、`#` 参数，也不得指向符号链接；注意 CGO 依赖。
- **网络数据库默认使用加密连接**：MySQL、PostgreSQL、MongoDB、Neo4j 均提供安全默认值；本地显式降级只能放在受信配置中。
- **手动 `db.Connect` 必须配对 `Close`**，避免连接泄漏。
- 连接建立属于启动期一次性动作，不要在请求处理中反复 `db.Connect`；请求中复用解析得到的 `*db.DB` / `*db.Manager`。

控制器中按连接使用：

```go
func (c *Order) Recent() *context.Response {
    database, err := framework.ResolveServiceAs[*db.DB](c.App, framework.ServiceDB)
    if err != nil {
        return c.Error("默认数据库不可用", 500)
    }
    manager, err := framework.ResolveServiceAs[*db.Manager](c.App, framework.ServiceDBManager)
    if err != nil {
        return c.Error("数据库管理器不可用", 500)
    }

    // 写走默认连接
    id, err := database.Name("orders").InsertGetId(map[string]interface{}{
        "user_id": 1,
        "amount":  99,
    })
    if err != nil {
        return c.Error("下单失败", 500)
    }

    // 读走只读库
    read, err := manager.Connection("read")
    if err != nil {
        return c.Error("只读库不可用", 500)
    }
    rows, err := read.Name("orders").Order("id DESC").Page(1, 20).Select()
    if err != nil {
        return c.Error("查询失败", 500)
    }
    return context.NewResponse().Json(map[string]interface{}{
        "id":   id,
        "list": rows,
    })
}
```
