# 模型关联

模型支持一对一、一对多、反向关联和多对多关联。关联可以定义后预加载，也可以在已有模型值上立即查询。

## 关联类型

| 类型 | 当前模型 | 关联模型 | 典型含义 |
|---|---|---|---|
| `HasOne` | 本地键 | 关联表外键 | 用户有一个资料 |
| `HasMany` | 本地键 | 关联表外键 | 用户有多个订单 |
| `BelongsTo` | 当前表外键 | 关联表所有者键 | 订单属于用户 |
| `BelongsToMany` | 当前模型本地键 | 中间表和关联表主键 | 用户拥有多个角色 |

关联模型必须是有效的 `*db.Model`，关联名称、外键、本地键、所有者键和中间表名都必须通过标识符校验。

## 定义关联

```go
if err := userModel.DefineHasOne("profile", profileModel, "user_id", "id"); err != nil {
	return err
}

if err := userModel.DefineHasMany("orders", orderModel, "user_id", "id"); err != nil {
	return err
}

if err := orderModel.DefineBelongsTo("user", userModel, "user_id", "id"); err != nil {
	return err
}

if err := userModel.DefineBelongsToMany(
	"roles",
	roleModel,
	"user_role",
	"user_id",
	"role_id",
	"id",
); err != nil {
	return err
}
```

多对多参数含义：

- `pivotTable`：中间表短表名，框架会按当前数据库前缀解析。
- `foreignKey`：当前模型在中间表中的键。
- `relatedForeignKey`：关联模型在中间表中的键。
- `localKey`：当前模型查询结果中的本地键。
- 关联模型使用自身配置的主键读取关联记录。

同一模型不能重复注册同名关联；关联模型、当前模型或任一键非法时返回 `ErrInvalidRelation`。

## 预加载

```go
rows, err := userModel.
	With("profile", "orders", "roles").
	WhereField("status", "=", 1).
	Select()
```

预加载在 `Find`、`Select`、`Paginate` 和 `Chunk` 的列表读取阶段执行。`ChunkById` 与 `SeekPage` 当前只应用模型获取器，不执行 `With` 关联预加载；需要关联数据时应使用 `Chunk` 或在服务层单独批量读取。框架先读取主表关联键，再使用 `IN` 批量读取关联表，避免逐行调用关联查询。

根 `ModelQuery` 通过 `WithContext(ctx)` 绑定的请求上下文会继续传递到关联表和多对多中间表查询，取消或超时可以回收整组预加载请求。多个关联按照 `With` 的声明顺序串行执行，关系较多时应评估额外查询延迟。

结果形态：

- `HasOne`、`BelongsTo`：关联不存在时为 nil map，存在时为单行 map。
- `HasMany`：关联不存在时为空 `[]map[string]interface{}`。
- `BelongsToMany`：没有中间表关联时为空 `[]map[string]interface{}`。

关联模型自己的软删除过滤、获取器和其它模型配置同样适用。`Count` 和普通聚合不会为了预加载而改变统计语义。

## 立即查询

已知本地键值时可以直接查询：

```go
profile, err := userModel.HasOne(profileModel, "user_id", userID)
orders, err := userModel.HasMany(orderModel, "user_id", userID)
user, err := orderModel.BelongsTo(userModel, userID, "id")
roles, err := userModel.BelongsToMany(
	roleModel,
	"user_role",
	"user_id",
	"role_id",
	userID,
)
```

立即查询会先校验模型和关联键。`HasOne` 使用关联模型的 `Find` 语义，只返回第一行；如果业务要求严格一对一，应在数据库建立唯一约束。预加载路径会检查同一键是否返回多行并报错；`BelongsToMany` 先查询中间表，再按关联模型主键批量查询关联记录。

## 键与数据类型

预加载会保留关联键的具体类型。数字 `1` 与字符串 `"1"` 不会被视为同一个键；整数、字符串、布尔、时间和有限浮点等键必须在主表、关联表和中间表中保持稳定类型。nil、NaN、无穷或不支持的复合类型会返回 `ErrInvalidRelation`。

一对一关系要求关联外键唯一。预加载发现同一个本地键对应多条记录时会报错，而不是随机取第一条；反向关联发现所有者键重复时同样报错。

## 投影要求

如果自定义主查询字段，必须保留关联定义依赖的本地键或外键：

```go
rows, err := userModel.
	With("orders").
	Field("id,name").
	Select()
```

上例保留了 `id`，因此可以加载 `orders`。如果省略 `id`，框架会返回缺少关联键的错误。`With` 中的关联名称必须已定义，重复名称和未定义名称会返回 `ErrInvalidRelation`。

## 事务与关联

预加载本身会发起多条查询。如果主表读取、关联读取和后续写入必须观察同一个一致性快照，应在服务层使用事务，并评估当前模型查询器与事务查询的组合；不要在控制器中分别读取多个模型再手动拼接业务结果。
