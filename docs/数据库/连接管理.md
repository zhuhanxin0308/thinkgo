# 连接管理

`framework/db` 将连接、查询状态和连接生命周期分开管理。业务代码通常使用 `*db.DB` 创建查询；需要多数据源时使用 `*db.Manager` 取得命名连接。

## DB 与 Query 的边界

`*db.DB` 只保存底层连接、表前缀、自动时间戳配置和日志器，不保存某一次查询的条件或分页状态。每次调用 `Name`、`Table` 都返回独立查询对象，因此同一个数据库句柄可以被并发请求复用。

```go
database, err := framework.ResolveServiceAs[*db.DB](app, framework.ServiceDB)
if err != nil {
	return err
}

users := database.Name("users")
archive := database.Table("archive_users")
```

`Name` 传入不带前缀的短表名，自动追加 `database.prefix`；`Table` 传入最终完整表名，不追加前缀。`ResolveTableName` 可复用短表名的前缀解析规则：

```go
fullName := database.ResolveTableName("users")
```

不要把 `Name` 和 `Table` 混用：已经包含前缀的表名再次使用 `Name` 会产生重复前缀。

## 建立连接

应用启动时使用 `db.Connect`，它会先校验 `db.Config`，再从连接器注册表查找 `Type` 对应的连接器：

```go
database, err := db.Connect(db.Config{
	Type:     "mysql",
	Hostname: "127.0.0.1",
	Hostport: "3306",
	Database: "thinkgo",
	Username: "root",
})
if err != nil {
	return err
}
defer database.Close()
```

连接器由 `framework/db/connector` 包的 `init` 注册。应用入口需要导入该包以触发内置连接器注册；自定义连接器必须处理注册错误，不能静默覆盖同名连接器。

## 多连接

`db.Manager` 使用安全的连接名称管理多个 `*db.DB`，默认连接名必须在已注册连接中存在：

```go
manager := db.NewManager("mysql")
if err := manager.Add("mysql", mysqlDB); err != nil {
	return err
}
if err := manager.Add("analytics", analyticsDB); err != nil {
	return err
}

defaultDB, err := manager.Default()
analyticsDB, err := manager.Connection("analytics")
```

连接名称只允许安全标识符。`Add` 会拒绝空连接、非法名称、重复名称以及管理器关闭后的写入；`Default` 和 `Connection` 会明确返回默认连接配置错误、连接不存在或管理器已关闭。

应用初始化时，框架按连接名称建立并注册全部 `connections`，再把 `default` 指向的实例注册为 `framework.ServiceDB`。任一连接配置、连接建立或注册失败都会记录为启动错误，不会把其它连接静默提升为默认连接。

非 `run` 的命令行入口使用 `framework.BuildConsoleApp` 时会跳过数据库连接，因此命令代码不能假设 `framework.ServiceDB` 可用。需要数据库的脚本或测试应显式调用 `db.Connect`，并由调用方负责关闭：

```go
database, err := db.Connect(db.Config{
	Type:     "sqlite",
	Database: "runtime/task.db",
})
if err != nil {
	return err
}
defer database.Close()
```

## 关闭顺序

应用退出时统一关闭管理器或应用持有的数据库句柄：

```go
manager, err := framework.ResolveServiceAs[*db.Manager](app, framework.ServiceDBManager)
if err != nil {
	return err
}
if err := manager.Close(); err != nil {
	return err
}
```

`DB.Close` 和 `Manager.Close` 都是幂等的。关闭数据库后会阻止新的数据库租约，并等待已经开始的查询或事务释放租约，再关闭底层连接。多次注册同一个 `*db.DB` 时，管理器只关闭该实例一次，并聚合所有关闭错误。

## 查询上下文

请求内的查询应传入请求上下文：

```go
ctx, cancel := context.WithTimeout(req.Raw().Context(), 3*time.Second)
defer cancel()

rows, err := database.Name("orders").WithContext(ctx).Select()
```

`WithContext(nil)`、`QueryContext(nil, ...)` 和 `ExecuteContext(nil, ...)` 会返回查询错误。内置 SQL 连接会把上下文传给底层驱动；不支持上下文接口的特殊连接会回退到其普通接口。MongoDB 和 Neo4j 连接自身还会施加默认操作超时。

## 底层连接接口

通常不需要直接操作连接。确有高阶驱动能力需求时，可通过 `GetConnection` 获取 `db.Connection`，并先检查返回错误，再进行明确的类型断言。

`db.Connection` 提供统一的查询、插入、更新、删除、计数和关闭能力；SQL 连接额外实现 `RawQueryable` 和上下文接口。MongoDB、Neo4j 实现统一接口，但不因此获得 SQL 的 JOIN、原生 SQL 或事务能力。
