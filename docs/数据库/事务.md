# 事务

事务能力由 `db.Tx` 提供，只适用于 SQL 连接。MongoDB 和 Neo4j 不走该事务封装。

## 闭包事务

推荐使用闭包事务：

```go
err := app.DB.Transaction(func(tx *db.Tx) error {
	if _, err := tx.Name("users").Insert(map[string]interface{}{
		"name": "张三",
	}); err != nil {
		return err
	}

	if _, err := tx.Name("logs").Insert(map[string]interface{}{
		"message": "create user",
	}); err != nil {
		return err
	}

	return nil
})
```

闭包返回 error 时自动回滚；闭包正常返回时自动提交。业务错误与回滚错误通过 `errors.Join` 同时保留，可分别用 `errors.Is` 判断。闭包内 panic 会先回滚，再原样重新抛出；回滚失败会写入脱敏数据库日志。

`Transaction(nil)`、`TransactionContext(nil, fn)` 或空回调会返回 `ErrInvalidTransaction`，不会 panic。

## 带上下文的事务

HTTP 请求内推荐使用请求上下文：

```go
err := app.DB.TransactionContext(req.Raw().Context(), func(tx *db.Tx) error {
	_, err := tx.Name("orders").
		WhereField("id", "=", 1).
		Update(map[string]interface{}{"status": 2})
	return err
})
```

通过 `tx.Name()` 或 `tx.Table()` 创建的查询会自动继承事务上下文。上下文取消后，后续 SQL 会返回驱动/context 错误，闭包返回该错误即可触发回滚。

## 手动事务

```go
tx, err := app.DB.Begin()
if err != nil {
	return err
}

if _, err := tx.Name("users").Insert(data); err != nil {
	return errors.Join(err, tx.Rollback())
}

if err := tx.Commit(); err != nil {
	return err
}
```

提交或回滚是互斥的单次状态转换。重复提交、重复回滚或交叉调用会返回 `ErrTransactionDone`；此后通过该事务创建的 `tx.Name()` / `tx.Table()` 查询同样返回 `ErrTransactionDone`，不会退回普通连接执行。

事务开始时持有数据库连接生命周期租约，提交或回滚后释放。`DB.Close()` 会冻结新事务并等待活动事务结束，再关闭连接池；因此每条手动事务路径都必须明确提交或回滚。

## 隔离级别

需要指定隔离级别或只读事务时使用 `BeginTx`：

```go
tx, err := app.DB.BeginTx(req.Raw().Context(), &sql.TxOptions{
	Isolation: sql.LevelSerializable,
	ReadOnly:  false,
})
```

## Table 与 Name

```go
tx.Table("tg_users") // 完整表名，不加前缀
tx.Name("users")     // 短表名，自动追加前缀
```

事务中的简单查询和 JOIN/GROUP/DISTINCT、聚合、`Inc`/`Dec`、批量写入都使用同一个 `sql.Tx`，并遵守字段与排序校验、参数化查询和无 WHERE 写保护。支持 `RETURNING` 的方言会使用模型配置的实际主键。

## 批量插入与事务

`InsertAll` 在需要分批写入且当前不在事务中时，会自动创建事务包裹所有批次，避免部分批次成功、部分失败。

如果已经在事务中调用 `InsertAll`，它会复用当前事务。任一批次或 `RowsAffected` 读取失败时，错误返回给调用方，由闭包事务统一回滚；自动事务会同时保留执行与回滚错误。

## 常见错误

当前连接不是 SQL 连接、SQL 依赖为空、数据库已关闭或事务已结束时，会返回对应的 `ErrInvalidTransaction`、`ErrDatabaseUnavailable`、`ErrDatabaseClosed` 或 `ErrTransactionDone`，调用方应使用 `errors.Is` 判断。

当前连接不是 SQL 连接时，错误信息包含：

```text
当前数据库连接不支持事务操作
```

控制台命令中使用事务前要确认 `app.DB` 非空，因为非 `run` 命令默认跳过数据库连接。
