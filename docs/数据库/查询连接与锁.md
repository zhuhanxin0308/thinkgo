# 查询连接与锁

## JOIN

查询构造器提供 `Join`、`LeftJoin` 和 `RightJoin`：

```go
database := app.DB()
rows, err := database.Name("orders").
	Join("users", "orders.user_id = users.id").
	WhereField("orders.status", "=", 1).
	Field("orders.id,users.name AS user_name").
	Select()
```

JOIN 条件只允许“字段 操作符 字段”形式，支持 `=`、`!=`、`<>`、`>`、`>=`、`<`、`<=`，多个条件使用 `AND` 连接：

```go
q.Join("users", "orders.user_id = users.id AND orders.tenant_id = users.tenant_id")
```

JOIN 条件不接受值占位符、函数、子查询、OR、注释或任意原生片段。需要更复杂的关联逻辑时，应先评估能否拆成安全的 ORM 条件；确实不能表达时使用服务层参数化原生 SQL。

## 表名和前缀

`Name` 创建的主查询会对 JOIN 表也追加配置前缀：

```go
database.Name("orders").Join("users", "orders.user_id = users.id")
```

如果配置前缀为 `tg_`，主表和 JOIN 表分别解析为 `tg_orders`、`tg_users`。`Table` 创建的查询按完整表名处理，不追加前缀。不要把完整表名传给 `Name`。

## 字段冲突

JOIN 默认只返回主表字段。显式选择关联表字段时，结果 map 的列名必须唯一：

```go
q.Field("orders.id AS order_id,users.id AS user_id,users.name AS user_name")
```

未设置唯一别名的同名列可能在数据库驱动返回时产生冲突，框架会拒绝无法安全解析的结果，而不是静默覆盖已有值。

## 统计与分页

JOIN、GROUP、HAVING、DISTINCT 或锁查询无法通过简单的基础连接接口表达。框架会构造完整 SQL；`Count` 和 `Paginate` 会对完整 SELECT 包一层子查询，统计过滤、分组和去重后的实际结果。

```go
page, err := database.Name("orders").
	Join("users", "orders.user_id = users.id").
	WhereField("users.status", "=", 1).
	Paginate(1, 20)
```

## 悲观锁

```go
row, err := database.Name("accounts").
	WhereField("id", "=", accountID).
	Lock(true).
	Find()
```

`Lock(true)` 请求排他锁，`Lock(false)` 请求共享锁；不传参数时默认排他锁。方言映射如下：

| 方言 | 排他锁 | 共享锁 |
|---|---|---|
| MySQL | `FOR UPDATE` | `LOCK IN SHARE MODE` |
| PostgreSQL | `FOR UPDATE` | `FOR SHARE` |
| SQLite | 不追加行级锁子句 | 不追加行级锁子句 |
| SQL Server | 由连接器按当前能力处理 | 由连接器按当前能力处理 |
| Oracle | 由 Oracle 方言处理 | 由 Oracle 方言处理 |

锁通常应在事务内使用，读取、业务判断和更新放在同一 `db.Tx` 中。MongoDB 和 Neo4j 不支持此 SQL 锁 API。
