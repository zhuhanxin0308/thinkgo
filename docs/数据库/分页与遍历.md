# 分页与遍历

## 分页

```go
database := app.DB()
page, err := database.Name("users").
	WhereField("status", "=", 1).
	Order("id DESC").
	Paginate(2, 20)
```

查询构造器的 `Paginate(page, pageSize)` 返回 `*db.Paginator[map[string]any]`；模型使用 `db.Paginate[T](query, page, pageSize)` 返回 `*db.Paginator[T]`。字段包括：

```text
List Total Page PageSize LastPage HasMore
```

`ToMap` 返回适合 JSON 响应的键：

```text
list total page page_size last_page has_more
```

页码小于 `1` 会归一化为 `1`；页大小小于 `1` 使用 `db.DefaultPageSize`，当前默认值为 `20`。页码乘页大小发生整数溢出、总数为负数或总页数超出 `int` 范围时返回 `ErrInvalidPagination`。

分页先执行 `Count`，再执行带 LIMIT/OFFSET 的列表查询。JOIN、GROUP、HAVING、DISTINCT 会使用完整子查询计数，确保 `total` 与列表查询语义一致。

## 游标分页

大表接口如果不需要精确总数，应使用显式的 `SeekPage`，让下一页从上一页末尾主键继续读取：

```go
page, err := database.Name("users").
	WhereField("status", "=", 1).
	Field("id,name,status").
	SeekPage(20, "id", nil)
if err != nil {
	return err
}
return context.NewResponse().Json(page.ToMap())
```

下一页把 `NextCursor` 编码后传回服务端，再作为 `after` 使用：

```go
nextPage, err := database.Name("users").
	WhereField("status", "=", 1).
	Field("id,name,status").
	SeekPage(20, "id", decodedCursor)
```

查询构造器的 `SeekPage` 返回 `*db.CursorPage[map[string]any]`，包含 `List`、`NextCursor`、`PageSize` 和 `HasMore`。它不会执行 `Count`，也不会使用 `OFFSET`，内部固定按 `pkField ASC` 查询并多读取一行判断是否还有下一页；因此会覆盖查询上原有的 `Order`、`Limit` 和 `Offset`。`pkField` 必须存在于投影中，并且在业务上唯一、非空、严格递增。框架不会自动把 `Paginate` 或 `Chunk` 改写为游标分页。

默认游标只接受整数和 `time.Time`。文本、`[]byte`、按文本返回的 DECIMAL/NUMERIC 或自定义主键必须使用 `SeekPageWithCodec(pageSize, pkField, codec, after)`，codec 的比较规则必须与数据库类型和 collation 一致；否则返回 `ErrUnsupportedCursorKey`。游标缺失、类型漂移或不严格递增返回 `ErrInvalidDatabaseRow`。

## 流式读取

SQL 和 MongoDB 查询可以使用 `Each` 逐行处理大结果集：

```go
err := database.Name("users").
	WhereField("status", "=", 1).
	Order("id ASC").
	Each(func(row map[string]interface{}) bool {
		process(row)
		return true
	})
```

`Each` 不会把完整结果集物化为切片，回调返回 `false` 会立即停止读取并关闭结果集。它保留 `WithContext` 的取消语义；SQL 连接继续执行时间、二进制和重复列校验，MongoDB 连接按游标逐文档规范化并支持显式字段投影。当前 Neo4j 和其它未实现流式能力的连接会返回明确的能力错误。

## OFFSET 分块

```go
err := database.Name("users").Chunk(500, func(rows []map[string]interface{}) bool {
	for _, row := range rows {
		process(row)
	}
	return true
})
```

`Chunk(count, callback)` 使用 OFFSET 分批，每批按 `count` 限制查询。`count` 小于等于 `0` 时使用默认批量大小 `100`；回调不能为空，返回 `false` 会立即结束，不再请求下一批。

OFFSET 适合数据量有限或需要遵循复杂排序的场景。大表深分页会随着 OFFSET 增大而变慢；遍历过程中插入、删除或更新排序数据可能造成漏读或重复。

## 主键游标分块

```go
err := database.Name("users").ChunkById(1000, "id", func(rows []map[string]interface{}) bool {
	for _, row := range rows {
		process(row)
	}
	return true
})
```

`ChunkById` 使用递增游标；`count` 小于等于 `0` 时同样使用默认批量大小 `100`：

```sql
WHERE id > ? ORDER BY id ASC LIMIT ?
```

MongoDB 会把同一语义转换为游标字段的比较过滤、升序排序和限制。它要求游标字段存在、值类型受支持且严格递增。结果缺少游标、游标类型漂移、游标不推进或出现无法比较的值时返回 `ErrInvalidDatabaseRow`。框架在回调前保存下一游标，因此回调修改行数据不会破坏遍历。

主键游标适用于大表全量遍历，但要求游标是稳定的递增字段，并且业务应为过滤条件与游标字段建立匹配索引。框架不会自动创建索引，也不会把普通 `Chunk` 或 `Paginate` 隐式改写成游标查询。若业务主键不是 `id`，应传入实际字段；模型配置了自定义主键时也应使用该主键。

## 模型遍历

模型层统一使用泛型函数，原 `ModelQuery.Paginate/SeekPage/Chunk/ChunkById` 调用需迁移。普通 DTO 使用值类型；嵌入 `*db.Model`、需要保存的记录使用指针类型。

```go
query := userModel.With("profile").WhereField("status", "=", 1).Order("id")
page, err := db.Paginate[UserOutput](query, 1, 20)

err = db.ChunkById(query, 500, func(rows []*User) (bool, error) {
	if err := handleUsers(rows); err != nil {
		return false, err
	}
	return true, nil
})
```

`db.Paginate`、`db.SeekPage`、`db.Chunk` 和 `db.ChunkById` 均继承事务、软删除、获取器及显式 `With` 关联。关联按当前可见页或批次加载，额外探测行不会执行获取器或进入关联查询。分页列表为空时为非 nil 空切片；映射失败不返回部分分页，也不把失败批次交给回调。

```go
page, err := db.SeekPage[UserOutput](query, 50, nil)
nextPage, err := db.SeekPage[UserOutput](query, 50, page.NextCursor)
```

`db.SeekPage` 默认使用模型主键，显式游标列和排序 codec 使用 `db.SeekPageWithCodec[T](query, size, field, codec, after)`；分批入口为 `db.ChunkByIdWithCodec(query, size, field, codec, callback)`。游标保存数据库原始值，不受获取器或回调修改展示字段影响；DTO 可不声明游标字段，但数据库投影必须包含它。跨 HTTP 传递时应保持原始整数精度和数据库类型；需要固定游标协议的接口可自行编码并声明对应响应 DTO。

`db.Chunk` 保留显式排序，未排序时使用模型主键；每批多取一行判断是否结束。回调返回 `(false, nil)` 正常停止，返回错误立即终止，取消上下文会返回取消错误。批次之间不复用列表或模型实例。修改筛选结果集的任务使用主键游标；需要整体原子性或一致快照时，由业务绑定具有相应隔离级别的事务并处理返回错误。

`Paginator[T]` 与 `CursorPage[T]` 可直接作为 JSON 响应和 `openapi.RegisterTyped` 的输出类型。字段采用 `list`、`page_size`、`has_more` 等 JSON 名称；游标分页的 `next_cursor` 由驱动决定类型，OpenAPI 保留其动态 JSON 值语义。
