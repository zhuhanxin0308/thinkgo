# 模型

`db.Model` 是表名、模型配置和模型查询器的薄封装。业务模型通常嵌入 `*db.Model`，由服务层调用；控制器不直接操作模型。

## 应用层组织

业务模型统一放在 `app/<应用名>/model` 目录下，不在该目录下继续创建业务子目录。一张真实表对应一个模型文件，模型文件使用真实表名命名，不增加 `Model`、`Entity` 等文件后缀，例如：

```text
app/index/model/users.go
app/index/model/orders.go
app/index/model/order_items.go
```

模型名称、文件名和表名应保持可读的一致关系。使用 `NewModelAuto` 时，结构体名称必须能准确推断真实表名。

## 自动推断表名

```go
package model

import "thinkgo/framework/db"

// Users 对应 users 表。
type Users struct {
	*db.Model
}

// NewUsers 创建用户模型。
func NewUsers(database *db.DB) (*Users, error) {
	base, err := db.NewModelAuto(database, Users{})
	if err != nil {
		return nil, err
	}
	return &Users{Model: base}, nil
}
```

`NewModelAuto` 和 `GetTableName` 只做具名结构体名称到小写蛇形的转换，不自动复数化：

```text
Users         -> users
AdminUsers    -> admin_users
OrderItems    -> order_items
RBACApiRoutes -> rbac_api_routes
```

`nil`、匿名结构体、非结构体或无法验证的模型会返回 `ErrInvalidModel`。数据库表名如果和推断结果不同，必须显式绑定，不要依赖猜测：

```go
// UserRecord 实际对应 user_records 表，使用显式表名。
type UserRecord struct{ *db.Model }

func NewUserRecord(database *db.DB) *UserRecord {
	return &UserRecord{Model: db.NewModel(database, "user_records")}
}
```

## 写入与更新

```go
affected, err := userModel.Insert(map[string]interface{}{
	"name": "张三",
})

id, err := userModel.InsertGetId(map[string]interface{}{
	"name": "李四",
})

updated, err := userModel.
	Where("id = ?", id).
	Update(map[string]interface{}{"name": "王五"})
```

模型会复制传入的 `map`；修改器、事件、自动时间戳和主键回填只修改内部工作副本。`Update` 必须包含调用方提供的业务 WHERE 条件，无条件 `UpdateMap` 会返回 `ErrUnsafeFullTableMutation`。

结构体写入：

```go
type UserRow struct {
	ID   int64  `thinkgo:"id,omitempty"`
	Name string `thinkgo:"name"`
}

row := &UserRow{Name: "张三"} // 必须传入非 nil 指针
err := userModel.Create(row)

	// ThinkPHP 风格：零值主键执行新增，非零主键按主键执行更新。
	row.Name = "李四"
	err = userModel.Save(row)
```

结构体更新要求主键非零，并会把主键从 `SET` 子句中剔除：

```go
row.Name = "李四"
err = userModel.Update(row)
```

## 显式配置

```go
userModel := db.NewModel(database, "user").
	PrimaryKey("id").
	AutoTimestamp(true).
	CreateTimeField("created_at").
	UpdateTimeField("updated_at")
```

`Create` 要求非 nil 结构体指针；零值主键会从 INSERT 中移除，并把数据库返回值按模型配置回填到原结构体。`Save` 与 ThinkPHP 模型语义一致：零值主键调用新增流程，非零主键调用按主键更新流程。`thinkgo:"-"` 跳过字段，`thinkgo:"col,omitempty"` 在零值时跳过字段；非法、重复或不可写字段会返回错误。

## 主键

默认主键是 `id`：

```go
userModel.PrimaryKey("user_id")
```

非默认主键模型在插入主键回传、关联预加载、多对多和结构体更新时必须显式声明主键。非法主键标识符会形成模型配置错误，并由后续终端方法返回。

MongoDB 是逻辑名与存储名不同的特例：未显式调用 `PrimaryKey` 时，模型字段 `id` 自动映射到 MongoDB 固有 `_id`，Create/Save/Find/Delete 可直接围绕结构体 `ID string` 完整往返。显式 `PrimaryKey("id")` 表示集合确实存在业务字段 `id`，会关闭默认映射；应用必须在 Create/Save 前提供非零业务主键，否则在 Insert 前返回 `ErrInvalidModel`。显式 `PrimaryKey("_id")` 则要求结构体主键使用 `thinkgo:"_id"` 标签。默认映射的逻辑 `id` 和存储 `_id` 均不可通过 Update 修改，违规时在驱动写入前返回 `ErrInvalidQuery`。该规则只属于 Model 层，直接 Query API 仍按调用方给出的字段名执行。

结构体主键支持有符号/无符号整数、字符串、MongoDB `bson.ObjectID` 和空接口；实际可用类型仍受当前驱动的 `DriverCapabilities` 约束。`Create`/新增分支的 `Save` 会在访问数据库前验证主键字段存在、可写且与驱动 ID 类型兼容，因此配置错误不会造成“记录已插入但结构体无法回填”。若驱动在运行期返回了声明之外的 ID 类型或数值溢出，写入已完成时会返回可由 `errors.Is(err, db.ErrPartialWrite)` 识别的 `*db.PartialWriteError`；其中保留 `InsertResult`，调用方必须据此对账，不能直接重试插入。

## 自动时间戳

数据库配置启用 `auto_timestamp` 后，模型会继承全局配置。也可以单独设置：

时间值类型由 `timestamp_value_type` 控制：

```text
unix datetime timestamp date native
```

`datetime`、`timestamp` 和 `date` 的自动值按应用 `default_timezone` 生成；`native` 使用 `time.Time` 作为参数并交给数据库驱动处理。ORM 写入边界（含事务和批量写入）以及显式时间条件会先把 `time.Time` 统一到该时区，但不改变绝对时刻。`unix` 保存绝对时刻，不受时区影响。框架 JSON 响应会把 `time.Time` 统一输出为 RFC3339 UTC，前端不应依赖服务器本地时区。

模型中的表名是不带前缀的短表名，模型查询内部使用 `DB.Name` 解析前缀。`SetDB` 可给已经创建的模型绑定数据库，但数据库不能为空；`Table` 可修改模型的短表名并返回模型本身。

## 模型能力

- 查询：`Where`、`Find`、`Select`、`Count`、`Order`、`Field`、`Paginate`、`SeekPage`、`Chunk` 和 `ChunkById`。
- 写入：`Insert`、`UpdateMap`、`DeleteRecord`、`Create`、`Update`、`Delete`、`ForceDelete` 和 `Restore`。
- 字段行为：结构体标签、获取器、修改器和搜索器。
- 生命周期：自动时间戳、软删除和六类模型事件。
- 关联：一对一、一对多、反向关联、多对多、立即查询和预加载。

## 分层调用

服务层负责组合模型查询和业务规则：

```go
// UserService 负责用户业务，不把数据库查询暴露给控制器。
type UserService struct {
	users *model.Users
}

func (s *UserService) Find(ctx context.Context, id int64) (map[string]interface{}, error) {
	return s.users.Where("id = ?", id).
		WithContext(ctx).
		Find()
}
```

控制器应先使用验证器校验请求参数，再调用服务。复杂查询优先继续使用模型查询器和 ORM；只有安全查询器无法表达时才在服务或仓储层使用[原生 SQL](原生SQL.md)。
`Update`、`Delete`、`ForceDelete` 和 `Restore` 都要求业务 WHERE 条件。框架自动注入的 `delete_time IS NULL` / `IS NOT NULL` 不算业务条件，不能绕过全表保护。`Restore` 仅适用于已启用软删除的模型。

## 获取器与修改器

```go
err := userModel.Getter("status", func(value interface{}, row map[string]interface{}) interface{} {
	if fmt.Sprint(value) == "1" {
		return "启用"
	}
	return "禁用"
})

err = userModel.Setter("password", func(value interface{}, row map[string]interface{}) interface{} {
	return hashPassword(fmt.Sprint(value))
})
```

获取器作用于查询结果，修改器作用于插入和更新数据。`Getter`、`Setter`、`Searcher`、`On` 都返回 `error`；字段非法、回调为 `nil` 或重复注册会返回 `ErrInvalidModel`，调用方必须处理。

## 搜索器

```go
err := userModel.Searcher("keyword", func(q *db.Query, value interface{}, data map[string]interface{}) *db.Query {
	return q.WhereLike("name", "%"+fmt.Sprint(value)+"%")
})

rows, err := userModel.WithSearch(
	[]string{"keyword"},
	map[string]interface{}{"keyword": "go"},
).Select()
```

Query 链为不可变对象，因此 Searcher 必须返回追加条件后的 `*db.Query`；旧的无返回值回调不再兼容。

## 模型事件

```go
err := userModel.On(db.ModelBeforeInsert, func(data map[string]interface{}) bool {
	return data["name"] != ""
})
```

事件类型：

```text
before_insert after_insert before_update after_update before_delete after_delete
```

`before_*` 回调返回 `false` 会阻止操作。同一事件可注册多个回调并按注册顺序执行：前一个回调接受的修改会传给后一个回调，但每个回调收到独立的深拷贝，不能反向修改调用方或已执行回调保存的数据。`after_*` 在数据库操作完成后触发，每个回调同样获得独立快照；插入/更新载荷包含实际持久化的主键和自动时间戳，软删除/物理删除载荷包含最终持久化字段及删除统计。未知事件类型或 `nil` 回调会返回 `ErrInvalidModel`。

## 关联定义

一对一：

```go
err := userModel.DefineHasOne("profile", profileModel, "user_id", "id")
```

一对多：

```go
err := userModel.DefineHasMany("orders", orderModel, "user_id", "id")
```

反向关联：

```go
err := orderModel.DefineBelongsTo("user", userModel, "user_id", "id")
```

多对多：

```go
err := userModel.DefineBelongsToMany("roles", roleModel, "user_role", "user_id", "role_id", "id")
```

预加载：

```go
rows, err := userModel.With("profile", "orders").Select()
```

所有关联定义方法都返回 `error`，并拒绝无效模型、非法键和重复名称。预加载始终使用数据库返回的原始关系键建立内部索引，再把获取器应用到公开结果，因此 getter 改写外键或主键的展示值不会破坏 has-one、has-many、belongs-to 或 belongs-to-many 匹配。分组仍区分键的具体类型，数字 `1` 与字符串 `"1"` 不会串联；缺失关联键、唯一键重复、一对一返回多行、重复预加载或未定义关联会返回 `ErrInvalidRelation`。

## 分页与遍历

```go
p, err := userModel.Where("status = ?", 1).Paginate(1, 20)

err = userModel.ChunkById(1000, "id", func(rows []map[string]interface{}) bool {
	return true
})
```

模型分页会自动应用获取器和关联预加载。

## 上下文

```go
rows, err := userModel.
	Where("status = ?", 1).
	WithContext(req.Raw().Context()).
	Select()
```

HTTP 请求中建议传入请求上下文，使数据库操作随请求取消。
