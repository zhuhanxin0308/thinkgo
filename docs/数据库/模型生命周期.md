# 模型生命周期

模型生命周期由自动时间戳、软删除、获取器/修改器配合模型事件组成。终端模型写入方法会按统一顺序执行这些能力。

## 自动时间戳

数据库连接可以全局启用自动时间戳，模型也可以单独覆盖：

```go
userModel.
	AutoTimestamp(true).
	CreateTimeField("created_at").
	UpdateTimeField("updated_at")
```

插入时缺失或为零值的创建时间和更新时间会自动填充；更新时更新时间会自动填充。已有的非零时间不会被覆盖。支持的落库类型：

```text
unix      Unix 秒级整数
datetime  2006-01-02 15:04:05
timestamp 2006-01-02 15:04:05
date      2006-01-02
native    驱动原生 time.Time
```

字段值为整数、字符串、`time.Time` 或 nil 时，框架会按类型和配置处理；窄整数无法容纳当前 Unix 时间或不支持的零值类型会返回错误。

## 软删除

```go
userModel.SoftDelete("deleted_at")

active, err := userModel.Select()
all, err := userModel.WithTrashed().Select()
deleted, err := userModel.OnlyTrashed().Select()
```

启用软删除后：

- 默认查询自动追加 `deleted_at IS NULL`。
- `WithTrashed` 包含全部记录。
- `OnlyTrashed` 只查询已删除记录。
- `Delete` 更新删除时间字段，不执行物理 DELETE。
- `ForceDelete` 忽略软删除配置，执行物理删除。
- `Restore` 将删除时间字段恢复为空。

模型 `Update`、`Delete`、`ForceDelete` 和 `Restore` 都要求调用方显式提供业务 WHERE。自动注入的软删除条件不能替代业务条件。

## 事件

```go
if err := userModel.On(db.ModelBeforeInsert, func(data map[string]interface{}) bool {
	return data["name"] != ""
}); err != nil {
	return err
}
```

支持的事件：

```text
before_insert  after_insert
before_update  after_update
before_delete  after_delete
```

同一事件可以注册多个回调，并按注册顺序执行。`before_*` 回调返回 `false` 时会阻止操作；`after_*` 返回值不会阻止已经完成的数据库操作。未知事件类型、nil 回调或非法模型配置会返回 `ErrInvalidModel`。

## 执行顺序

单行模型写入的逻辑顺序可以理解为：

```text
复制输入 -> 修改器 -> before 事件 -> 自动时间戳/SQL 执行 -> 主键回填 -> after 事件
```

模型删除会根据软删除配置在 SQL 执行前选择 UPDATE 或 DELETE，但仍触发删除前后事件。事件回调不应执行不可逆的外部副作用；需要和数据库结果一致的审计或消息发送应放在事务服务中处理。

## 获取器与修改器

获取器只作用于模型 `Find` 和 `Select` 返回的行；修改器作用于模型插入和更新数据：

```go
if err := userModel.Getter("status", func(value interface{}, row map[string]interface{}) interface{} {
	if fmt.Sprint(value) == "1" {
		return "启用"
	}
	return "禁用"
}); err != nil {
	return err
}
```

字段名、回调和重复注册都会校验。获取器按照字段名稳定顺序执行；关联预加载结果也会使用关联模型的获取器。
