# 查询构造器

查询构造器由 `app.DB.Table()` 或 `app.DB.Name()` 创建。每次调用都会返回新的 `Query` 实例，不跨请求共享状态。

## Table 与 Name

```go
// 使用完整表名，不追加前缀。
app.DB.Table("tg_users")

// 使用短表名，自动追加 database.prefix。
app.DB.Name("users")
```

JOIN 表会跟随主表的前缀规则。

## 查询数据

```go
row, err := app.DB.Name("users").
	WhereField("id", "=", 1).
	Find()

rows, err := app.DB.Name("users").
	WhereLike("name", "%张%").
	Order("id DESC").
	Page(1, 20).
	Select()
```

`Find` 会在克隆查询上设置 `LIMIT 1`，不会污染原查询对象。

## Where 条件

推荐使用安全 API：

```go
q := app.DB.Name("users").
	WhereField("status", "=", 1).
	WhereIn("id", []interface{}{1, 2, 3}).
	WhereBetween("age", 18, 60).
	WhereLike("name", "%go%").
	WhereNull("deleted_at")
```

`Where` 兼容多种形式：

```go
q.Where("id = ?", 1)
q.Where("status", 1)
q.Where("age", ">=", 18)
q.Where(map[string]interface{}{"status": 1})
q.Where([][]interface{}{{"age", ">=", 18}, {"status", "=", 1}})
q.Where(func(g *db.ConditionGroup) {
	g.Where("status = ?", 1).WhereOr("status = ?", 2)
})
```

普通 `Where` 会校验字段、操作符、参数数量和谓词形式。复杂表达式使用 `WhereRaw`：

```go
q.WhereRaw("JSON_EXTRACT(profile, '$.role') = ?", "admin")
```

`WhereRaw` 是显式原生 SQL 入口，调用方必须自行保证参数化和输入安全。

## 字段、排序和分组

```go
q.Field("id,name,email")
q.Order("id DESC")
q.Group("status")
q.Having("total > ?", 10)
q.HavingField("total", ">", 10)
```

字段列表、排序字段、分组字段会做标识符白名单校验。聚合函数形式的复杂 HAVING 请用 `HavingRaw`。

## JOIN

```go
rows, err := app.DB.Name("orders").
	Join("users", "orders.user_id = users.id").
	WhereField("orders.status", "=", 1).
	Field("orders.id,users.name").
	Select()
```

JOIN 条件只允许 `field op field` 形式，支持 `AND` 连接多个条件。字段支持 `table.field`。

## 写入数据

```go
id, err := app.DB.Name("users").Insert(map[string]interface{}{
	"name": "张三",
	"age":  18,
})
```

插入数据不能为空；空 `map` 会返回错误，避免生成跨方言不可靠的空字段 INSERT。

批量插入：

```go
affected, err := app.DB.Name("users").InsertAll([]map[string]interface{}{
	{"name": "a", "age": 1},
	{"name": "b", "age": 2},
})
```

`InsertAll` 要求每行至少包含一个字段，且每行字段集合一致。占位符数量超过方言上限时自动分批，多批写入会包裹事务保证原子性；SQL Server 按 2100 参数上限分批，SQLite 和 Oracle 按 1000 以内的保守预算分批，MySQL 和 PostgreSQL 使用高参数预算。

## 更新与删除

```go
affected, err := app.DB.Name("users").
	WhereField("id", "=", 1).
	Update(map[string]interface{}{"name": "李四"})

affected, err = app.DB.Name("users").
	WhereField("id", "=", 1).
	Delete()
```

无 WHERE 的 `Update` 和 `Delete` 会被拒绝，防止误更新或误删全表。普通 `Update` 的数据不能为空；仅使用 `Inc`/`Dec` 生成 SET 表达式时可传空 `map`。

自增自减：

```go
affected, err := app.DB.Name("users").
	WhereField("id", "=", 1).
	Inc("score", 5).
	Update(map[string]interface{}{})
```

## 聚合与字段读取

```go
total, err := app.DB.Name("orders").Count()
sum, err := app.DB.Name("orders").Sum("amount")
avg, err := app.DB.Name("orders").Avg("amount")
max, err := app.DB.Name("orders").Max("amount")
min, err := app.DB.Name("orders").Min("amount")

name, err := app.DB.Name("users").WhereField("id", "=", 1).Value("name")
names, err := app.DB.Name("users").Column("name")
nameMap, err := app.DB.Name("users").Column("name", "id")
```

`Count` 对 JOIN、GROUP、HAVING、DISTINCT 会自动包一层子查询统计真实总数。

## 分页

```go
p, err := app.DB.Name("users").
	WhereField("status", "=", 1).
	Paginate(1, 20)

return context.NewResponse().Json(p.ToMap())
```

分页结果包含：

```text
list total page page_size last_page has_more
```

## 分块遍历

```go
err := app.DB.Name("users").Chunk(100, func(rows []map[string]interface{}) bool {
	return true
})

err = app.DB.Name("users").ChunkById(1000, "id", func(rows []map[string]interface{}) bool {
	return true
})
```

大表遍历优先使用 `ChunkById`，避免 OFFSET 深分页性能下降和数据增删造成漏读。

## 悲观锁

```go
row, err := app.DB.Name("users").
	WhereField("id", "=", 1).
	Lock(true).
	Find()
```

MySQL 使用 `FOR UPDATE` 或 `LOCK IN SHARE MODE`，PostgreSQL 使用 `FOR UPDATE` 或 `FOR SHARE`，SQLite 和 SQL Server 不输出尾部锁子句。

## 上下文

```go
ctx, cancel := context.WithTimeout(req.Raw().Context(), 3*time.Second)
defer cancel()

rows, err := app.DB.Name("users").
	WithContext(ctx).
	Select()
```

内置 SQL 连接支持 context 取消和超时。

## 原生 SQL

```go
rows, err := app.DB.Query("SELECT * FROM users WHERE id = ?", 1)
affected, err := app.DB.Execute("UPDATE users SET name = ? WHERE id = ?", "张三", 1)
```

原生 SQL 统一使用 `?` 占位符，框架按方言转换为 `$1`、`@p1`、`:1` 等形式。错误日志只记录参数数量，不记录参数值；原生 SQL 或 `WhereRaw` 中的字符串字面量会被脱敏后再写入日志。
