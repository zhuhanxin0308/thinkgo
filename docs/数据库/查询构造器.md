# 查询构造器

查询构造器由 `*db.DB`、`*db.Tx` 或模型创建，用于构造一次独立的查询。链式方法会返回当前查询对象，终端方法才真正访问数据库。

## 创建查询
链式方法采用不可变语义，必须接收返回的新 Query。`query.WhereField(...)` 若不赋值或不继续链式调用，不会修改原对象；同一个 base Query 可以安全派生多个并发分支。

## Table 与 Name

```go
database, err := framework.ResolveServiceAs[*db.DB](app, framework.ServiceDB)
if err != nil {
	return err
}
query := database.Name("users")
fullTableQuery := database.Table("tg_users")
```

两种入口的表名语义不同：

| 入口 | 参数 | 是否追加 `prefix` |
|---|---|---|
| `DB.Name` | 不带前缀的短表名 | 是 |
| `DB.Table` | 最终完整表名 | 否 |

JOIN 表沿用主查询的前缀规则。`Name("users")` 下的 `Join("orders", ...)` 会对两个短表名追加前缀；`Table("tg_users")` 下的 JOIN 表按完整名称处理。

## 链式与终端方法

查询条件和查询选项可以组合：

```go
rows, err := database.Name("users").
	WhereField("status", "=", 1).
	Field("id,name,email").
	Order("id DESC").
	Limit(20).
	Select()
```

常用终端方法包括：

- `Find`：返回第一行；没有记录时返回 `nil, nil`。
- `Select`：返回行映射切片。
- `Count`：返回精确的非负 `int64` 总数。
- `Insert`、`Update`、`Delete`：返回影响行数或插入结果。
- `Paginate`、`SeekPage`、`Chunk`、`ChunkById`、`Each`：执行页码分页、游标分页、分块或流式查询。
- `Sum`、`Avg`、`Max`、`Min`、`Value`、`Column`：读取聚合或字段结果。

`Find` 会在查询副本上追加 `LIMIT 1`。`Paginate`、模型软删除条件和复杂 `Count` 也会在副本上构造，原查询对象不会被终端方法污染，可以重复执行。

## 查询状态与并发

`DB.Name`、`DB.Table` 和查询的链式操作都不会把状态写入全局单例。框架在执行前复制条件、参数、JOIN、分组和写入表达式；同一个已经构造好的查询可以在只读场景下复用，业务代码仍应避免在多个 goroutine 中同时修改同一个链式对象。

模型查询器 `*db.ModelQuery` 在底层查询之上增加获取器、软删除、修改器、事件和关联预加载，详见[模型查询](模型查询.md)。

## SQL 生成

`BuildSelectSQL` 可以构造完整 SELECT SQL 和绑定参数，适合调试或作为内部子查询来源：

```go
sqlText, args, err := database.Name("orders").
	WhereField("status", "=", 1).
	BuildSelectSQL()
```

业务代码不应把用户输入直接放入表名、字段名、排序或 SQL 片段。安全入口会校验标识符、操作符和占位符；复杂、确实需要原生语法的场景才使用显式的 Raw API，规则见[原生 SQL](原生SQL.md)。

## 写入安全

结构化 ORM 的 `Update` 和 `Delete` 必须存在调用方提供的业务 `WHERE`，否则返回 `ErrUnsafeFullTableMutation`。模型自动注入的软删除条件不算业务条件。普通更新数据不能为空；只使用 `Inc` 或 `Dec` 时可以传空 `map`。
普通 `Where` 会校验字段、操作符、参数数量和谓词形式；`map` 条件按字段名排序，SQL 与参数顺序稳定。`WhereTime` 按数据库 `timestamp_value_type` 转换时间，字段类型不同于默认值类型时使用 `WhereTimeAs`；两者都拒绝零时间、空值和 NaN/Inf。复杂表达式使用 `WhereRaw`：

```go
q.WhereRaw("JSON_EXTRACT(profile, '$.role') = ?", "admin")
```

`WhereRaw` 是显式原生 SQL 入口，调用方必须自行保证参数化和输入安全。

## 字段、排序和分组

```go
q.Field("id,name,email")
q.Order("id DESC")
q.Group("status")
q.Having("total > ?", 10)
q.HavingField("total", ">", 10)
```

字段列表、别名、排序字段、分组字段会做标识符白名单校验，并由当前 SQL 方言引用标识符。聚合函数形式的复杂 HAVING 请用 `HavingRaw`。

Oracle 的 `Name`/`Table`/字段/排序等逻辑标识符按普通未引用 schema 规则规范化为大写后引用，例如 `app.users` 生成 `"APP"."USERS"`。确实使用大小写敏感 quoted schema 时，请在受信边界使用显式原生 SQL。

## JOIN

```go
rows, err := database.Name("orders").
	Join("users", "orders.user_id = users.id").
	WhereField("orders.status", "=", 1).
	Field("orders.id,users.name").
	Select()
```

JOIN 条件只允许 `field op field` 形式，支持 `AND` 连接多个条件。字段支持 `table.field`。未调用 `Field` 时，框架默认投影 `主表.*`，不会把关联表的同名列写入结果 map；需要关联表字段时必须显式选择，并为所有同名列设置唯一别名。

## 写入数据

```go
affected, err := database.Name("users").Insert(map[string]interface{}{
	"name": "张三",
	"age":  18,
})

id, err := database.Name("users").InsertGetId(map[string]interface{}{
	"name": "李四",
	"age":  20,
})
```

`Insert` 与 ThinkPHP 一样返回影响行数；只有 `InsertGetId` 返回驱动报告的真实主键。插入数据不能为空；空 `map` 会返回错误。框架先复制调用方 `map`，自动时间戳、模型修改器和主键回填不会修改调用方持有的数据。支持 `RETURNING` 的方言使用模型实际主键，不再固定为 `id`；驱动不能提供主键时 `InsertGetId` 返回 `ErrInsertIDUnavailable`，不会用影响数冒充。

`Save(data)` 在没有 WHERE 时插入，有 WHERE 时更新；`Save(data, true)` 强制插入。force flag 超过一个会返回 `ErrInvalidQuery`。

批量插入：

```go
affected, err := database.Name("users").InsertAll([]map[string]interface{}{
	{"name": "a", "age": 1},
	{"name": "b", "age": 2},
})
```

`InsertAll` 会逐行复制输入，要求每行至少包含一个字段且字段集合一致。占位符数量超过方言上限时自动分批，多批写入会包裹事务保证原子性；任一批次执行或读取影响行数失败时回滚，并同时保留业务错误与回滚错误。

## 更新与删除

```go
affected, err := database.Name("users").
	WhereField("id", "=", 1).
	Update(map[string]interface{}{"name": "李四"})

affected, err = database.Name("users").
	WhereField("id", "=", 1).
	Delete()
```

需要区分 matched/modified 或保留删除副作用时使用 `UpdateResult` / `DeleteResult`。普通 `Update` 优先返回可证明的真实修改数，否则返回驱动影响数。无 WHERE 的 `Update` 和 `Delete` 会被拒绝，防止误更新或误删全表。普通 `Update` 的数据不能为空；仅使用 `Inc`/`Dec` 生成 SET 表达式时可传空 `map`。

自增自减：

```go
affected, err := database.Name("users").
	WhereField("id", "=", 1).
	Inc("score", 5).
	Update(nil)
```

`Inc`/`Dec` 的步长必须是正整数，最多传一个；字段名、算术符和步长都会由框架生成或绑定，步长不会内联进 SQL。同一字段不能重复配置增减表达式，也不能同时出现在 `Update` 数据中。

## 聚合与字段读取

```go
total, err := database.Name("orders").Count()
sum, err := database.Name("orders").Sum("amount")
avg, err := database.Name("orders").Avg("amount")
max, err := database.Name("orders").Max("amount")
min, err := database.Name("orders").Min("amount")

name, err := database.Name("users").WhereField("id", "=", 1).Value("name")
names, err := database.Name("users").Column("name")
nameMap, err := database.Name("users").Column("name", "id")
```

`Count` 对 JOIN、GROUP、HAVING、DISTINCT 会自动包一层子查询统计真实总数。聚合值会按驱动常见整数、浮点、文本和 `json.Number` 类型精确解析；负数计数、非整数计数、溢出、NaN/Inf 或非法文本会返回 `ErrInvalidAggregateValue`，不会静默当作零。

`Value` 要求结果确实包含目标字段。`Column(field, key)` 要求每行同时包含目标字段和 key；两者都支持 `table.column` 限定字段，并兼容 SQL 驱动返回末段列名。重复 key 或字符串化后冲突会返回 `ErrInvalidDatabaseRow`，不会覆盖先前数据。

## 分页

```go
p, err := database.Name("users").
	WhereField("status", "=", 1).
	Paginate(1, 20)

return context.NewResponse().Json(p.ToMap())
```

分页结果包含：

```text
list total page page_size last_page has_more
```

`Paginator.Offset()` 返回 `(int, error)`，页码与页大小相乘溢出时返回 `ErrInvalidPagination`。`Paginate` 不修改原查询对象，可安全重复执行。

## 流式查询

```go
err := database.Name("users").Each(func(row map[string]interface{}) bool {
	return handleRow(row)
})
```

`Each` 支持 SQL 和 MongoDB 连接，按行读取并在结束或回调返回 `false` 时关闭底层结果集；它不会构造完整 `[]map[string]interface{}`。长时间运行的流式查询应绑定 `WithContext(ctx)`；Neo4j 和其它未实现流式能力的连接会返回明确的能力错误。

## 分块遍历

```go
err := database.Name("users").Chunk(100, func(rows []map[string]interface{}) bool {
	return true
})

err = database.Name("users").ChunkById(1000, "id", func(rows []map[string]interface{}) bool {
	return true
})
```

`SeekPage` 适合不需要精确总数的大表列表接口：首页传入 `after=nil`，后续页面传入上一页返回的 `NextCursor`：

```go
page, err := database.Name("users").
	WhereField("status", "=", 1).
	Field("id,name,status").
	SeekPage(20, "id", nil)
if err != nil {
	return err
}
if page.HasMore {
	// 将 page.NextCursor 编码后返回给客户端。
}
```

框架会固定使用 `pk ASC` 并读取 `pageSize+1` 行，查询上已有的 `Order`、`Limit`、`Offset` 不会影响游标分页。`pk` 必须同时满足：存在于查询投影、唯一、非空并严格递增。不能满足这些约束时不要使用 `SeekPage`，也不要依赖框架自动改写 `Paginate` 或 `Chunk`。

回调不能为空；返回 `false` 会立即停止且不再发起下一批查询。默认 `ChunkById` 只接受整数和 `time.Time` 游标。文本、`[]byte`、驱动按文本返回的 DECIMAL/NUMERIC 或自定义主键必须调用 `ChunkByIdWithCodec`，并提供与数据库列类型及 collation 一致的 `db.CursorCodec`；框架不会再用 Go 字典序猜测数据库排序。缺失、类型漂移或不推进会返回 `ErrInvalidDatabaseRow`，未提供必需 codec 时返回 `ErrUnsupportedCursorKey`。

```go
type binaryTextCodec struct{}

func (binaryTextCodec) Compare(previous, next interface{}) (int, error) {
	left, leftOK := previous.(string)
	right, rightOK := next.(string)
	if !leftOK || !rightOK {
		return 0, db.ErrInvalidDatabaseRow
	}
	return strings.Compare(left, right), nil
}

err = database.Name("users").ChunkByIdWithCodec(1000, "code", binaryTextCodec{}, func(rows []map[string]interface{}) bool {
	return true
})
```

游标分页的文本或自定义主键使用同样的显式 codec：

```go
page, err = database.Name("users").SeekPageWithCodec(20, "code", binaryTextCodec{}, nil)
```

自定义 codec 的 `Compare(previous, next any) (int, error)` 必须与目标列的真实排序规则相同；例如 Go 字节序比较只适合数据库二进制 collation。框架在调用回调前复制下一游标，因此回调修改结果行不会破坏推进。大表遍历优先使用 keyset 方式，避免 OFFSET 深分页性能下降和数据增删造成漏读。

## 悲观锁

```go
row, err := database.Name("users").
	WhereField("id", "=", 1).
	Lock(true).
	Find()
```

锁能力不会再被静默忽略：

| 方言 | 排他锁 | 共享锁 | 分页 + 锁 |
|---|---|---|---|
| MySQL | `FOR UPDATE` | `LOCK IN SHARE MODE` | builder 支持，需目标版本实服复核 |
| PostgreSQL | `FOR UPDATE` | `FOR SHARE` | builder 支持，需实服复核 |
| SQLite | 返回 `ErrUnsupportedFeature` | 返回 `ErrUnsupportedFeature` | 不支持 |
| SQL Server | 主表后 `WITH (UPDLOCK, ROWLOCK)` | 主表后 `WITH (HOLDLOCK, ROWLOCK)` | builder 支持，待实服复核 |
| Oracle | `FOR UPDATE` | 返回 `ErrUnsupportedFeature` | 返回 `ErrUnsupportedFeature` |

`Lock()`/`Lock(true)` 选择排他锁，`Lock(false)` 选择共享锁。未知锁模式返回 `ErrUnsupportedLockMode`；SQL Server 表提示只附加到主表，不自动扩散到 JOIN 表。

## 上下文

```go
rows, err := database.Name("users").
	WithContext(req.Raw().Context()).
	WhereField("id", "=", 1).
	Select()
```

上下文会传递到 SQL 驱动的 `SelectContext`、`InsertContext`、`UpdateContext`、`DeleteContext` 和 `CountContext`。模型查询器也支持同名的 `WithContext`。

## 原生 SQL

```go
rows, err := database.Query("SELECT * FROM users WHERE id = ?", 1)
affected, err := database.Execute("UPDATE users SET name = ? WHERE id = ?", "张三", 1)
```

原生 SQL 统一使用 `?` 占位符，框架按方言转换为 `$1`、`@p1`、`:1` 等形式。PostgreSQL 的单字符 JSONB 存在操作符写作 `??`，例如 `WhereRaw("payload ?? ?", "role")` 会执行为 `payload ? $1`；`?|`、`?&`、`@?` 可直接使用且不占用参数序号。占位符扫描会忽略字符串、引用标识符、行/块注释和 PostgreSQL dollar quote 中的问号，未闭合引用或参数数量不一致会返回错误。

SQL 行映射保留二进制列的 `[]byte` 类型并复制驱动缓冲区；结果出现同名列时必须使用唯一别名，否则返回 `ErrInvalidDatabaseRow`。错误日志只记录参数数量和脱敏 SQL，不记录绑定值；字符串字面量、PostgreSQL dollar quote、行注释和块注释内容都会替换为脱敏标记。

自定义 SQL 方言需要实现完整 `db.Builder`，包括 `DialectName`、`QuoteIdentifier`、`QuoteFields`、`Rebind`、`Pagination`、`Lock(db.LockMode) (db.LockSpec, error)`、`SupportsLastInsertId`、`InsertReturning` 和 `MaxBindParams`。不能使用通用多行 `VALUES` 的方言还应实现可选的 `db.BatchInsertBuilder`；Oracle 已通过该接口生成 `INSERT ALL`。`MaxBindParams` 必须返回该驱动单条语句可接受的正数参数预算，否则批量写入会返回配置错误。

## 错误判断

数据库错误支持 `errors.Is`。业务通常需要区分：

```go
switch {
case errors.Is(err, db.ErrUnsafeFullTableMutation):
    // 缺少业务 WHERE 条件。
case errors.Is(err, db.ErrInvalidPagination):
    // 分页为负、越界或溢出。
case errors.Is(err, db.ErrInvalidQuery):
    // 标识符、占位符、上下文或查询状态非法。
case errors.Is(err, db.ErrDatabaseClosed):
    // 数据库已经进入关闭状态。
case errors.Is(err, db.ErrUnsupportedFeature):
    // 当前驱动不能安全实现请求的锁或方言组合。
}
```
