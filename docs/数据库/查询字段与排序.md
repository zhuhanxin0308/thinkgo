# 查询字段与排序

字段投影、排序、分组和聚合筛选都使用结构化入口。动态字段应来自服务层白名单，不应直接接受请求中的任意字符串。

## 字段投影

```go
database, err := framework.ResolveServiceAs[*db.DB](app, framework.ServiceDB)
if err != nil {
	return err
}
rows, err := database.Name("users").
	Field("id,name,email AS contact_email").
	Select()
```

`Field` 支持逗号分隔的字段、点分表字段和显式 `AS` 别名。字段名和别名会经过标识符校验，并由 SQL 方言引用。`*` 可用于选择全部字段。

JOIN 查询默认只投影主表字段，避免不同表的同名列在结果 map 中相互覆盖。需要关联表字段时必须显式 `Field`，并给同名字段设置唯一别名：

```go
rows, err := database.Name("orders").
	Join("users", "orders.user_id = users.id").
	Field("orders.id,users.name AS user_name").
	Select()
```

## 排序

```go
q.Order("created_at DESC, id ASC")
```

每个排序项只能包含一个字段和可选的 `ASC` 或 `DESC`。函数、表达式、随机排序、分号和注释不属于安全排序语法；需要特殊排序时，应在服务层用固定映射选择有限的预定义 SQL，而不是直接拼接请求参数。

## 分组与 HAVING

```go
q.Group("status,tenant_id").
	HavingField("total", ">", 10)
```

`Group` 只接受安全字段列表。`Having` 与 `Where` 类似支持受限谓词和绑定参数：

```go
q.HavingRaw("COUNT(*) > ?", 10)
```

复杂聚合条件使用 `HavingRaw`，仍必须绑定值并保证原生 SQL 来源可信。`Group`、`Having` 会影响 `Count` 的执行方式，框架会在需要时包装完整查询，详见[聚合与字段值](聚合与字段值.md)。

`Having` 和 `HavingRaw` 是替换式设置入口，连续调用时只保留最后一组条件及其绑定参数；需要追加安全字段条件时使用 `HavingField`，它会按 `AND` 追加。

## 去重

```go
userIDs, err := database.Name("orders").
	Distinct().
	Field("user_id").
	Column("user_id")
```

`Distinct` 作用于当前投影。带有 `DISTINCT` 的查询执行 `Count` 或 `Paginate` 时，框架统计去重后的真实结果，而不是底层扫描行数。

## 分页组合

```go
rows, err := database.Name("users").
	Field("id,name").
	Order("id DESC").
	Page(2, 20).
	Select()
```

`Limit`、`Offset`、`Page` 会校验负数和整数溢出；不同数据库的分页语法由方言构建器生成，不要在 `Order` 或 Raw SQL 中自行追加方言特定分页片段。

## 模型查询

模型查询器复用这些字段方法，并在终端读取时应用模型获取器：

```go
rows, err := userModel.
	Field("id,name").
	Order("id DESC").
	Select()
```

模型关联预加载需要依赖关联键。若自定义 `Field` 时省略了关联需要的本地键，预加载会返回关联错误，因此预加载查询应保留关联定义中使用的键字段。
