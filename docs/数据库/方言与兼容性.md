# 方言与兼容性

SQL 查询统一由框架的 `db/builder` 包生成。业务代码使用 `?` 占位符和安全查询 API，执行时由方言处理标识符引用、占位符重绑定、分页、锁、主键回传和批量参数上限。

## 内置 SQL 方言

| 配置类型 | 数据库 | 主要差异 |
|---|---|---|
| `mysql` | MySQL / MariaDB | 默认 TLS；支持 `LastInsertId`、`LIMIT/OFFSET` 和 MySQL 锁语法 |
| `pgsql` | PostgreSQL | 默认 `sslmode=verify-full`；使用 `$N` 占位符和 `RETURNING` 回传主键 |
| `sqlsrv` | SQL Server | 使用 `@pN` 占位符和 `OFFSET ... FETCH`；无排序时分页会补默认排序 |
| `sqlite` | SQLite | 使用 CGO；文件库启用外键、WAL 和忙等待；`:memory:` 只能使用单连接 |
| `oracle` | Oracle | 需要 `oracle` build tag 和 godror 环境；使用 `:N` 占位符、`OFFSET ... FETCH` 和 Oracle 批量插入 |

Oracle 连接器和方言只在 `oracle` 构建标签下参与编译，构建环境还需要 Oracle 客户端依赖。

## 表名与字段引用

安全入口先验证标识符，再交给方言引用。不要在业务层硬编码反引号、双引号或方括号来适配某一个数据库；字段、排序、分组和 JOIN 表名使用 ORM API。

## 分页

- MySQL、PostgreSQL、SQLite 使用 `LIMIT/OFFSET`。
- SQL Server、Oracle 使用 `OFFSET ... FETCH`。
- 无排序的 SQL Server 分页会追加稳定的默认排序以满足语法要求。
- 业务代码统一使用 `Limit`、`Offset`、`Page` 或 `Paginate`，不要手写分页尾子句。

## 主键回传

支持 `LastInsertId` 的驱动走驱动返回值。PostgreSQL 不使用 `LastInsertId`，由连接层生成 `INSERT ... RETURNING <primary_key>`；模型配置的 `PrimaryKey` 会决定回传列，不应假设永远是 `id`。

## 悲观锁

| 方言 | `Lock(true)` | `Lock(false)` |
|---|---|---|
| MySQL | `FOR UPDATE` | `LOCK IN SHARE MODE` |
| PostgreSQL | `FOR UPDATE` | `FOR SHARE` |
| Oracle | `FOR UPDATE` | `FOR UPDATE` |
| SQLite | 忽略行级锁子句 | 忽略行级锁子句 |
| SQL Server | 当前实现不追加尾部锁子句 | 当前实现不追加尾部锁子句 |

不同数据库的锁粒度和事务隔离仍由数据库本身决定，业务不能只依赖统一 API 推断完全相同的并发语义。

## 批量参数上限

`InsertAll` 根据方言的 `MaxBindParams` 自动计算每批行数；实现 `BatchStatementSizer` 的方言还可以追加单条批量语句字节预算。当前内置 MySQL 连接器会把驱动的 `maxAllowedPacket` 传入该预算，且使用保守的参数包大小估算。Oracle 使用 `INSERT ALL`，其它 SQL 方言使用各自支持的批量形式。调用方只需保持每行字段集合一致。

## 连接默认值

- MySQL 默认启用 TLS 并校验证书；开发环境如需跳过校验必须在 `params` 中显式配置字符串 `tls=skip-verify`，不支持 `tls_verify` 字段。
- PostgreSQL 默认追加 `sslmode=verify-full` 并校验证书链和主机名，可由连接参数显式覆盖。
- SQL Server 默认 `encrypt=true`，可由连接参数显式覆盖。
- SQLite 默认启用外键、5000 毫秒 busy timeout，文件库启用 WAL；路径必须是普通文件，拒绝符号链接。
- MongoDB 默认 `tls=true`，Neo4j 默认使用 `neo4j+s`，详见各自独立章节。

## 跨数据库开发边界

不要把某个数据库特有的函数、类型或语法放进公共模型和服务接口。需要数据库专有能力时，应在服务或仓储层隔离，并为目标驱动添加集成测试；模型、验证器和控制器保持与具体方言无关。
