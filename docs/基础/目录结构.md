# 目录结构

ThinkGo 把项目宿主资源、应用业务代码和框架实现分开。一个应用的控制器、中间件、模型、验证器、多语言和路由定义都位于 `app/<应用名>/` 下，不能放在 `app/` 根目录或项目根 `route/` 目录。

应用组件关系、启动生命周期和请求处理链见[架构章节](../架构/README.md)。

```text
thinkgo/
├── app/
│   ├── index/                    默认应用
│   │   ├── application.go        应用定义和组件注册入口
│   │   ├── controller/           控制器
│   │   ├── middleware/           应用中间件
│   │   ├── model/                业务模型
│   │   ├── service/              业务服务
│   │   ├── validate/             验证器
│   │   ├── lang/                 多语言 JSON 文件
│   │   └── route/                应用路由定义
│   └── admin/                    另一个应用，结构与 index 对齐
│       ├── application.go
│       ├── controller/
│       ├── middleware/
│       ├── model/
│       ├── service/
│       ├── validate/
│       ├── lang/
│       └── route/
├── cmd/
│   ├── cert/                     本地开发证书生成工具
│   └── think/                    多应用命令行入口
├── config/                       项目级 JSON 配置和宿主配置
├── docs/                         框架文档
├── framework/                    框架核心
├── public/                       项目级公共静态资源
├── runtime/                      应用运行时目录
└── main.go                       统一 HTTP 服务入口
```

## 应用目录

### `application.go`

`application.go` 通过 `Register(app *framework.App) error` 把组件注册到当前应用，并通过 `framework.ApplicationDefinition` 登记应用名称和路径。它是应用的组合根，不应把另一个应用的注册对象写入当前 App。

### 控制器、中间件和路由

控制器位于 `app/<应用名>/controller`，由当前应用的 `application.go` 调用 `app.RegisterController` 注册。路由中的 `Controller@Action` 只在当前应用查找控制器。

中间件位于 `app/<应用名>/middleware`，由 `app.RegisterGlobalMiddleware` 或当前应用的 Pipeline API 装配。应用包不通过 `init()` 写入共享全局中间件表。

路由位于 `app/<应用名>/route`，通常由 `Load(app *framework.App) error` 负责注册，再由 `app.RegisterRouteLoader(route.Load)` 接入应用初始化。

### 模型、服务和验证器

`app/<应用名>/model` 放业务模型，模型文件按真实表名使用小写蛇形命名；`app/<应用名>/service` 放业务服务、仓储和外部依赖编排；`app/<应用名>/validate` 放验证器。

调用边界固定为：

```text
Controller -> Validator -> Service -> Model/ORM
```

控制器不能直接操作数据库或查询构造器。模型优先使用 `db.NewModelAuto`，只有结构体转蛇形后与表名不一致时才显式绑定表名。

### 多语言和视图

`app/<应用名>/lang` 放语言包，文件名是不含扩展名的语言标识，例如 `zh-cn.json`、`en-us.json`。视图目录为 `app/<应用名>/view`，当前应用的 `App` 会独立加载这些资源。

## 项目级目录

- `config/`：项目配置和统一 HTTP/TLS/HTTP3 宿主配置。`config/app.json` 可设置默认应用、应用映射和域名绑定。
- `public/`：统一宿主提供的公开静态资源，不经过动态中间件；私有资源不能放入此目录。
- `runtime/<应用名>/`：当前应用的日志、缓存和 Session 文件。证书工具的 `runtime/cert.pem`、`runtime/key.pem` 仍属于项目运行时产物。
- `framework/`：框架能力，不依赖具体 `app` 业务包。
- `cmd/`：命令行和工具入口；业务组件生成使用 `think make:* --app <name>`。

根级 `route/`、`app/controller`、`app/middleware`、`app/model`、`app/validate` 和 `app/lang` 不属于有效应用结构，不应重新创建兼容目录。

## 运行时边界

`ApplicationManager` 为每个应用维护独立的容器、路由、中间件、事件、配置覆盖和运行时路径；`MultiHttp` 只共享项目级监听器和宿主资源。应用配置可以覆盖自己的业务配置，但不能改变统一监听器的地址、端口、TLS 或 HTTP/3 边界。
