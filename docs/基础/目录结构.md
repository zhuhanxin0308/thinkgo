# 目录结构

`thinkgo create my-project` 生成的业务项目使用 `app/<应用名>` 原生多应用布局。项目级定义放在项目根 `app`，每个应用的控制器、模型、路由、验证器、语言包和生命周期定义放在自己的目录。框架通过 Go 模块依赖引用，不复制到业务工程。

```text
my-project/
├── autoload_generated.go           HTTP 入口的应用清单
├── app/
│   ├── autoload_generated.go       项目公共扩展清单，不导入子应用
│   ├── base_controller.go          项目公共控制器基类
│   ├── event.go                    项目级事件
│   ├── middleware.go               项目级中间件
│   ├── provider.go                 项目级容器绑定
│   ├── service.go                  项目级服务
│   └── <应用名>/
│       ├── autoload_generated.go   应用组件清单
│       ├── config/                 应用配置覆盖层
│       ├── controller/
│       ├── model/
│       ├── validate/
│       ├── service/
│       ├── command/
│       ├── event/
│       ├── listener/
│       ├── subscribe/
│       ├── middleware/
│       ├── lang/
│       ├── route/app.go
│       ├── view/
│       ├── event.go
│       ├── middleware.go
│       ├── provider.go
│       └── service.go
├── config/                          项目级配置与宿主监听配置
├── public/                          公共静态资源
├── runtime/<应用名>/                应用隔离的运行数据
├── cmd/think/                       项目 CLI
│   ├── autoload_generated.go       仅 thinkgo_runtime 标签启用的应用清单
│   └── commandautoload/           命令类型清单
├── go.mod                           依赖 github.com/zhuhanxin0308/thinkgo/v3
└── main.go                          项目 HTTP 入口
```

## 业务分层

```text
Controller -> Validator -> Service -> Model/ORM
```

- `app/<name>/controller` 读取请求、选择验证场景、调用服务并返回响应。
- `app/<name>/validate` 定义输入规则和错误消息。
- `app/<name>/service` 组合业务规则、事务、模型和外部依赖。
- `app/<name>/model` 保存表映射与持久化行为。
- `app/<name>/route` 只注册当前应用路由。

控制器、模型、验证器和应用清单由 `service:discover` 静态发现。开发者不修改 `main.go` 或 `autoload_generated.go`。

项目不需要 `appregistry` 包。HTTP 和 CLI 入口引用各应用的静态定义，通用注册、校验和生命周期逻辑由框架执行。根 `app` 不导入子应用，应用控制器可以通过嵌入 `app.BaseController` 复用公共能力；继续直接嵌入 `framework.Controller` 也受支持。旧项目的注册入口迁移见[代码生成命令](../命令行/代码生成命令.md)。

## 配置和运行目录

- `config/` 先加载，提供 `default_app`、`app_map`、`domain_bind`、`deny_app_list`、宿主监听和共享默认值。
- `app/<name>/config/` 随该应用初始化叠加，只能影响该应用；不能覆盖项目级应用解析或监听地址、端口、TLS/HTTP3。
- `public/` 属于项目宿主；静态请求经过项目全局安全与中间件管道，但不会进入某个应用的路由或应用中间件。需要应用级鉴权的资源不能直接放入该目录。
- `runtime/<name>/` 隔离日志、缓存、Session 和应用临时数据，不应提交版本库。
- 框架源码位于独立的 ThinkGo 仓库根目录，不导入业务工程；根 `go.mod` 声明 `github.com/zhuhanxin0308/thinkgo/v3`。框架仓库的 `config/` 是 Go 配置包，测试用 JSON 在 `testdata/project/config/`，不同于上图的业务项目配置目录。

组件关系见[架构章节](../架构/README.md)，生成规则见[代码生成命令](../命令行/代码生成命令.md)。
