# 目录结构

ThinkGo 的目录按应用层和框架层分离。业务代码只写在 `app`、`route`、`config`、`cmd` 等应用目录，`framework` 只承载框架能力。

```text
thinkgo/
├── app/
│   ├── controller/      控制器
│   ├── middleware/      应用全局中间件
│   ├── model/           业务模型
│   ├── validate/        验证器
│   └── lang/            多语言 JSON 文件
├── cmd/
│   ├── cert/            本地开发证书生成工具
│   └── think/           命令行入口
├── config/              JSON 配置文件
├── docs/                框架文档
├── framework/           框架核心
├── public/              静态资源目录
├── route/               路由定义
├── runtime/             日志、缓存、会话、证书等运行时文件
└── main.go              HTTP 服务入口
```

## 应用目录

`app/controller` 中的控制器必须通过 `framework.MustRegisterController` 注册。控制器注册名要和路由中的 `"Controller@Action"` 保持一致。

`app/middleware` 中的全局中间件通过 `framework.MustRegisterGlobalMiddleware` 注册。应用内置的 `RequestID` 中间件会读取或生成 `X-Request-ID`，并写入响应头。

`app/model` 放业务模型。模型应显式绑定真实表名；自动模型命名只做结构体名转 `snake_case`，不会自动复数化。

`app/validate` 放验证器。验证器通常嵌入 `validate.Validator`，配置 `Rule`、`Message` 和 `Scene`。

`app/lang` 放语言包，文件名即语言标识，例如 `zh-cn.json`、`en-us.json`。

## 框架目录

`framework` 下按能力拆包：`route`、`http`、`context`、`db`、`cache`、`session`、`middleware`、`validate`、`view`、`log`、`event`、`exception`、`console` 等。

框架内部不依赖 `app`。需要跨包协作时使用接口抽象，例如数据库层只依赖最小日志接口，异常层只依赖应用契约。

## 运行时目录

`runtime` 是运行时产物目录，不应提交到版本库：

- `runtime/log`：日志文件。
- `runtime/cache`：文件缓存。
- `runtime/session`：文件会话。
- `runtime/cert.pem`、`runtime/key.pem`：本地开发证书。

## 静态资源目录

`public` 中的文件在 HTTP 内核里优先于动态路由处理，且位于全局中间件之前。需要鉴权保护的资源不要放到 `public`。
