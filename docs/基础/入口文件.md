# 入口文件

ThinkGo 有两个主要入口：HTTP 服务入口和命令行入口。

## HTTP 入口

项目根目录 `main.go` 是 HTTP 服务入口。入口文件必须空导入控制器、中间件和路由包，触发各包 `init()` 完成注册。

```go
package main

import (
	"fmt"
	"os"

	_ "thinkgo/app/controller" // 注册控制器
	_ "thinkgo/app/middleware" // 注册全局中间件
	"thinkgo/framework"
	"thinkgo/framework/http"
	_ "thinkgo/route" // 注册路由
)

func main() {
	app := framework.NewApp()
	kernel, err := http.NewHttp(app)
	if err != nil {
		_ = app.Close()
		fmt.Fprintln(os.Stderr, "HTTP kernel initialization failed:", err)
		os.Exit(1)
	}
	app.Kernel = kernel
	if err := app.Run(); err != nil {
		fmt.Fprintln(os.Stderr, "Application exited with error:", err)
		os.Exit(1)
	}
}
```

入口文件只负责装配应用，不写业务路由、业务控制器或业务中间件逻辑。`Run` 会在退出路径统一调用 `Close`；若绕过 `Run`，调用方必须自行调用 `app.Close()` 并处理返回错误。

## 命令行入口

`cmd/think/main.go` 是命令行入口。它会注册内置命令：

```text
list
version
clear
run
route:list
config:dump
make:controller
make:model
make:command
make:validate
make:middleware
make:event
make:listener
make:subscribe
make:service
```

运行方式：

```bash
go run cmd/think/main.go list
go run cmd/think/main.go run -p 9000
```

入口显式传递命令参数，不依赖全局 `os.Args` 解析状态。内置命令注册、严格参数解析、命令执行、输出写入和 `app.Close()` 的错误都会返回入口；失败信息写入 stderr，进程以非零状态退出。

## Web 与命令行的初始化差异

`run` 命令需要启动 HTTP 服务，因此使用完整应用初始化。

其它命令使用 `framework.NewConsoleApp()`，会跳过数据库连接。编写自定义命令时，不要假设 `app.DB` 一定存在；需要数据库时应显式判断并处理错误。

## 开发证书入口

`cmd/cert/main.go` 生成本地开发证书：

```bash
go run cmd/cert/main.go
```

生成文件：

```text
runtime/cert.pem
runtime/key.pem
```

工具生成带 `localhost`、`127.0.0.1` 和 `::1` SAN 的 ECDSA P-256 自签名证书。两个目标均以独占方式创建；任一文件已存在时命令失败且不会覆盖或留下不匹配文件对。类 Unix 私钥权限为 `0600`，Windows 私钥使用禁止继承且仅授权当前用户的受保护 DACL。路径穿越和指向项目根目录外的符号链接会被拒绝，任何生成或输出错误都会产生非零退出状态。
