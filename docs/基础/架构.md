# 架构

ThinkGo 以 `framework.App` 作为应用实例，组合容器、配置、日志、路由、HTTP 内核、数据库、缓存、事件、语言、视图、Cookie、Session 和调试能力。

## 应用实例

创建应用：

```go
app := framework.NewApp()
```

命令行非 `run` 命令使用：

```go
app := framework.NewConsoleApp()
```

`NewConsoleApp` 会跳过数据库连接，适合 `version`、`list`、`make:*` 这类不需要数据库的命令。

构造器会立即执行一次幂等初始化。`.env`、配置、语言包、日志、数据库和路由加载错误可通过 `StartupError()` 获取；重复调用 `Initialize() error` 不会替换资源或叠加后台任务。启动错误最多保留 64 条，超出部分只累计省略数量，避免持续故障无限占用内存。

## 容器

`framework.Container` 支持两种生命周期：

- `Bind`：单例模式，首次解析后缓存。
- `BindFactory`：工厂模式，每次解析都创建新实例。

```go
container.Bind("mailer", func(container *framework.Container) (interface{}, error) {
	config, err := container.Make("mail.config")
	if err != nil {
		return nil, err
	}
	return NewMailer(config), nil
})

mailer, err := container.Make("mailer")
```

工厂需要解析其他服务时必须使用注入的 `container` 参数。循环依赖、参数类型错误、非法返回签名和工厂 panic 都通过 `Make` 返回错误。并发解析同名单例只执行一次工厂；同名 `Bind`、`BindFactory`、`Instance` 或 `Delete` 会使旧实例和仍在执行的旧构建失效。

控制器注册时会保存控制器类型，并在应用初始化阶段以工厂模式绑定到容器。这样每个请求都会创建新的控制器实例，避免请求级状态被并发请求共享。

```go
framework.MustRegisterController("User", &User{})
```

## 服务提供者

服务提供者实现 `framework.ServiceProvider`：

```go
type DemoProvider struct{}

func (p *DemoProvider) Register(app *framework.App) error {
	// 在这里绑定服务到容器。
	return nil
}

func (p *DemoProvider) Boot(app *framework.App) error {
	// 在所有 Register 完成后启动服务。
	return nil
}

func (p *DemoProvider) Shutdown(app *framework.App) error {
	// 释放 Provider 持有的资源。
	return nil
}
```

注册服务提供者：

```go
if err := app.RegisterProvider(&DemoProvider{}); err != nil {
	return err
}
```

Provider 必须是非空指针。`BootProviders()` 会先关闭注册阶段，等待所有在途 `Register` 完成，然后触发 `AppInit`、按注册顺序执行 `Boot`，最后触发 `RouteLoaded`。重复调用返回首次启动结果，不重复执行；启动开始后再注册会返回错误。实现可选 `ServiceProviderShutdown` 的 Provider 会在 `App.Close()` 中按注册逆序释放。

`App.Run() error` 会检查初始化错误、启动 Provider、运行内核，并在任何退出路径调用幂等的 `App.Close() error`。直接驱动内核或仅创建应用而不调用 `Run` 时，调用方必须自行关闭应用并处理清理错误；运行中的应用由 `Run` 持有关闭权，外部并发 `Close` 会返回 `ErrApplicationRunning`，避免提前释放仍在使用的资源。

## 注册机制

框架使用包级注册表衔接应用代码：

| 注册表 | 注册函数 | 用途 |
|---|---|---|
| 控制器 | `MustRegisterController` | 绑定 `"Controller@Action"` 中的控制器 |
| 路由加载器 | `MustRegisterRouteLoader` | 在应用初始化后集中加载路由 |
| 全局中间件 | `MustRegisterGlobalMiddleware` | 接入应用全局中间件 |

注册表不再暴露可变 map/slice；应用初始化读取持锁快照。同名控制器、nil 回调和非法名称会立即失败，`Must*` 适合在 `init()` 中把程序员配置错误直接暴露出来。路由加载器签名为 `func(*framework.App) error`，返回错误或 panic 都会进入应用启动错误。

入口文件必须空导入应用包，触发这些包的 `init()`：

```go
import (
	_ "thinkgo/app/controller"
	_ "thinkgo/app/middleware"
	_ "thinkgo/route"
)
```

## HTTP 内核

`framework/http.Http` 是 HTTP 内核，负责：

- 通过 `NewHttp(app) (*Http, error)` 一次性严格解析服务器、TLS、HTTP/3、压缩、请求体限制和可信代理配置。
- 冻结路由并用只读索引并发匹配；返回 404、405/Allow 和自动 OPTIONS。
- 用真实路径校验后的文件句柄处理静态资源；SPA fallback 仅用于 GET/HEAD。
- 构造请求对象，在业务前解析并校验结构化请求体。
- 执行全局、路由、控制器中间件。
- 调度闭包路由或签名已校验的控制器动作，控制器中间件缺失时失败关闭。
- 捕获 panic 并交给异常处理器。
- 记录访问日志并触发 HTTP 生命周期事件。

## 数据与状态边界

`app.Config`、`app.Cache`、`app.Log`、`app.Event`、`app.DB` 等是应用级共享能力。

`context.Request`、`context.Response`、控制器实例、请求级 Session/Cookie、请求级 Debug 都是请求级对象，不能写入全局变量。

跨中间件传递请求级数据使用：

```go
req.Set("request_id", value)
value := req.GetData("request_id")
```
