# 安装

ThinkGo 使用 Go Modules 管理依赖。开始前先确认本机 Go 版本满足 `go.mod` 中的 `go` 指令；当前最低要求为 `go 1.26.5`，不得使用缺少当前标准库安全修复的旧补丁版本。

## 获取依赖

```bash
go mod download
go mod verify
```

如果依赖发生变化，使用：

```bash
go mod tidy
```

## 运行服务

HTTP 服务入口是项目根目录的 `main.go`：

```bash
go run main.go
```

命令行入口在 `cmd/think/main.go`：

```bash
go run cmd/think/main.go list
go run cmd/think/main.go run
go run cmd/think/main.go run -p 9000
```

`run -p` 会覆盖 `config/app.json` 和 `.env` 中的端口配置。除 `run` 外，`version`、`list`、`make:*` 等命令默认跳过数据库连接。

## TLS 与 HTTP/3

当前 `config/app.json` 默认关闭 TLS 与 HTTP/3。需要启用时，证书路径默认为：

```text
runtime/cert.pem
runtime/key.pem
```

启用 HTTP/3 时必须同时启用 TLS。生产环境应使用受信任 CA 签发的正式证书，开发证书仅用于本机调试。

本地没有证书时，可运行开发证书工具：

```bash
go run cmd/cert/main.go
```

该工具生成 ECDSA P-256 本地证书并拒绝覆盖已有 `cert.pem` 或 `key.pem`。需要轮换时应先人工备份并成对移走旧文件，再重新执行；不要只删除其中一个文件。类 Unix 私钥权限为 `0600`，Windows 使用仅当前用户可访问的受保护 DACL。

生产环境应使用受信 CA 签发的正式证书，并保护私钥文件权限；开发证书只用于本机调试。

## 数据库准备

默认数据库配置在 `config/database.json`，默认连接名为 `mysql`。启动完整 Web 应用前需要保证默认连接可用；开发时也可以通过环境变量覆盖默认连接：

```text
DB_TYPE=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASS=secret
DB_NAME=thinkgo
```

## 验证安装

```bash
go build ./...
go test ./...
```

框架不要求数据库才能启动 HTTP 核心；无数据库配置的最小启动和真实请求验收可执行：

```bash
CGO_ENABLED=0 go test -mod=readonly -count=1 ./framework/http -run '^TestMultiHttpRunsWithoutDatabase$' -v
```

数据库相关业务只在访问时返回明确错误。正式环境若启用 TLS，仍必须提供受信任的证书和私钥；这与数据库是否可用是两条独立的启动前置条件。

SQLite 相关能力依赖 CGO。Windows 使用 MSYS2 UCRT64 时，`gcc.exe` 所在目录必须同时加入 `PATH`，使 GCC 能找到 `ld` 等子工具：

```powershell
$env:PATH = "C:\msys64\ucrt64\bin;$env:PATH"
$env:CGO_ENABLED = "1"
go test ./...
```

## 跨平台多架构构建

Windows 端可运行：

```bat
build.bat
```

Linux 端可运行：

```bash
chmod +x build.sh
./build.sh
```

两个脚本都会展示当前 Go 支持的 `GOOS/GOARCH` 列表并支持交互选择，也可直接传入目标平台。例如：

```bat
build.bat windows/amd64
build.bat linux arm 7
```

```bash
./build.sh linux/arm64
./build.sh windows amd64
```

产物写入已忽略的 `bin` 目录，文件名包含目标平台和 `nocgo`。两个脚本均使用 `CGO_ENABLED=0`，不包含 SQLite CGO 驱动能力；需要 SQLite 时应在具备 C 工具链的目标环境中使用 `CGO_ENABLED=1` 构建。

## 持续验证

仓库 CI 会执行 Linux CGO、Oracle 构建标签、Race Detector、Windows 平台测试、全部 `framework/...` 与 `app/index/...` 包的逐包 80% 覆盖率门禁、固定版本 Staticcheck/actionlint/gosec 和 `govulncheck`。本地提交前至少运行：

```bash
go mod verify
go mod tidy -diff
go vet ./...
go test -shuffle=on -count=1 ./...
CGO_ENABLED=0 go run -mod=readonly honnef.co/go/tools/cmd/staticcheck@v0.7.0 ./...
go run -mod=readonly github.com/rhysd/actionlint/cmd/actionlint@v1.7.12
CGO_ENABLED=0 go run -mod=readonly github.com/securego/gosec/v2/cmd/gosec@v2.25.0 -quiet -exclude-dir=.worktrees -exclude-dir=tmp -exclude-dir=bin ./...
CGO_ENABLED=1 go test -race -shuffle=on -count=1 ./framework/...
go run golang.org/x/vuln/cmd/govulncheck@v1.6.0 ./...
```

覆盖率门禁可在本地按框架包逐包执行：

```bash
coverage_dir="$(mktemp -d)"
trap 'rm -rf "$coverage_dir"' EXIT
for package in $(go list ./framework/... ./app/index/...); do
  profile="$coverage_dir/${package//\//_}.out"
  go test -count=1 -coverprofile="$profile" "$package" || exit 1
  statements="$(awk 'NR > 1 { count++ } END { print count + 0 }' "$profile")"
  if [ "$statements" -eq 0 ]; then
    echo "$package has no executable statements; coverage check skipped"
    continue
  fi
  coverage="$(go tool cover -func="$profile" | awk '/^total:/ {gsub(/%/, "", $3); print $3}')"
  awk -v actual="$coverage" 'BEGIN { exit !(actual + 0 >= 80) }' || {
    echo "$package coverage ${coverage}% is below 80%"
    exit 1
  }
  echo "$package coverage ${coverage}%"
done
```
