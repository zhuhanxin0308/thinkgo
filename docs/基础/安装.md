# 安装

ThinkGo 只发布 `github.com/zhuhanxin0308/thinkgo/framework`。仓库根模块是开发和多应用示例宿主，不是可安装产品，也不提供应用二进制 Release。

## 下游项目

当前仓库没有与源码版本对应的 `framework/v1.0.0` 标签和 GitHub Release 证据，不能把本地测试通过解释成公共版本已发布。发布工作流成功后，从实际 Release 复制版本号替换下方的 `vX.Y.Z`：

```bash
go mod init example.com/project
go get github.com/zhuhanxin0308/thinkgo/framework@vX.Y.Z
go mod verify
```

Go 版本以目标框架版本的 `go.mod` 为准。正式下游项目必须解析公开版本，不得依赖本仓库 `go.work` 或本地 `replace`。框架发布后应在空目录分别使用默认模块代理和 `GOPROXY=direct` 验证可获取性。

## 创建完整项目

`go get` 添加依赖，`go install` 安装命令。公开版本发布后，可安装同版本 CLI：

```bash
go install github.com/zhuhanxin0308/thinkgo/framework/cmd/thinkgo@vX.Y.Z
thinkgo create my-project
cd my-project
go test ./...
thinkgo list
thinkgo build linux/amd64
```

需要将 Go 的可执行文件安装目录加入 PATH。`create` 在执行命令的当前目录下创建 `my-project`；目标不存在或为空时允许创建，有任何内容（包括隐藏文件、子目录）时拒绝。创建过程获取 CLI 对应版本的框架依赖，写入 `go.mod`/`go.sum`，生成默认 `index` 应用及静态清单；失败时不留下半个项目，也不覆盖已有文件。本地未标记版本的开发 CLI 会尝试获取最新公开版本，因此正式发布前不能用此方式声称线上安装已验证。

生成的骨架具备 HTTP 与 CLI 入口、13 个配置文件、语言包、模板、静态资源、测试和忽略规则。数据库默认使用惰性连接，试用首页无需先启动数据库；使用模型前配置项目数据库。进入项目后，`thinkgo` 与 `go run ./cmd/think` 使用同一套命令实现。

## 仓库开发

根宿主与 `framework` 是两个模块，必须分别在独立依赖图中校验：

```powershell
$env:GOWORK = "off"
go mod verify
go test ./...

Push-Location framework
try {
    go mod verify
    go test ./...
} finally {
    Pop-Location
}
```

本地开发时根 `go.mod` 可以把框架替换到 `./framework`，但该替换不构成发布证据。依赖变化后分别执行 `go mod tidy -diff`，再按需同步 `go.work`。

## 运行示例宿主

```bash
go run .
go run ./cmd/think list
go run ./cmd/think run
go run ./cmd/think make:app admin
go run ./cmd/think service:discover
```

根入口注册 `app/autoload_generated.go` 中的全部编译期应用。所有应用会在网络监听前初始化；任一应用失败都会阻断启动。

## 数据库与 TLS

数据库实例地址和凭据通过系统环境或未跟踪的 `.env` 注入。应用可配置 `lazy`、`required`、`degraded` 或 `disabled` 启动策略；生产取舍必须与 readiness 和流量入口一致。

TLS 与 HTTP/3 默认关闭。HTTP/3 必须同时启用 TLS；生产环境必须使用受信 CA 证书并保护私钥权限。示例开发证书不能作为生产凭据。

SQLite 测试依赖 CGO 和可用 C 工具链。`CGO_ENABLED=0` 构建不包含 SQLite CGO 驱动能力，不能把无 CGO 构建通过解释成 SQLite 生产验收。

完整发布门禁见仓库根 [RELEASING.md](../../RELEASING.md)。
