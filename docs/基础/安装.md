# 安装

ThinkGo v3 的公共模块为 `github.com/zhuhanxin0308/thinkgo/v3`，框架源码位于仓库根目录。业务项目通过可安装 CLI 创建，框架 Release 不包含用户应用的二进制。

## 下游项目

已有 Go 项目可以直接添加 v3 依赖；创建新项目推荐使用下一节的 CLI：

```bash
go mod init example.com/project
go get github.com/zhuhanxin0308/thinkgo/v3@v3.0.0
go mod verify
```

v3.0.0 要求 Go 1.26.6 或更新版本，具体以目标版本的 `go.mod` 为准。正式下游项目必须解析公开版本，不依赖本地 `replace`。版本与发布状态见 [GitHub Releases](https://github.com/zhuhanxin0308/thinkgo/releases)。

## 创建完整项目

`go get` 添加依赖，`go install` 安装命令。安装同版本 CLI：

```bash
go install github.com/zhuhanxin0308/thinkgo/v3/cmd/thinkgo@v3.0.0
thinkgo create my-project
cd my-project
go test ./...
thinkgo list
thinkgo build linux/amd64
```

需要将 Go 的可执行文件安装目录加入 PATH。`create` 在执行命令的当前目录下创建 `my-project`；目标不存在或为空时允许创建，有任何内容（包括隐藏文件、子目录）时拒绝。创建过程获取 CLI 对应版本的框架依赖，写入 `go.mod`/`go.sum`，生成默认 `index` 应用及静态清单；失败时不留下半个项目，也不覆盖已有文件。本地未标记版本的开发 CLI 会尝试获取最新公开版本，因此正式发布前不能用此方式声称线上安装已验证。

生成的骨架具备 HTTP 与 CLI 入口、13 个配置文件、语言包、模板、静态资源、测试和忽略规则。数据库默认使用惰性连接，试用首页无需先启动数据库；使用模型前配置项目数据库。进入项目后，`thinkgo` 与 `go run ./cmd/think` 使用同一套命令实现。

## 仓库开发

克隆框架仓库后，直接在仓库根目录校验框架模块：

```powershell
$env:GOWORK = "off"
go mod verify
go mod tidy -diff
go build ./...
go vet ./...
go test ./...
go run ./cmd/thinkgo --version
```

仓库根没有业务 HTTP 入口。测试用 JSON 配置位于 `testdata/project/config/`，根 `config/` 是框架配置包。下游项目和框架是各自独立的 Go 模块，分别运行检查；本地替换只用于开发，不构成公开安装证据。

## 运行生成的项目

在 `thinkgo create` 创建的项目目录执行：

```bash
go run .
go run ./cmd/think list
go run ./cmd/think run
go run ./cmd/think make:app admin
go run ./cmd/think service:discover
```

项目根入口注册 `app/autoload_generated.go` 中的全部编译期应用。所有应用会在网络监听前初始化；任一应用失败都会阻断启动。

## 数据库与 TLS

数据库实例地址和凭据通过系统环境或未跟踪的 `.env` 注入。应用可配置 `lazy`、`required`、`degraded` 或 `disabled` 启动策略；生产取舍必须与 readiness 和流量入口一致。

TLS 与 HTTP/3 默认关闭。HTTP/3 必须同时启用 TLS；生产环境必须使用受信 CA 证书并保护私钥权限。示例开发证书不能作为生产凭据。

SQLite 测试依赖 CGO 和可用 C 工具链。`CGO_ENABLED=0` 构建不包含 SQLite CGO 驱动能力，不能把无 CGO 构建通过解释成 SQLite 生产验收。
