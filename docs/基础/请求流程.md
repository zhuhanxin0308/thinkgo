# 请求流程

本章描述一次 HTTP 请求在 ThinkGo 中的完整处理路径。

## 启动阶段

应用启动时执行：

1. 加载 `.env`。
2. 加载 `config/*.json`。
3. 用环境变量覆盖应用、服务器、TLS、数据库等配置。
4. 初始化日志、语言、缓存、视图、Cookie、Session、数据库。
5. 绑定控制器类型到容器。
6. 注册框架中间件：Recovery、Session、Trace、CSRF、语言检测。
7. 注册应用全局中间件。
8. 应用路由配置。
9. 执行路由加载器。
10. `AppInit` 在 Provider Boot 前触发，Provider 全部启动后触发 `RouteLoaded`，随后 HTTP 内核冻结路由并开始监听。

## 请求进入

`Http.ServeHTTP` 接收请求后：

1. 包装响应写入器，用于记录真实最终状态码。
2. 校验请求对象、Host 白名单并冻结路由配置。
3. 创建 `context.Request`，注入可信代理、请求体硬上限与 multipart 内存限制。
4. 调用 `Request.Parse()`；非法 Content-Type、JSON、表单返回 400，请求体超限返回 413，业务逻辑不会执行。
5. 触发 `HttpRun` 事件。
6. TLS 与 HTTP/3 同时启用时写入 `Alt-Svc`，再按协商结果启用响应压缩。
7. 注册统一收尾：异常恢复、压缩关闭、terminate、访问日志、`HttpEnd` 和上传临时文件清理。

## 静态资源

动态路由前先处理 `public`：

- `/` 命中 `public/index.html` 时直接返回。
- 其它路径会解析真实路径并用已校验的文件句柄响应；越界符号链接、点段和反斜杠路径均被拒绝。
- SPA 入口的成功结果和缺失结果都使用 250ms 的有界检查缓存，避免未命中请求反复访问文件系统；缓存内容按请求复制。
- 静态资源不经过应用中间件。

需要鉴权保护的文件不要放到 `public`。

## 中间件与路由

未命中静态资源后进入中间件管道：

```text
全局中间件 -> 路由匹配 -> 路由中间件 -> 控制器中间件 -> 控制器动作
```

路由匹配顺序：

1. 当前方法的静态路由（精确域名优先于无域名约束）。
2. 当前方法的动态路由。
3. HEAD 回落到 GET。
4. 通配方法路由。
5. 路径存在但方法不匹配时返回 405；OPTIONS 可自动返回 204 和 `Allow`。
6. 仅 GET/HEAD 可进入自动路由。
7. MISS 路由。

自动路由只有 `config/route.json` 中 `url_route_must=false` 时启用。

## 控制器分发

路由处理器支持两种形式：

```go
func(*context.Request) *context.Response
```

或：

```text
Controller@Action
```

控制器分发流程：

1. 从容器中按注册名解析控制器。
2. 校验 `Init` 和动作反射签名。
3. 调用控制器 `Init(app, req)`。
4. 解析控制器级中间件；别名缺失时失败关闭。
5. 调用动作方法并处理可选 `error` 返回值。
6. 将返回值转换为响应。

动作返回值转换规则：

| 返回值 | 响应 |
|---|---|
| `*context.Response` | 原样返回 |
| `string` | 文本响应 |
| 其它值 | JSON 响应 |

动作可返回 `(value, error)`，只返回 `error` 也受支持；非空错误在生产环境转换为通用 500，详细信息只写日志。

## 请求结束

响应发送或异常响应完成后，HTTP 内核先关闭压缩流，再执行已收集的 terminate 回调并清理 multipart 临时文件，随后记录访问日志并触发 `HttpEnd`。未提交的压缩缓冲在 panic 时会被丢弃，不会与异常响应拼接。
