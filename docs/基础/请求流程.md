# 请求流程

本章描述一次 HTTP 请求在 ThinkGo 中的完整处理路径。

## 启动阶段

应用启动时执行：

1. 加载 `.env`。
2. 加载 `config/*.json`。
3. 用环境变量覆盖应用、服务器、TLS、数据库等配置。
4. 初始化日志、语言、缓存、视图、Cookie、Session、数据库。
5. 绑定控制器类型到容器。
6. 注册框架中间件：Recovery、Session、Trace、CSRF、语言检测。
7. 注册应用全局中间件。
8. 应用路由配置。
9. 执行路由加载器。
10. 触发 `RouteLoaded` 和 `AppInit` 事件。

## 请求进入

`Http.ServeHTTP` 接收请求后：

1. 如启用 HTTP/3，写入 `Alt-Svc` 响应头。
2. 包装响应写入器，用于记录最终状态码。
3. 创建 `context.Request`，注入可信代理与 multipart 内存限制。
4. 注册 defer：异常恢复、压缩关闭、访问日志、`HttpEnd` 事件、上传临时文件清理。
5. 触发 `HttpRun` 事件。
6. 校验 Host 白名单。
7. 按配置启用响应压缩。
8. 限制请求体大小。

## 静态资源

动态路由前先处理 `public`：

- `/` 命中 `public/index.html` 时直接返回。
- 其它路径会安全映射到 `public` 目录内。
- 静态资源不经过应用中间件。

需要鉴权保护的文件不要放到 `public`。

## 中间件与路由

未命中静态资源后进入中间件管道：

```text
全局中间件 -> 路由匹配 -> 路由中间件 -> 控制器中间件 -> 控制器动作
```

路由匹配顺序：

1. 静态路由。
2. 通配方法静态路由。
3. 动态路由。
4. 通配方法动态路由。
5. 自动路由。
6. MISS 路由。

自动路由只有 `config/route.json` 中 `url_route_must=false` 时启用。

## 控制器分发

路由处理器支持两种形式：

```go
func(*context.Request) *context.Response
```

或：

```text
Controller@Action
```

控制器分发流程：

1. 从容器中按注册名解析控制器。
2. 调用控制器 `Init(app, req)`。
3. 解析控制器级中间件。
4. 调用动作方法。
5. 将返回值转换为响应。

动作返回值转换规则：

| 返回值 | 响应 |
|---|---|
| `*context.Response` | 原样返回 |
| `string` | 文本响应 |
| 其它值 | JSON 响应 |

## 请求结束

响应发送后，HTTP 内核会执行已收集的 terminate 回调。随后记录访问日志并触发 `HttpEnd` 事件，最后清理 multipart 上传产生的临时文件。
