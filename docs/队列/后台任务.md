# 持久化队列与周期调度

`framework/queue` 定义不可变任务、生产者、处理器和精确类型路由；`framework/queue/asynq` 使用 Redis/Asynq 提供持久化入队、延迟执行、唯一任务、失败重试、归档、Worker 和 Cron 调度。

任务类型、负载和传播 Header 都有硬上限。负载最大 1 MiB；注册和处理时使用精确任务类型，不使用可能意外接管其它业务任务的前缀匹配。

```go
redisClient := redis.NewClient(&redis.Options{Addr: redisAddress})
producer, err := asynqqueue.NewProducerFromRedisClient(redisClient)
if err != nil {
	return err
}
defer producer.Close()

task, err := queue.NewTask(
	"mail.send",
	[]byte(`{"user_id":42}`),
	map[string]string{"traceparent": traceParent},
)
if err != nil {
	return err
}
info, err := producer.Enqueue(request.Context(), task, queue.EnqueueOptions{
	Queue:     "critical",
	MaxRetry:  5,
	Timeout:   time.Minute,
	UniqueFor: time.Minute,
})
```

零值选项使用 `default` 队列、25 次失败重试和 30 分钟任务时限。明确不允许重试时设置 `DisableRetry: true`；它不能与 `MaxRetry` 同时设置。`UniqueFor` 至少一秒，唯一性由任务类型、负载和队列共同决定。

Worker 必须显式配置并发度、队列权重、关闭时限和拉取间隔：

```go
router := queue.NewRouter()
if err := router.Register("mail.send", queue.HandlerFunc(sendMail)); err != nil {
	return err
}
worker, err := asynqqueue.NewWorkerFromRedisClient(redisClient, asynqqueue.WorkerConfig{
	Concurrency:       16,
	Queues:            map[string]int{"critical": 6, "default": 3, "low": 1},
	ShutdownTimeout:   30 * time.Second,
	TaskCheckInterval: time.Second,
})
if err != nil {
	return err
}
if err := worker.Start(router); err != nil {
	return err
}
defer worker.Shutdown()
```

处理器返回非 nil 错误时由后端重试；超过重试上限后进入归档。处理器必须具备幂等性，外部副作用应使用业务幂等键、数据库唯一约束或事务发件箱，不能假设消息只投递一次。

周期任务在 Scheduler 启动前注册：

```go
scheduler, err := asynqqueue.NewSchedulerFromRedisClient(redisClient, time.UTC)
if err != nil {
	return err
}
if _, err := scheduler.Register("0 3 * * *", cleanupTask, queue.EnqueueOptions{
	Queue: "low",
}); err != nil {
	return err
}
if err := scheduler.Start(); err != nil {
	return err
}
defer scheduler.Shutdown()
```

调度器时区必须显式传入 `time.UTC`，非 UTC 时区会被拒绝。周期任务不能再设置 `ProcessAt`。多个调度器实例可以运行，但业务仍需根据任务性质设置唯一窗口或幂等约束，防止重复副作用。
