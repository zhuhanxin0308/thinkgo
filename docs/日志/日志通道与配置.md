# 日志通道与配置

应用配置位于 `config/log.json`：

```json
{
    "default": "file",
    "channels": {
        "file": {
            "type": "file",
            "path": "./runtime/log",
            "level": ["info", "warning", "error", "debug", "sql"]
        }
    }
}
```

`default` 必须指向 `channels` 中存在的通道。当前应用工厂支持的通道驱动类型是 `file`；未知类型、通道配置不是对象、默认通道缺失或文件治理配置非法会记录启动错误。

应用会把相对 `path` 按应用根目录解析。`level` 必须是字符串数组；空数组表示不过滤。文件通道还支持 `max_file_size`、`retention_days`、`max_files` 和 `max_total_size`，零值使用驱动默认值。

级别配置在初始化和 `SetLevels` 时发布为不可变快照，请求热路径只做无锁读取；调用方修改传入切片不会改变已发布策略。日志默认使用异步队列满时同步写入（`OverflowSync`），需要明确丢弃语义时才设置 `OverflowDrop`。丢弃策略会通过 `DroppedEntryCount()` 暴露累计数量，不能把队列溢出当作静默成功。

## 使用命名通道

```go
logger, err := framework.ResolveServiceAs[*log.Log](app, framework.ServiceLog)
if err != nil {
	return err
}
logger.Channel("sql").Info("查询完成")
```

运行期注册：

```go
if err := logger.RegisterChannel("sql", sqlLogger); err != nil {
	return err
}
```

`Channel(name)` 找不到名称时回退到当前日志器，不返回 nil。`RegisterChannel` 拒绝空名称、nil、重复名称、已关闭通道和会形成引用环的日志器图。

父日志器关闭时会等待自己的异步队列和驱动，再递归关闭已注册的子通道。不要把父通道注册为自己的子通道，也不要让两个通道互相引用。

## 直接添加驱动

```go
if err := logger.AddDriver(customDriver); err != nil {
	return err
}
```

驱动会收到同一条日志；`AddDriver` 拒绝 nil 和已关闭日志器。驱动接口见[刷盘、关闭与错误](刷盘、关闭与错误.md)。
