# 日志

日志入口是 `app.Log`。框架支持多驱动、多通道、级别过滤、调用位置记录、异步批量刷盘和关闭时刷盘。

## 配置

`config/log.json`：

```json
{
    "default": "file",
    "channels": {
        "file": {
            "type": "file",
            "path": "./runtime/log",
            "level": ["info", "warning", "error", "debug", "sql"],
            "max_file_size": 10485760,
            "retention_days": 30,
            "max_files": 100,
            "max_total_size": 1073741824
        }
    }
}
```

文件日志按日期和 `max_file_size` 轮转，并同时执行以下限制：

- `retention_days`：保留天数，默认 `30`。
- `max_files`：最多文件数，默认 `100`。
- `max_total_size`：全部受管日志的最大总字节数，默认 `1073741824`。

清理只处理 `YYYY-MM-DD.log` 和 `YYYY-MM-DD_N.log`，不会删除当前打开的日志文件。日志目录和文件在类 Unix 系统使用 `0700/0600`，Windows 使用仅授权当前进程用户的受保护 DACL。相对 `path` 基于应用根目录解析；无效路径、非整数或负数治理配置会产生启动错误。

直接构造文件驱动时使用 `driver.NewFileWithOptions(path, options) (*File, error)`，以便在启动阶段处理目录与权限错误。`FileOptions` 零值采用上述安全默认值。控制台重定向使用 `driver.NewConsoleWithWriter(writer) (*Console, error)`；驱动不会关闭调用方传入的 writer。

## 基础记录

```go
app.Log.Info("服务启动")
app.Log.Warning("配置缺失")
app.Log.Error("创建用户失败")
app.Log.Debug("调试信息")
app.Log.Sql("SELECT * FROM users")
```

支持 PSR 风格级别：

```text
Emergency Alert Critical Error Warning Notice Info Debug Sql
```

## 上下文日志

```go
app.Log.ErrorCtx("创建用户失败", map[string]interface{}{
	"user_id": userID,
	"error":   err.Error(),
})
```

上下文在调用时进行递归快照，类型化 map、slice、array、结构体、指针和循环引用均受支持。调用返回后的修改不会影响已入队日志。

## 格式化日志

```go
app.Log.Infof("用户 %d 登录", userID)
app.Log.Errorf("保存失败: %v", err)
```

## 通道

配置多个 channel 后，可以按通道写日志：

```go
app.Log.Channel("sql").Info("查询完成")
```

通道不存在时回退到当前日志器。

运行期注册使用 `RegisterChannel(name, channel) error`；空名称、`nil`、重复名称、已关闭通道或循环引用会返回错误。`AddDriver(driver) error` 同样拒绝 `nil` 驱动和关闭后的日志器，日志器取得已注册驱动的关闭责任。

## 调试模式

`app_debug=true` 时，框架会添加控制台日志驱动，并启用调用位置记录。

```text
[2026-07-03 10:00:00.000][INFO][file.go:12] message
```

## 异步刷盘与关闭

普通日志通过异步队列批量写入。队列满时会降级为同步写入，避免丢日志。

需要确认此前日志已经交给全部驱动时调用：

```go
if err := app.Log.Flush(ctx); err != nil {
	return err
}
```

退出时调用 `Close`，它会等待队列和在途同步写入，关闭全部驱动及命名通道，并聚合返回刷盘和关闭错误：

```go
if err := app.Log.Close(); err != nil {
	return err
}
```

`Shutdown() error` 是兼容旧名称的别名，新代码使用 `Close()`。`app.Run()` 会通过 `app.Close()` 统一关闭日志；绕过 `app.Run()` 的调用方必须调用 `app.Close()` 并处理聚合错误。

`SetBufferSize` 和 `SetFlushInterval` 仅能在首次记录或 `Flush` 前调用，参数无效或异步队列已启动时返回错误。

## 驱动错误

驱动写入、批量保存、panic 或关闭失败时，日志器会把已脱敏的单行错误写入兜底输出，累计 `DriverErrorCount()`，并通过下一次 `Flush` 或 `Close` 返回。待返回错误最多保留 64 条，超出部分以省略数量汇总，避免持续故障无限占用内存。

## 敏感信息

日志上下文会按 map 键、HTTP Header 名和结构体 JSON 字段名递归脱敏 `password`、`token`、`secret`、`cookie`、`authorization`、`session`、`api_key`、`refresh_token` 等敏感值，输出为 `[REDACTED]`，且不会修改调用方传入的数据。消息、级别、调用位置和驱动兜底错误中的换行、回车、制表符会被转义，避免伪造日志行。
业务日志仍应避免直接把密码、token、Cookie、Authorization 或个人隐私数据写入消息正文。
