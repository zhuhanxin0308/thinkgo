## 数据完整性与错误口径

图包登记完成 **1,680** 个正式轮次，其中 **1,618** 个记为测量有效轮次。已发出且成功的请求为 **242,616,947** 次；登记的非预期 HTTP 状态、业务语义、网络与 socket 错误以及应用/数据库 OOM 次数均为 0。

这不等于所有计划负载都已成功发送。固定到达率的 72 轮中有 **62** 轮出现未发出迭代，共 **459,679** 次，独立于已发请求的错误计数。图 00 另记录 **528 / 528** 项事务一致性审计通过。上述均为随图包提供的记录，本次文档接入没有重新运行这些实验。

## 如何解释图中的数字

吞吐柱展示独立轮次的中位数；误差线及阴影表示观察到的最小—最大值，不是置信区间。P50/P95/P99/P99.9 展示各轮分位数的中位数，未合并所有请求；固定 VU 不代表各框架接受了相同绝对到达率。

内存以 250 毫秒间隔采样。图 09 的总量是含文件缓存的 `cgroup memory.current`，与匿名内存分别取三轮峰值中的最大值，两者不是同一时刻的组成，也不能称为 RSS。

CPU 占用使用等效逻辑 CPU 数。每请求 CPU 开销只计应用进程树，分子为完整资源采样窗口内的 CPU 时间，可能包含负载启动和结束尾段；不能当作处理函数精确耗时或整机成本。

启动就绪耗时包含容器启动、健康检查、inspect 和 PHP 生产缓存重建，不是纯框架初始化或首请求延迟。三次重复的变异系数只能描述本次观察波动，不证明差异具有统计显著性。

**适用边界：** 不外推到公网、TLS、冷缓存、ORM、不同硬件、资源隔离方式、业务实现或部署形态。完整压测工程与逐请求原始数据不在该图包中，见[来源说明](SOURCE.md)。
