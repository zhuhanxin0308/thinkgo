# 语言中间件

`framework.App.LoadLangPack()` 返回一个全局中间件。它读取应用的 `framework/lang.Lang` 检测配置，为每个请求选择语言，并将结果写入 `framework.LangRequestKey`（当前值为 `_lang`）。它不修改共享语言管理器的当前语言，因此可以安全用于并发请求。

## 来源优先级

默认顺序是：

```text
查询参数 -> Cookie -> 配置的请求头 -> Accept-Language -> 默认语言
```

默认配置对应：`lang`、`think_lang`、`think-lang`。查询参数名称、Cookie 名称、请求头名称、是否启用 Cookie 和是否启用浏览器检测都可以在 `config/lang.json` 配置。

每个显式来源都要经过 `Lang.MatchLanguage`，必须是已加载且在允许列表中的语言；无效候选不会终止请求，而是继续尝试下一个来源。所有来源都无效时使用 `GetDefaultLang()`。

## Accept-Language

开启 `auto_detect_browser` 后，框架最多读取 8192 字节、最多处理 32 个候选。候选按 `q` 从高到低排序，相同权重保留请求头原始顺序；`q=0`、非法 q、重复 q、NaN、Inf、负数和大于 1 的值都会被忽略。`*` 会尝试默认语言。

关闭浏览器检测时，`Accept-Language` 完全不参与选择，但显式查询参数、Cookie 和自定义请求头仍然有效。

## 下游访问

```go
locale := request.GetData(framework.LangRequestKey)
```

控制器应使用 `GetLang` 或 `Lang`，服务层可以接收控制器传入的语言标识。不要在请求处理中调用共享语言服务的 `SetLang` 模拟切换语言。`next` 为空时语言中间件返回 500；正常情况下总是继续调用下游。

应用初始化完成后语言配置按不可变快照读取，每个请求只在 `Request` 中保存 `_lang`。因此不要把请求语言写入包级变量、共享控制器字段或语言服务的全局当前值；需要在模板或服务中使用时，从当前请求或控制器读取。

管理员 API 在自己的路由链中还会执行 `appmiddleware.Locale`，将 `Accept-Language` 严格归一为 `zh-cn` 或 `en-us`，其他语言回退 `zh-cn`。
