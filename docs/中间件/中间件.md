# 中间件概览

中间件在请求处理器前后执行公共逻辑，例如请求编号、语言检测、会话、CSRF、调试、认证和审计。中间件可以调用 `next` 继续处理，也可以直接返回响应短路请求。

## 处理器签名

框架统一使用：

```go
type Handler func(
    request *context.Request,
    next func(*context.Request) *context.Response,
) *context.Response
```

处理器负责返回 `*context.Response`。下游返回 `nil` 时，HTTP 内核会在全局管道返回后生成 500；具体中间件也可以按自身协议保留 `nil`，例如 Session 和 CSRF 不会为了写 Cookie 伪造成功响应。

## 作用域

ThinkGo 有三层中间件：

| 作用域 | 注册位置 | 生效时机 |
|---|---|---|
| 项目全局 | 根 `app/middleware.go` 的 `Middleware()` | 请求解析和项目级静态资源处理之前 |
| 应用全局 | `app/<name>/middleware.go` 的 `Middleware()` | 解析并选择目标应用后、业务路由处理之前 |
| 路由 | `Router.Add`、HTTP 方法快捷方法、分组参数 | 路由成功匹配后 |
| 控制器 | `Controller.SetMiddleware` 声明别名 | `Initialize` 完成后、动作执行前 |

Host 校验、路由冻结和请求对象创建发生在全局中间件之前。全局中间件先执行，其管道终点再解析请求并选择项目级 `public` 静态资源或业务路由；因此静态资源会经过全局中间件，但不会经过路由、分组或控制器中间件。

## 默认装配顺序

每个 `framework.App.initialize` 创建自己的应用管道时按以下顺序追加：

```text
Recovery
-> CORS（cors.enable=true 时）
-> Security Headers（security_headers.enable=true 时）
-> Rate Limit（rate_limit.enable=true 时）
-> Session（app.session_enable=true 时）
-> Trace（app.app_trace=true 时）
-> CSRF（app.csrf_enable=true 时）
-> app.LoadLangPack()
-> 根 `app/middleware.go` 声明的项目全局中间件
-> 请求解析、项目级静态资源或应用上下文选择
-> `app/<name>/middleware.go` 声明的应用全局中间件
```

这是项目全局管道的初始顺序；`config/middleware.json` 的显式优先级会在最后对已注册中间件重新排序。完成请求解析和应用上下文选择后，HTTP 内核执行目标应用自己的管道，再继续执行路由中间件、控制器中间件和控制器动作。CORS 和 CSRF 别名无论是否全局启用都会分别注册为 `cors`、`csrf`，供路由或控制器按需引用。项目级 `public/` 静态文件只经过项目全局管道，不经过应用、路由或控制器中间件。

认证、授权、审计等业务中间件不属于框架内置能力。确实跨应用共享的能力在根 `app/middleware.go` 声明；只属于一个业务应用的能力在 `app/<name>/middleware.go` 或该应用路由层声明。

## 继续与短路

```go
func Auth(request *context.Request, next func(*context.Request) *context.Response) *context.Response {
    if request.Header("Authorization") == "" {
        return context.NewResponse().Abort(http.StatusUnauthorized, map[string]interface{}{
            "message": "未提供认证信息",
        })
    }
    return next(request)
}
```

不调用 `next` 就会阻止后续中间件、路由和动作。中间件必须保证短路响应具有明确状态码，并避免在认证、CSRF 等保护失败时继续放行。
