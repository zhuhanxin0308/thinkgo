# 中间件

中间件用于在请求进入控制器前后执行公共逻辑，例如鉴权、请求编号、Session、CSRF、Trace、CORS 等。

## 函数签名

```go
func(req *context.Request, next func(*context.Request) *context.Response) *context.Response
```

中间件可以调用 `next(req)` 继续后续流程，也可以直接返回响应短路请求。

## 全局中间件

应用全局中间件放在 `app/middleware`，通过 `framework.RegisterGlobalMiddleware` 注册：

```go
package middleware

import (
	"thinkgo/framework"
	"thinkgo/framework/context"
)

func init() {
	framework.RegisterGlobalMiddleware(Auth)
}

func Auth(req *context.Request, next func(*context.Request) *context.Response) *context.Response {
	if req.Header("Authorization") == "" {
		return context.NewResponse().Abort(401, map[string]interface{}{
			"message": "unauthorized",
		})
	}
	return next(req)
}
```

应用初始化时会按注册顺序追加全局中间件。

## 路由中间件

```go
app.Route.Get("/api/profile", "User@Profile", Auth)
```

分组也可以挂中间件：

```go
app.Route.Group("/admin", func() {
	app.Route.Get("/dashboard", "Dashboard@Index")
}, Auth)
```

## 控制器中间件

先注册别名：

```go
app.Middleware.Alias("auth", Auth)
```

再在控制器里声明：

```go
c.SetMiddleware(framework.ControllerMiddleware{
	Name: "auth",
	Only: []string{"Profile", "Update"},
})
```

别名不存在时框架会记录 warning，并跳过该中间件。

## 执行顺序

```text
Recovery -> Session -> Trace -> CSRF -> Language -> 应用全局中间件 -> 路由中间件 -> 控制器中间件 -> 控制器动作
```

Session、Trace、CSRF 是否全局启用由配置控制：

| 配置 | 说明 |
|---|---|
| `app.session_enable` | 启用 Session 中间件 |
| `app.app_trace` | 启用 Trace 中间件 |
| `app.csrf_enable` | 全局启用 CSRF 中间件 |

CSRF 即使未全局启用，也会注册为 `csrf` 别名，供路由或控制器按需使用。

## 中间件别名与优先级

```go
app.Middleware.Alias("auth", Auth)
app.Middleware.PipeByName("auth")
app.Middleware.SetPriority([]string{"auth", "csrf"})
```

优先级列表中的别名会稳定排到前面，其它中间件保持原有相对顺序。

## terminate 生命周期

需要在响应发送后执行逻辑时使用 `Lifecycle`：

```go
handler := func(req *context.Request, next func(*context.Request) *context.Response) *context.Response {
	return next(req)
}

terminator := func(req *context.Request, resp *context.Response) {
	// 响应发送后执行收尾逻辑。
}

app.Middleware.Pipe(middleware.Lifecycle(handler, terminator))
```

terminate 回调异常只记录日志，不会影响已经发送的响应。
只有本次请求真实执行过的中间件会进入 terminate 回调；前置中间件短路后，后续未执行中间件的 terminate 不会被收集。

## 内置中间件

### Recovery

捕获 panic，并交给异常处理器渲染响应。生产环境不暴露堆栈；调试详情只对本机回环请求开放。

### Session

为每个请求创建独立 Session 实例，请求结束时仅在数据变更后保存。
如果下游返回 nil 响应，Session 会保持 nil 交由 HTTP 内核兜底，不会尝试写入 Cookie。
如果 Session 保存失败，中间件会返回 500 错误响应，不会继续返回下游业务成功响应。

### Trace

只在 `app_trace=true` 且请求来自本机回环链路时注入调试条。调试条资源路径为：

```text
/__thinkgo_debug__/trace.css
/__thinkgo_debug__/trace.js
```

### CSRF

双重提交 Cookie 模式。安全方法下发 token，状态变更方法要求 Cookie token 与请求头或表单 token 一致。

### CORS

通过 `middleware.CorsWithConfig` 创建。凭证模式不会和通配来源 `*` 混用，白名单来源会自动设置 `Vary: Origin`。
