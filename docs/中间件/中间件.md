# 中间件概览

中间件在请求处理器前后执行公共逻辑，例如请求编号、语言检测、会话、CSRF、调试、认证和审计。中间件可以调用 `next` 继续处理，也可以直接返回响应短路请求。

## 处理器签名

框架统一使用：

```go
type Handler func(
    request *context.Request,
    next func(*context.Request) *context.Response,
) *context.Response
```

处理器负责返回 `*context.Response`。下游返回 `nil` 时，HTTP 内核会在全局管道返回后生成 500；具体中间件也可以按自身协议保留 `nil`，例如 Session 和 CSRF 不会为了写 Cookie 伪造成功响应。

## 作用域

ThinkGo 有三层中间件：

| 作用域 | 注册位置 | 生效时机 |
|---|---|---|
| 全局 | 当前 `App.RegisterGlobalMiddleware` | 动态请求进入路由前 |
| 路由 | `Router.Add`、HTTP 方法快捷方法、分组参数 | 路由成功匹配后 |
| 控制器 | `Controller.SetMiddleware` 声明别名 | `Init` 完成后、动作执行前 |

`public` 静态资源在动态管道之前处理，因此不会经过这些应用和路由中间件。请求解析、Host 校验和路由冻结也发生在全局中间件之前。

## 默认装配顺序

每个 `framework.App.initialize` 创建自己的应用管道时按以下顺序追加：

```text
Recovery
-> Session（app.session_enable=true 时）
-> Trace（app.app_trace=true 时）
-> CSRF（app.csrf_enable=true 时）
-> app.LoadLangPack()
-> 当前应用 `application.go` 注册的全局中间件
```

其中 CSRF 别名无论是否全局启用都会注册为 `csrf`，这样路由或控制器可以按需引用。动态请求完成路由匹配后，HTTP 内核继续执行路由中间件、控制器中间件和控制器动作。

应用管理员路由在路由层另行注册自己的链，顺序见[管理员中间件](管理员中间件.md)。

## 继续与短路

```go
func Auth(request *context.Request, next func(*context.Request) *context.Response) *context.Response {
    if request.Header("Authorization") == "" {
        return context.NewResponse().Abort(http.StatusUnauthorized, map[string]interface{}{
            "message": "未提供认证信息",
        })
    }
    return next(request)
}
```

不调用 `next` 就会阻止后续中间件、路由和动作。中间件必须保证短路响应具有明确状态码，并避免在认证、CSRF 等保护失败时继续放行。
