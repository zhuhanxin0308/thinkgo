# 中间件安全边界

## 请求进入边界

HTTP 内核先校验请求、Host、请求体和路由冻结状态，再进入全局中间件。`public` 静态资源和 SPA 入口在全局管道之前处理，不经过认证、Session、CSRF、Trace 或应用全局中间件；需要保护的文件不能放在 `public`。

## 失败关闭

保护类中间件遇到配置、依赖、路由元数据、认证、授权、Session 保存或审计写入错误时，应返回错误并停止下游。控制器中间件别名缺失、CSRF token 不合法、管理员来源不在白名单时都不能继续调用动作。

通用 CORS 的设计不同：普通请求的来源未命中时会继续下游但不添加 CORS 头；它不是认证机制。需要拒绝所有非白名单来源时使用管理员 CORS 或显式拒绝中间件。

## 请求级状态

中间件之间使用 `Request.Set` 和 `Request.GetData` 传递请求级数据，例如 `_session`、`_debug`、`_lang`、`request_id` 和管理员认证上下文。请求级值不能写入包级变量、共享控制器实例或应用单例中的可变字段。

## 敏感信息

- Recovery 的详细异常页只允许调试模式下的本机请求；生产环境返回通用错误。
- Trace 要求底层连接和所有代理头地址均为回环地址，并对面板文本做 HTML 转义。
- CSRF token 使用 HMAC、时间窗口、规范 Base64 和常量时间比较；安全 Cookie 不使用 HttpOnly，因为浏览器脚本需要读取它并写入请求头。
- Session Cookie 强制 HttpOnly，Session 数据和完整信封受大小上限约束。
- RequestID、用户代理、Origin 和管理员 token 都有格式或长度边界，非法调用方值不得被原样写回响应或审计。

## 代理协议与安全 Cookie

`trusted_proxies` 在启动时编译为不可变的代理集合，只有直接连接地址命中该集合时，`X-Forwarded-Proto` 才能影响 `Request.IsSsl()`。非可信来源伪造的转发头会被忽略。框架 Session 中间件把这个已经确认的协议结论传给 `NewRequestSessionWithSecure`；业务直接调用旧 Cookie/Session 入口时仍保留原有请求判断，迁移代码可逐步使用显式安全入口。

生产环境的 Cookie/CSRF 密钥为空、具体 Host 白名单缺失或 CSRF 未启用时，框架按类别输出一次性 warning 并记录启动错误，`App.Run` 不会继续监听端口。`allowed_hosts` 使用全匹配 `*` 同样不满足安全基线；部署系统仍应把这些 warning 纳入发布检查。

## 响应结束

HTTP 内核发送响应后关闭压缩流，再执行当前请求真实经过的 terminate 回调，清理 multipart 临时资源，记录访问日志并触发 `HttpEnd`。terminate 回调不应依赖响应仍可修改；它们发生 panic 时只记录日志，不改变已发送响应。
