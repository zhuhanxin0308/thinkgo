# 请求编号

`app/index/middleware/request_id.go` 提供 index 应用的 `RequestID` 中间件，由 `app/index/application.go` 注册为全局中间件。其它应用应在自己的 middleware 包中注册需要的请求编号策略。它把请求编号同时放入请求上下文和响应头，供日志、服务和管理员 API 使用。

## 生成与透传

```go
requestID := middleware.EnsureRequestID(request)
```

处理规则：

1. 如果请求上下文已有合法 `request_id`，直接复用。
2. 否则读取 `X-Request-ID`。
3. 请求头不合法或为空时生成新的 UUID，并写入请求上下文。
4. 下游返回后，如果下游把请求上下文中的编号更新为另一个合法值，响应使用该规范值。
5. `RequestID` 向响应写入 `X-Request-ID`；下游返回 `nil` 时先生成空响应再写头。

合法编号最多 128 字节，必须匹配：

```text
^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$
```

`ValidRequestID` 是共享的校验入口。非法调用方编号不会被原样反射到响应、日志或审计记录；`EnsureRequestID(nil)` 仍会返回新 UUID，但没有请求上下文可写入。

## 管道位置

应用中间件注册表快照在框架内置语言中间件之后追加，因此默认 `RequestID` 位于语言中间件之后、路由匹配之前。管理员 CORS 的预检响应和管理员 JSON 响应也会通过 `adminhttp.EnsureRequestID` 复用同一编号实现。
