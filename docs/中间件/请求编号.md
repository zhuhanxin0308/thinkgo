# 请求编号

ThinkPHP 默认项目不内置请求编号中间件，因此 ThinkGo 也不会隐式生成或启用 `RequestID`。业务需要 `X-Request-ID` 时，应把它作为普通应用中间件实现。

## 文件与装配

```text
app/index/middleware/request_id.go
app/index/middleware.go
```

中间件应完成以下边界：

1. 只接受长度和字符集经过校验的调用方 `X-Request-ID`。
2. 缺失或非法时生成新的不可预测编号。
3. 使用 `Request.Set` 保存请求级编号。
4. 在下游响应返回后写入 `X-Request-ID` 响应头。
5. 不把编号或 Request 保存到包级变量。

实现后，将处理器加入目标应用 `app/<name>/middleware.go` 的 `Middleware()` 列表即可。只有所有应用都需要它时才放进根 `app/middleware.go`。框架不会要求开发者修改 HTTP 内核或注册表。
