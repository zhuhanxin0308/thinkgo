# 管理员中间件

管理员中间件属于管理员应用实现，文件全部位于 `app/admin/middleware`，使用 `middleware` 包：

```text
admin_cors.go
admin_locale.go
admin_authentication.go
admin_authorization.go
admin_audit.go
admin_route_metadata.go
admin_runtime.go
```

管理员应用的路由加载器从 `thinkgo/app/admin/middleware` 导入这些实现。中间件不会进入 `index` 或其它应用的管道。

## 注册顺序

`route.LoadAdmin` 为每个管理员业务路由注册：

```text
CORS -> Locale -> RouteContract -> Authentication -> Audit -> Authorization -> Controller
```

管理员 OPTIONS 预检路由只挂 CORS，不进入语言、认证、审计或授权，也不会进入控制器。

## CORS

`NewCORS` 只处理存在 `Origin` 的请求。来源必须是单一、无用户信息、无路径/查询/片段且协议为 HTTP 或 HTTPS 的 Origin，并且必须精确命中服务配置的允许来源。非法或不在白名单的来源返回 403，不反射来源，也不允许 Cookie 凭证。

合法预检只允许 `GET`、`POST`、`PUT`、`PATCH`、`DELETE` 和固定请求头白名单，成功返回 204、`X-Request-ID`、`Vary`、允许方法/请求头、暴露 `X-Request-ID` 和 600 秒预检缓存。业务响应会追加相同的无凭证 CORS 头；下游返回 `nil` 时转为内部错误响应。

## Locale

`Locale` 调用管理员服务层的语言解析，只支持 `zh-cn` 和 `en-us`，默认 `zh-cn`。`Accept-Language` 超过 512 字节、解析失败或不包含中文/英文时回退默认语言，并写入框架的 `_lang` 请求数据。

## Authentication

`NewAuthentication` 先验证 HTTP 内核写入的可信路由元数据、路由合同和公开路由表。公开路由只有：

```text
POST /api/admin/v1/auth/login
POST /api/admin/v1/auth/refresh
POST /api/admin/v1/auth/mfa/verify
```

其他路由必须携带唯一的 `Authorization: Bearer <token>`。认证方案、重复头、控制字符和超长 token 都被拒绝；通过后调用 `AccessAuthenticator` 服务，并把有效管理员主体写入请求上下文。主体缺少管理员 ID 或 Session ID 时失败关闭。

## Audit

`NewAudit` 只为已认证请求建立审计记录。它要求可信路由元数据和 `AuditMetadata` 中的动作码、资源类型；记录请求编号、管理员、角色快照、权限码、动作、资源 ID、路由、状态、业务码、来源 IP、用户代理、风险级别和耗时。

服务层已经在业务事务内成功提交完整审计并调用 `MarkAuditCommitted`，且响应为 2xx 时，中间件不会重复记录；失败响应仍会补记录。审计服务写入失败会替换业务响应为错误响应，避免静默丢失高风险操作记录。

## Authorization

`NewAuthorization` 从请求上下文恢复管理员主体，构造 `rbac.Subject` 并调用 `RouteAuthorizer` 服务。服务返回的策略必须同时匹配可信路由的方法、路径、控制器动作，以及路由目录声明的访问策略和权限码；任何不一致都返回配置错误，不允许仅凭超级管理员身份绕过未登记路由。

中间件只依赖 `adminhttp.Runtime` 暴露的服务接口，不直接操作数据库。`Runtime` 会为一个应用实例延迟解析并缓存依赖，允许来源返回防御性副本；依赖缺失或运行时无效时所有受保护请求失败关闭。
