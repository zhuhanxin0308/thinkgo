# 启动服务

`run` 命令启动一个统一 HTTP/TLS/HTTP3 宿主。多个应用共用同一个端口，通过域名或 URL 首段选择目标应用：

```bash
go run cmd/think/main.go run
go run cmd/think/main.go run --port=9000
go run cmd/think/main.go run --app admin --port 9000
```

`--app` 是命令目标应用选项，适用于查看或生成等应用级命令；`run` 仍然启动 `ApplicationManager` 管理的全部应用，不能只启动一个应用并为其它应用另开监听器。

## 端口和启动检查

端口必须是 1 至 65535 的十进制整数。指定端口且启动检查通过后会同时：

1. 写入当前进程环境变量 `SERVER_PORT`；
2. 写入所有应用的 `app.server.port` 配置；
3. 创建统一 `MultiHttp` 宿主；
4. 在 Provider 启动、路由冻结和所有应用配置检查成功后开始监听。

校验或初始化失败时，不会修改 `SERVER_PORT` 或应用内存配置。任一应用初始化失败、Provider 启动失败或宿主配置不一致，整个服务启动失败。

## 应用选择

请求运行时的选择顺序为域名绑定、路径应用映射、默认应用：

```text
admin.example.com/users   -> admin 应用的 /users
/admin/users              -> admin 应用的 /users
/users                    -> default_app 应用的 /users
```

应用映射、域名绑定和拒绝列表配置见[多模块和多应用](../架构/多模块和多应用.md)。

## Air 热重载

如果 `air` 在 PATH 中，命令会在项目根目录运行它，并准备 `bin` 目录。构建产物为：

```text
bin/server       # 非 Windows
bin/server.exe   # Windows
```

Air 构建的是项目根 `main.go`，该入口会重新创建全部应用和统一宿主。端口通过 `SERVER_PORT` 传递给子进程，应用级路径和注册入口仍从各自 `app/<name>/` 读取。

## 普通模式

未安装 Air 时，命令输出安装提示并创建 `http.NewMultiHttp(manager)`，通过统一宿主启动服务。HTTP 配置错误、Provider 启动失败、路由冻结失败、服务运行失败和应用关闭失败都会返回错误；命令不会在初始化失败后继续监听端口。

## 监听配置边界

HTTP 地址、端口、TLS 证书、HTTP/3、压缩、可信代理和超时属于项目级宿主配置。应用目录下的配置可以覆盖业务、路由和资源配置，但不能让不同应用使用不同监听器配置。

完整入口组装见[入口文件](../架构/入口文件.md)，请求生命周期见[请求流程](../架构/请求流程.md)。
