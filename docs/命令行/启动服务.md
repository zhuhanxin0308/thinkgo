# 启动服务

`run` 启动一个原生多应用 HTTP/TLS/HTTP3 宿主：

```bash
go run ./cmd/think run
go run ./cmd/think run --port=9000
go run ./cmd/think run -p 9000
```

端口必须是 1 至 65535 的十进制整数。参数和项目配置校验成功后才写入当前进程配置，失败不会污染原值。

启动顺序：

1. 创建项目入口 `App` 并注册编译期应用清单。
2. 加载项目级配置并保存应用解析、监听和共享默认值快照。
3. 构建每个应用的独立 App，依次叠加 `app/<name>/config`、注册组件并 Boot Provider。
4. 为所有应用加载并冻结路由；任一应用失败都终止启动。
5. 构建只读域名/路径解析器，校验宿主 TLS/HTTP3 配置后才监听网络。

应用级 `server` 配置不会覆盖宿主的地址、端口、TLS 或 HTTP3。项目入口关闭时按逆序释放子应用和受管资源。

## Air 热重载

如果 `air` 在 PATH 中，命令在项目根目录运行它，并把构建产物写入 `bin/server` 或 `bin/server.exe`。每次构建前刷新根应用清单与全部 `app/<name>/autoload_generated.go`，随后编译开发宿主。默认排除运行时、构建、框架、命令和依赖目录，避免生成文件造成重载循环。

## 普通模式

未安装 Air 时，命令提示安装方式并直接运行同一个多应用 HTTP 内核。宿主地址、端口、TLS、HTTP/3 和超时读取项目 `config/app.json`；允许 Host、请求体限制、压缩与业务配置可以按应用叠加。

入口组装见[入口文件](../架构/入口文件.md)，请求生命周期见[请求流程](../架构/请求流程.md)。
