# 命令行

命令行文档已按命令系统、输入解析、输出错误、内置命令、代码生成和服务启动拆分，请从[命令行章节索引](README.md)进入。
命令行入口在 `cmd/think` 包。运行方式：

```bash
go run ./cmd/think list
```

默认入口不编译业务清单，`service:discover` 可以修复引用了已删除类型的旧生成文件。需要业务应用的命令会自动用 `thinkgo_runtime` 标签编译并执行完整宿主。部署独立 CLI 时，使用 `go build -tags=thinkgo_runtime -o think ./cmd/think`，所得制品运行时无需 Go 工具链；源码生成命令进行 Go 语义分析时仍需要工具链。

全局帮助使用 `-h/--help`，版本使用 `-V/--version`，可放在命令前后。`thinkgo -v` 同样显示版本；小写 `-v` 仅在命令名前作为版本别名，放在命令名后仍按该命令自己的选项解析，以兼容 `verbose` 等既有短选项。`help build` 显示单个命令帮助，`list make --raw` 只输出指定命名空间的命令列表。完整项目创建与发布包构建参见[内置命令](内置命令.md)。

## 内置命令

| 命令 | 说明 |
|---|---|
| `list` | 列出命令 |
| `version` | 显示版本 |
| `create` | 在当前目录下创建完整项目，目标须不存在或为空 |
| `build` | 按平台生成包含二进制与运行资源的 dist 发布包 |
| `make:app` | 在现有项目中创建原生业务应用 |
| `clear` | 安全清理当前缓存后端和本地文件缓存 |
| `run` | 启动 HTTP 服务 |
| `route:list` | 按 `--app` 列出目标应用路由 |
| `config:dump` | 按 `--app` 输出应用配置并脱敏敏感值 |
| `migrate` | 按 `--app` 执行目标应用待处理的数据库迁移 |
| `migrate:status` | 按 `--app` 展示并校验迁移状态；首次调用可能初始化迁移管理表 |
| `migrate:rollback` | 按 `--app` 和批次回滚迁移 |
| `deploy:check` | 默认检查全部编译应用，也可用 `--app` 限定一个应用 |
| `make:controller` | 创建控制器 |
| `make:model` | 创建模型 |
| `make:command` | 创建命令 |
| `make:validate` | 创建验证器 |
| `make:middleware` | 创建中间件 |
| `make:event` | 创建事件 |
| `make:listener` | 创建监听器 |
| `make:subscribe` | 创建订阅者 |
| `make:service` | 创建服务 |
| `optimize` | 执行配置、路由和模型元数据优化 |
| `optimize:config` | 校验并生成配置优化快照 |
| `optimize:route` | 生成供 URL 构建使用的命名路由缓存 |
| `optimize:schema` | 读取数据库并缓存真实字段结构 |
| `route:export` | 校验并导出真实路由清单 |
| `schema:validate` | 校验模型映射或指定数据表的可查询性 |
| `service:discover` | 刷新根应用清单和每个 `app/<name>` 的静态发现文件 |
| `vendor:publish` | 发布已注册扩展资源 |

需要数据库的迁移和部署检查会初始化选中的业务应用；`route:list`、`config:dump` 和生成器也会解析同一份编译期应用清单，但不会仅为展示帮助而建立数据库连接。初始化失败直接返回错误，不会返回可继续使用的半初始化应用；自定义命令若需要数据库，应调用 `c.App.DB()` 并处理数据库未配置的情况。

## 部署检查

```bash
go run ./cmd/think deploy:check
go run ./cmd/think deploy:check --strict
go run ./cmd/think deploy:check --app admin --strict
```

部署检查逐项输出 `PASS`、`WARN` 或 `FAIL`，并标注业务应用名称。失败项始终返回非零退出码；`--strict` 也把警告视为阻断。未传 `--app` 时检查全部编译应用，传入后只检查指定应用。默认检查应用生命周期和启动错误、生产环境与调试开关、显式 Host、TLS 文件与私钥权限、运行时目录写入和清理、默认数据库查询、只读迁移状态、已加载路由、安全响应头，以及 `RELEASING.md` 和公开 Go module 路径。每个外部资源检查有 10 秒上限，不会无限等待。

## run

```bash
go run ./cmd/think run
go run ./cmd/think run -p 9000
go run ./cmd/think run --port=9000
```

`-p` / `--port` 会校验端口范围。应用初始化和配置依赖通过检查后，端口才会同时写入进程环境变量 `APP_SERVER_PORT` 和当前应用内存配置；启动检查失败不会污染进程状态。

命令会探测 `air`。已安装时使用热重载；未安装时通过原生多应用 HTTP 内核以普通模式启动，并提示安装方式。所有编译应用都必须完成初始化、路由加载和冻结，任一应用失败都不会监听端口；退出时由入口 App 逆序关闭全部应用。热重载模式会在项目根目录准备 `bin`，刷新根清单及每个应用的 `autoload_generated.go`，再把构建产物输出为 `bin/server` 或 `bin/server.exe`。热重载由命令行直接传递 Air 参数，不需要 `.air.toml`；默认排除 `runtime`、`bin`、`tmp`、`framework`、`cmd`、`vendor`、`testdata` 和 `assets`。

## route:list

```bash
go run ./cmd/think route:list
go run ./cmd/think route:list --app admin
```

未传 `--app` 时选择项目配置的 `default_app`，输出目标应用已经加载并冻结的路由方法、路径和处理器；应用不存在或配置类型错误会失败，不会回退到其它应用。

## config:dump

```bash
go run ./cmd/think config:dump
go run ./cmd/think config:dump app.server
go run ./cmd/think config:dump --app admin database
```

配置输出读取选中应用独立叠加后的配置，先按 JSON 语义归一化，再递归脱敏 `password`、`token`、`secret`、`session`、`cookie`、`authorization`、`credential`、`passphrase`、`private_key`、`api_key`、`access_key`、`connection_string`、`dsn`、`uri`、`url` 等字段。直接查询敏感点路径（例如 `config:dump database.password`）同样只输出 `[REDACTED]`，强类型映射和结构体不能绕过脱敏。

## 自定义命令

命令需要实现 `console.ICommand`。通常嵌入 `console.Command`：

```go
type Demo struct {
	console.Command
}

func (c *Demo) Configure() {
	c.Signature = "app:demo"
	c.Description = "执行应用命令"
	c.AddArgument("name", "目标名称", true)
	c.AddOption("output", "o", "输出目录", "./dist")
	c.AddBoolOption("force", "f", "强制覆盖")
}

func (c *Demo) Execute(input *console.Input, output *console.Output) error {
	name := input.GetArgument(0)
	dir := input.GetOption("output")
	force := input.GetOption("force")
	output.Writeln(name + " -> " + dir + " force=" + force)
	return output.Err()
}
```

注册命令：

```go
if err := cli.Register(&Demo{}); err != nil {
	return err
}
```

`ICommand.Execute`、`Console.Register` 和 `Console.Run` 都返回 `error`。命令业务错误、参数错误、重复注册和输出流写入错误必须向入口层传播；`cmd/think` 会输出到标准错误流并以非零状态退出。命令签名、描述及参数声明非法时注册失败，重复签名不会静默覆盖。

## 参数和选项

支持：

```text
--name value
--name=value
-n value
-n=value
--flag
-f
--
```

短选项会按命令声明映射到长选项。布尔选项出现即为 `true`，不会消费后续位置参数。声明为取值型的选项可以接收负数值，例如 `--offset -1`。

`--` 表示选项解析结束，后续 token 即使以 `-` 开头也会作为位置参数处理。

解析器会拒绝未知或重复选项、缺少选项值、非法布尔值、缺少必填参数和多余位置参数。`NewInput` 只使用显式传入的参数，不读取或修改全局 `os.Args`。

## 输出

```go
output.Write("text")
output.Writeln("line")
output.Info("info")
output.Warning("warning")
output.Error("error")
output.Success("success")
```

`Error` 写入 stderr，其余方法写入 stdout。颜色只在交互式终端启用；重定向或管道输出默认无 ANSI 序列，设置 `NO_COLOR` 或 `TERM=dumb` 也会禁用颜色。状态输出会转义换行和 ANSI 等控制字符，防止终端注入；调用方可通过 `output.Err()` 获取首个写入错误。

## 注意事项

生成器接受 `--app admin ClassName` 或 `admin@ClassName`，两种来源冲突时拒绝执行。类型路径支持 `admin@account/User` 或反斜线分隔，子目录必须是合法 Go 包名；绝对路径、空片段、点号与父目录跳转会失败。嵌套控制器、模型和验证器通过 `account.User` 名称注册。源码在 `app/<name>` 约束内格式化后独占创建，已有同名文件和并发覆盖都会失败。`make:model` 生成的构造器返回 `(*ModelType, error)`，通过 `db.NewModelFor` 绑定实例。

`clear` 默认先调用所选应用默认缓存 store 的 `Flush()`；后端失败时输出错误并停止本地清理。后端成功后，使用文件驱动清理应用缓存目录中受管的 `.cache` 与陈旧临时文件，保留活动锁、同步文件和非缓存文件；不会删除日志、文件 Session、证书或离线数据库文件。`session.type=cache` 的会话若位于本次清理的缓存后端，也会随缓存清理。

`clear [app]` 选择已注册应用，省略应用名时使用默认应用。`--cache` 显式选择上述缓存清理；`--expire` 仅回收应用本地缓存目录中的过期受管文件，不执行后端 `Flush()`；`--dir` 额外移除空子目录。显式 `--log` 或 `--path` 仍会递归清理选定目录中的文件，请仅将它们用于确实需要删除的运行数据。
