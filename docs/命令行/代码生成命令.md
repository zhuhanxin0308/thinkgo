# 代码生成命令

组件生成器只写入 `app/<应用名>`。目标应用可以使用 `--app/-a`，也可以使用 ThinkPHP 风格的 `应用名@类型名`；同时提供且名称不一致时拒绝执行。

```bash
go run ./cmd/think make:controller Account --app admin
go run ./cmd/think make:model admin@UserProfile
go run ./cmd/think make:validate UserProfile --app admin
go run ./cmd/think make:middleware Auth --app admin
go run ./cmd/think make:controller admin@account/User
go run ./cmd/think make:command Report report:daily --app admin
```

省略应用时使用项目 `app.default_app`；缺失时回退到已编译的 `index`。支持以 `/` 或反斜线分隔类型子目录，目录段必须是合法 Go 包名；拒绝绝对路径、点号、父目录跳转和逃逸根目录的链接。示例中的控制器写入 `app/admin/controller/account/user.go`，以 `account.User` 注册。

## 生成位置

| 命令 | 目标文件 |
|---|---|
| `make:controller` | `app/<app>/controller/<name>.go` |
| `make:model` | `app/<app>/model/<snake_name>.go` |
| `make:crud` | `app/<app>/api/<snake_name>.go` 与 `<snake_name>_test.go` |
| `make:validate` | `app/<app>/validate/<name>.go` |
| `make:command` | `app/<app>/command/<name>.go` |
| `make:middleware` | `app/<app>/middleware/<name>.go` |
| `make:event` | `app/<app>/event/<name>.go` |
| `make:listener` | `app/<app>/listener/<name>.go` |
| `make:subscribe` | `app/<app>/subscribe/<name>.go` |
| `make:service` | `app/<app>/service/<name>.go` |

控制器、模型和验证器创建成功后会刷新目标应用清单及根 `app/autoload_generated.go`。其它生成器只创建实现文件：服务必须加入 `app/<name>/service.go`，中间件必须加入 `middleware.go`，事件、监听器和订阅者必须加入 `event.go`，应用命令必须由项目控制台显式注册。完成声明后运行 `service:discover`，它会重新扫描全部 `app/<name>`；CI 使用相同逻辑校验生成结果。

名称会把下划线、短横线或空格分隔的单词转换为导出 Go 类型，例如 `user_profile` 变为 `UserProfile`。`make:controller` 支持 `--api` 和 `--plain`，同时提供时 API 模板优先；`make:model` 使用 snake_case 文件名。`make:command` 接受可选第二参数作为命令签名，省略时使用类型名的小写形式。

## 从模型生成 CRUD

`make:crud` 读取现有模型的 Go 类型、列名、JSON 标签、验证规则、默认值和字段注释。模型字段的 `doc` 标签优先于普通注释，选定字段的说明会写入生成请求及输出的 `doc` 标签。模型必须匿名嵌入 `*db.Model`；生成前先明确资源路径、允许写入的字段和允许输出的字段：

```bash
go run ./cmd/think make:crud admin@User --write Name,Active,Note --read ID,Name,Active,Note --path /users
```

`--write` 和 `--read` 使用 Go 字段名，均不可省略。默认主键字段为 `ID`，可用 `--key UID` 指定整数或字符串主键。主键列入 `--write` 时仅允许在创建时提交；PATCH 始终禁止修改主键。标记 `json:"-"` 的字段不能选入白名单，`thinkgo:"列名,readonly"` 字段只能输出。重复字段、无法表达的类型和非法路径会在写文件前报错。

生成结果包含五个接口，以及独立的创建、更新、路径、分页输入和输出结构体：

| 方法与路径 | 行为 |
|---|---|
| `GET /users` | 按主键排序的类型化分页，仅查询输出白名单列 |
| `POST /users` | 创建并重新读取，成功返回 201 |
| `GET /users/:id` | 查询详情，不存在返回 404 |
| `PATCH /users/:id` | 仅修改提交的字段，成功返回 200 |
| `DELETE /users/:id` | 遵循模型的物理或软删除配置，成功返回 204 |

创建时只提交选定字段，其他列保留数据库默认值。PATCH 使用 `binding.Optional[T]`，支持零值和可空字段的 null，拒绝空更新和非空类型的 null；模型中的创建默认值不会填入未提交的更新字段。页码默认 1、每页默认 20，生成的请求标签限制最多 10000 页、每页 100 条，可按业务调整。

创建、更新和删除使用应用默认数据库，在同一事务中执行读取与写入；包括写入后重新读取失败在内的错误都会回滚。数据库须支持事务，数据表由项目现有迁移管理。使用命名连接的模型须按连接归属调整生成的事务入口。

生成器刷新模型发现清单，但不自动挂载业务路由。在现有路由加载器中调用 `api.RegisterUserRoutes(router, registry)`，其中 `router` 可以是 `app.Route()` 或已配置鉴权中间件的路由分组，`registry` 为应用共享的 OpenAPI 注册表。五个处理器均通过 `openapi.Handle` 同时声明路由与契约。

配套的 `user_test.go` 验证实际签名、路由和 OpenAPI 契约是否一致；数据库约束、权限和业务规则仍应使用独立测试数据库及 `testkit` 编写项目测试。调整模型后重新运行测试，生成命令不会覆盖已有 API 文件。

## 从源码注释生成 OpenAPI 元数据

```bash
go run ./cmd/think openapi:generate
go generate ./internal/apidoc
go run ./cmd/think openapi:generate --check
```

首次执行后，在路由加载器中使用生成的 `apidoc.NewRegistry(info)` 和 `registry.Routes(router).Get(path, Handler)`。普通处理器注释提供标题和说明，类型与字段注释提供 Schema 描述，`@Tags` 等少量注解补充分组信息；真实路由、签名和验证标签决定契约。CRUD 处理器的生成注释可以直接用于此流程。

产物位于项目 `internal/apidoc/comments_generated.go` 与 `comments_generated.json`，随程序编译。命令不启动业务 Provider、不改写依赖文件；`--check` 不写入文件，缺失或过期时失败。已启用的产物会随 `service:discover` 和发现清单生成事务一起更新。用法与注解规则见 [OpenAPI 契约](../接口/OpenAPI.md)。

## 安全写入

- 生成源码先通过 `go/format`。
- CRUD 实现与契约测试的函数体还会通过 `go/types` 检查，模型字段遮蔽 ORM 方法等错误会在写入前报告。
- 文件在项目根约束内独占创建，不覆盖已有源码。
- 拒绝绝对路径、路径穿越和逃逸根目录的符号链接。
- 生成或发现刷新失败时回滚本次新文件。
- 并发创建同名文件时只允许一个调用成功。

生成后执行：

```bash
go run ./cmd/think service:discover
go test ./...
```

命令参数规则见[输入解析](输入解析.md)，应用目录见[目录结构](../基础/目录结构.md)。
