# 文件系统路径与对外引用

关联 issue #52。`Local.Path()` 返回绝对 OS 路径是它的正式用途；本改进不把它静默改为相对路径，也不把路径格式化视为访问授权。

## 不同引用的用途

| 引用 | 用途 | 不应推断的保证 |
| --- | --- | --- |
| `disk.Path(key)` | 进程内调用需要 OS 路径的库、可信运维操作 | 不能直接回显前端；不能把它当作安全的文件打开句柄 |
| `PutFile` / `PutFileAs` 返回值 | 已保存文件在磁盘内的相对 key | 不是授权凭据，也不保证业务文件名无敏感信息 |
| `disk.URL(key)` | 用显式配置的公共 URL 前缀构造编码后的引用 | 不验证文件存在、不发布文件、不检查访问权限 |
| 业务文件 ID | 通过应用下载路由访问私有文件 | 仍需按已认证身份核验对象和租户权限 |

**不要把 `Path()`、含路径的原始错误或整个内部存储对象直接序列化给客户端。** HTTP 响应应只选择需要的公开字段；错误对外返回通用消息，内部诊断信息只进入受控日志。不要把真实服务器路径配置为公共 URL 前缀。

## 公开文件与私有文件

对于明确决定公开且已由静态服务或 CDN 发布的文件，保留上传 API 返回的 key，再用配置好的 `URL` 生成引用。不要用绝对路径字符串替换、删前缀或手动拼接来伪造 URL：操作系统路径分隔符、空格、`?`、`#` 和 `%` 的语义不同。

[可执行的 Path 示例](../../filesystem/path_security_example_test.go) 仅输出“内部路径是绝对路径”的布尔结果和 `/storage/...` 引用，不打印临时服务器路径。其临时磁盘没有被自动发布到网络。

对于私有文件，不向客户端发送 OS 路径。保存业务 ID 与相对 key 的服务器端关联，通过认证下载路由检查权限，再使用磁盘读取 API。缺少 URL 配置时 `Local.URL` 返回 `ErrURLNotSupported`；不应降级为把 `Path()` 当下载地址。

`VisibilityPrivate` 控制磁盘权限，不会阻止被 Web 服务器发布的文件通过 HTTP 访问。相对 key 也可能暴露业务信息，不能省略授权。`PutFileAs` 的文件名应由可信业务策略决定；这些 API 不承担上传类型、MIME 和大小的全面验证，本项不替代 issue #20 的上传策略工作。

## 验证与覆盖边界

回归使用真实临时磁盘及 multipart FileHeader 保存文件，验证上传返回相对 key、按 key 读取、Path 仍返回正确绝对路径，以及只序列化 key/URL 的响应不包含部署根目录。覆盖空格、Unicode、URL 特殊字符、越界路径拒绝和未配置公共 URL 的私有磁盘。

```sh
go test -race -shuffle=on -count=10 -run '^(TestIssue52|ExampleLocal_Path_serverOnly)' ./filesystem
```

这里修复的是易误用边界的公开说明、可执行示例和回归保障，不新增文件鉴权机制、不改变存储接口，也不宣称可以自动防止应用自行回显内部路径。
