# clear 的项目目录边界

处理 issue #50：`thinkgo clear --path <目录>` 仅接受项目内的子目录。可使用相对路径或项目内绝对路径；拒绝项目根、文件系统根、项目外目录、名称仅共享前缀的兄弟目录及不同卷。CLI 帮助同步为 project subdirectory。已有依赖项目外清理的脚本必须显式改用独立运维操作，框架不提供静默绕过。

`--path` 和 `--log` 文件清理从已打开的项目 `os.Root` 相对打开目标，不能在词法校验后再按不受约束的绝对路径打开。目标必须是真实目录；打开后核对目录身份并拒绝项目根。递归使用目标 Root，子项符号链接仅删除链接，不跟随到其指向的目录。保留 `.gitignore`、无 `--dir` 时的目录，以及缺失子目录的无操作行为。

缓存模式仍先使用已配置缓存服务的 Flush，并保持原来的缓存文件格式/过期处理、锁及远端后端职责；本变更不是对 Redis 或应用显式配置的存储后端施加文件系统沙箱。命令选项的原有 cache/log/path 选择优先级不变。

边界来自 `os.Root`，不是对有权限修改项目根、移动已打开目录、挂载文件系统或直接访问数据的本地管理者的沙箱。项目根和存储配置仍须可信，文件权限和挂载布局由运维管理。

测试在独立临时目录检查外部数据保留、相对/绝对子目录、目录标志、缺失路径、直接与祖先符号链接，以及目标选择后替换祖先目录。平台不允许创建符号链接时仅对应链接子测试明确跳过，不把它记作覆盖成功。
