# 开发服务器监听地址

`thinkgo run` 未传入 `--host` 时默认使用 `127.0.0.1`，只接受同一主机的 IPv4 回环连接。`thinkgo create` 新项目的 `config/app.json` 同样生成 `server.host: "127.0.0.1"`，仓库参考项目也采用相同配置。这减少开发服务器意外暴露给局域网的风险，但不是鉴权、TLS、Host 校验或防火墙的替代。

需要局域网调试时，显式运行 `thinkgo run --host 0.0.0.0`。当前 `run` 的既有地址校验拒绝含冒号的 IPv6 地址；本次不扩大地址支持范围。对外监听前应检查应用环境、凭据、调试信息、允许的 Host 与防火墙范围。

Docker 和 Compose 生成文件继续显式设置 `APP_SERVER_HOST=0.0.0.0`，以接受容器端口映射。容器内全接口监听不等于限制宿主暴露；现有 Compose 的 `ports` 映射保持不变。仅供本机开发时，应另外把宿主端口映射绑定到 `127.0.0.1`。本次没有改变镜像、端口、挂载、权限或发布逻辑。

## 现有项目迁移

已有项目的配置文件不会被自动重写。直接运行已生成的业务程序或现有二进制时，要检查其 `config/app.json` 和环境覆盖值。`run` 仍遵循原来的命令选项覆盖环境与运行时配置的流程，本次仅改变默认选项值；显式 `--host` 的优先级与合法地址范围不变。

## 回归边界

测试检查选项声明、普通和热重载两条启动编排、子进程环境、实际生成项目配置及 Docker 显式覆盖。进程执行与下游依赖下载通过现有测试接缝隔离，不将这些测试表述为真实 air、Docker 网络或新项目完整编译验收。现有项目编译/HTTP 请求测试和跨平台 CI 仍须完整通过。
