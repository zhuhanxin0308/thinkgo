# 缓存锁竞争退避

处理 issue #46：`RememberWithLock` / `RememberWithLockContext` 在锁被占用时不再固定每 5ms 查询。重试上限从 5ms 开始倍增至 100ms；每次等待在当前上限的一半至上限之间随机选择，并截断到本次剩余等待预算。随机数只用于调度，不用于锁 owner 或其他安全凭据。

沿用原来的 5 秒锁等待预算，不把等待计入新缓存 TTL，不改变锁租约、owner 校验、续租、条件提交或回调结果语义。每次重试前检查取消和等待截止点；后端错误立即返回，不作为竞争重试。这里限制重试等待，不承诺不遵守 context 的自定义后端调用能被强制中断。

无竞争的首次获取不等待。代价是锁释放后被等待者观察到的延迟可能增加，抖动也不保证公平；该改动不是新的端到端 QPS 测量。

`testing/synctest` 虚拟时钟测试检查 5 秒截止、最多 110 次尝试、取消/超时/后端失败不执行回调及无竞争无延迟。上限断言对随机样本的任何取值均成立，不依赖真实机器执行速度。既有锁丢失、续租、提交和异常退出回归必须继续通过。
