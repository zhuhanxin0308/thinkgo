# 认证授权、响应头与限流

## Bearer 认证与 RBAC

`framework/auth` 把认证、主体存储和授权拆成三个独立契约。内置静态 Token 存储只保存 SHA-256 摘要，不保存 Bearer 明文；生产系统也可以实现 `auth.TokenStore`，从数据库或密钥服务按摘要查询主体。

```go
identity, err := auth.NewIdentity(
	"user-42",
	[]string{"admin"},
	nil,
	map[string]string{"tenant": "tenant-a"},
)
if err != nil {
	return err
}
store, err := auth.NewStaticTokenStore(map[string]auth.Identity{
	deploymentToken: identity,
})
if err != nil {
	return err
}
authenticator, err := auth.Bearer(store)
if err != nil {
	return err
}
rbac, err := auth.NewRBAC(map[string][]string{
	"admin": {"users.read"},
})
if err != nil {
	return err
}
_, err = router.Get(
	"/api/users",
	controller,
	auth.Authenticate(authenticator),
	auth.Require(rbac, "users.read"),
)
```

认证中间件严格拒绝缺失、重复、错误 scheme、首尾空白和超长 `Authorization`。认证失败返回 401 和 `WWW-Authenticate`；已认证但权限不足返回 403。`auth.IdentityFromRequest` 始终返回防御性副本，业务代码不能通过修改切片或 map 污染请求主体。

静态 Token 适合测试、内部工具或由环境层注入的小规模凭据。面向用户的登录系统仍应使用经过审计的密码哈希、MFA、撤销、轮换和会话策略，不应把密码直接作为 Bearer Token。

## 浏览器安全响应头

`config/security_headers.json` 默认启用安全响应头中间件，且同时覆盖框架 `Response` 和直接写入 `http.ResponseWriter` 的标准库处理器。默认 CSP 不允许内联脚本；应用若需要 CDN、nonce、WebSocket 或第三方资源，应按资源清单收窄策略，不要直接改成 `default-src *`。

HSTS 只对 `Request.IsSsl()` 已确认的 HTTPS 响应写出。启用 preload 时，`max-age` 必须至少一年且必须启用 `includeSubDomains`；提交浏览器 preload 列表还会影响所有子域，必须在域名治理完成后另行决策。

## 请求限流

全局限流通过 `config/rate_limit.json` 启用，算法为 GCRA。正常响应包含 `RateLimit-Limit`、`RateLimit-Remaining`、`RateLimit-Reset`；超额响应返回 429、`Retry-After` 和 `Cache-Control: no-store`。存储异常返回 503，不会把基础设施故障伪装成用户超额。

默认键使用 `Request.Ip()`，因此只在直接来源命中 `app.server.trusted_proxies` 时接受 `X-Forwarded-For`。登录、验证码、密码重置等接口还应按账号、租户或设备建立更严格的路由级限流器：

```go
store, err := ratelimit.NewMemoryStore(100_000)
if err != nil {
	return err
}
limiter, err := middleware.NewRateLimit(middleware.RateLimitConfig{
	Store: store,
	Limit: ratelimit.Limit{
		Rate:   5,
		Period: time.Minute,
		Burst:  5,
	},
	Key: func(request *context.Request) (string, error) {
		// 业务键必须是已经验证并规范化的稳定标识。
		return request.Post("account"), nil
	},
})
```

`ratelimit.Store.Take` 必须原子完成判定和状态更新。多实例部署应提供 Redis/Lua 或具有等价事务语义的实现；普通的“先读后写”缓存实现会在并发下突破额度，不能作为共享限流存储。
