# 安全规范

本章集中说明 ThinkGo 当前实现的安全默认值和业务开发必须遵守的边界。

## 路由安全

`url_route_must=true` 是默认安全基线，只允许显式注册的路由。自动路由只有显式配置为 `false` 时启用。

自动路由仅接受 GET/HEAD/OPTIONS，并屏蔽基础控制器内置方法；业务控制器中不希望暴露的只读方法仍不要导出。路由注册、命名、正则、域名和扩展名配置必须处理返回错误；服务启动或首次匹配后路由冻结，禁止运行期修改。

## Host 与代理头

配置 Host 白名单：

```json
{
    "server": {
        "allowed_hosts": ["example.com", "*.example.com"]
    }
}
```

未配置白名单时只接受语法合法的任意 Host；配置后不匹配会返回 421。带端口的 Host 只接受 `1-65535` 的十进制端口，IPv6 必须使用方括号，服务名端口、溢出端口、畸形括号和未加括号的 IPv6 会被拒绝。

`X-Forwarded-For` 和 `X-Forwarded-Proto` 只在请求来源命中可信代理网段时生效：

```json
{
    "server": {
        "trusted_proxies": ["127.0.0.1", "10.0.0.0/8"]
    }
}
```

也可以用环境变量覆盖：

```text
SERVER_ALLOWED_HOSTS=example.com,api.example.com
SERVER_TRUSTED_PROXIES=127.0.0.1,10.0.0.0/8
```

受信代理列表任一项非法时 HTTP 内核拒绝启动。`X-Forwarded-For` 从右向左剥离受信节点；多值 `X-Forwarded-Proto` 使用最右侧值，客户端预置的左侧伪造值不会覆盖最近代理写入的协议。

代理网段在启动时编译为不可变集合，HTTP 热路径不会重复解析配置。只有可信代理得出的 `Request.IsSsl()` 才会传给框架 Session/Cookie 与 CSRF 的协议校验；旧的直接 Cookie/Session API 仍保留请求级兼容判断。生产环境缺少具体 Host 白名单、Cookie/CSRF 密钥或 CSRF 开关时，框架按类别输出一次性 warning 并记录启动错误，`App.Run` 不会继续监听端口；`allowed_hosts` 不得使用全匹配 `*`。

## 请求输入安全

HTTP 内核在业务逻辑前解析请求体。重复 JSON 键、尾随文档、非对象根节点、过深嵌套、非法表单返回 400，请求体超过 `max_body_bytes` 返回 413。数值访问器拒绝截断、溢出和 `NaN`/`Inf`；参数格式化不会调用不受信对象的 `String()`。

## SQL 安全

优先使用安全查询 API：

```go
WhereField
WhereMap
WhereIn
WhereBetween
WhereLike
WhereNull
WhereColumn
WhereExp
```

框架会校验表名、字段名、排序字段、操作符、JOIN 条件和表达式 token。

`WhereRaw`、`HavingRaw`、`db.DB.Query`、`db.DB.Execute` 是显式原生入口。使用时必须参数化：

```go
database, err := framework.ResolveServiceAs[*db.DB](app, framework.ServiceDB)
if err != nil {
	return err
}
rows, err := database.Query("SELECT * FROM users WHERE id = ?", id)
```

禁止把用户输入拼入 SQL 字符串。

无业务 WHERE 的 `Update`、`Delete`、`ForceDelete`、`Restore` 会被拒绝；模型自动注入的软删除条件不能绕过该保护。

## NoSQL 安全

MongoDB 普通条件值必须是标量，指针会递归解引用，map、slice、array、普通 struct 会被拒绝，避免运算符注入。条件必须完整解析并消费全部参数；重复字段不会互相覆盖，空 IN 生成恒假过滤器。连接默认启用 TLS。

Neo4j 的标签、属性名和别名会校验并引用，写路径同样拒绝点分属性键；条件解析失败或参数多余会返回错误，不会退化为空条件。`Delete` 使用严格的单条参数化 `DELETE`，只有显式调用 `DetachDelete` / `DetachDeleteResult` 才允许连带删除关系，两种模式都从同次执行读取删除统计以避免竞态；连接默认使用 `neo4j+s`。

## 缓存安全

缓存配置严格校验且不做驱动回退。业务缓存键不得使用 `__thinkgo_tag__:`、`__thinkgo_tag_reverse__:`、`__thinkgo_lock__:` 内部前缀；标签元数据中的非法键、非法标签、重复成员和超量成员会被视为损坏数据，在删除业务数据前返回错误。

文件缓存把业务键映射为 SHA-256 文件名，读取时复核普通文件与已打开句柄身份，并限制单项为 16 MiB。符号链接、目录、超大项和损坏 JSON 均返回错误。写入使用同目录原子替换；删除过期项时匹配已读取文件身份，不能删除并发写入的新文件。`Flush` 保留锁文件和非缓存文件。

Redis 必须使用非空 `prefix` 隔离应用数据。前缀中的 glob 字符会按字面量转义，带前缀清理保留活动锁。空前缀默认返回错误，只有独占 Redis DB 才允许显式设置 `allow_flush_db=true`；该授权按 SCAN 清理所选 DB 的缓存键并保留 ThinkGo 活动锁。

缓存锁 owner 使用加密随机数。Redis 释放锁通过 Lua 原子校验 owner；文件锁通过独占创建、过期时间与文件身份复核释放。锁必须设置有限 TTL，且业务只能在 `Acquire()` 返回 `true, nil` 后进入临界区。

## 文件路径安全

静态文件、模板文件、语言包和安全下载都会校验最终路径是否仍在允许根目录内。静态文件、模板和下载会复核真实路径与已打开文件句柄，指向根目录外部的符号链接会被拒绝；模板与语言文件还受单文件大小上限约束。

用户输入参与下载路径时必须使用：

```go
context.NewResponse().DownloadSafe(baseDir, relativePath, filename)
```

`Download` 的文件路径必须来自受信任来源。下载文件名会被净化，防止 `Content-Disposition` 头注入。

`make:*` 源码生成器和开发证书工具使用应用根目录约束与独占创建。路径穿越、根目录外符号链接、已有目标和并发覆盖都会失败；生成失败会清理半成品，不会截断已有源码、证书或私钥。

## Cookie 与 Session

Cookie 配置支持前缀、过期时间、签名有效期、路径、域名、Secure、HttpOnly、SameSite 和签名密钥。非空签名密钥必须至少 32 字节。

Cookie 请求级实例允许先不绑定响应 writer，写入时会显式返回不可用错误；普通 `nil` 和承载 nil 指针的 `http.ResponseWriter` 都不会进入写入路径。

配置 `cookie.secret` 后，Cookie 值使用 URL 安全编码并带 HMAC-SHA256 签名，签名绑定 Cookie 名称、协议版本和时间戳。`Get` 返回 `(value, found, error)`，会明确区分缺失、空值、重复同名 Cookie、签名篡改、未来时间戳和签名过期。

HTTPS 请求下框架会强制 Cookie Secure；`SameSite=None` 也会强制 Secure。

Session ID 由密码学随机源生成，只有后端已知且信封有效的 ID 才会复用。文件驱动使用哈希文件名、原子替换、限长读取和跨进程锁；类 Unix 权限为 `0700/0600`，Windows 使用当前用户专属 DACL。

Windows 文件锁允许删除共享并在删除前复核 owner，冲突只做有界重试；它只解决同机文件驱动并发，不是分布式锁。框架启动、MultiHttp 生命周期和路由冻结不依赖数据库、Redis 或任何分布式锁。没有 `config/database.json` 时，非数据库模块仍应正常启动和工作；显式错误数据库配置才形成启动错误，连接不可达保持 warning 兼容行为。

并发请求通过驱动原子 `Update` 合并字段。`Regenerate` 与 `Destroy` 会为旧 ID 写入限时撤销墓碑，使已经读取旧会话的并发请求也不能重建旧登录态。登录、提权等敏感操作后必须处理错误：

```go
if err := session.Regenerate(); err != nil {
    return err
}
```

## CSRF

内置 CSRF 是签名双重提交 Cookie 模式，Cookie token 带时间戳与 HMAC-SHA256，单纯注入一个与请求头相同的 Cookie 值无法通过校验：

- GET、HEAD、OPTIONS 下发或修复签名 token Cookie。
- POST、PUT、PATCH、DELETE 等状态变更方法要求 Cookie token 签名有效，并与唯一的请求头或表单 token 常量时间相等。
- 重复同名 Cookie、重复请求头、重复表单字段、过期/未来 token 和损坏 multipart 均拒绝。
- `config/csrf.json` 的 `secret` 为空时优先复用 `cookie.secret`；两者都为空时生成进程级随机密钥。多实例生产部署必须配置相同的至少 32 字节密钥。

默认请求头：

```text
X-CSRF-Token
```

默认表单字段：

```text
_csrf
```

## CORS

CORS 通配来源 `*` 不会与凭证模式混用。只有白名单命中的 Origin 才会在允许凭证时回显，并设置 `Vary: Origin`。

## 调试信息

`app_debug` 和 `app_trace` 不应在生产环境开启。

URL 脱敏先按查询键结构化替换敏感值，再统一处理嵌套查询值、路径和片段；已脱敏的占位符保持 URL 编码，避免二次文本脱敏改变调试输出契约。

即使开启调试，异常调试页、JSON trace 和 Trace 调试条也只对本机回环请求开放；代理头中的客户端地址必须全部是回环地址。

异常页和日志会脱敏常见敏感字段；异常消息、异常原因和调试文本中的明确 `password`、`token`、`secret`、`authorization` 等键值会替换为脱敏标记，并覆盖 JSON/带引号的键值形式。调试请求体只读取有限前缀并恢复原始流，二进制与 multipart 请求体不展示，URL 查询参数、请求头和结构化请求体分别脱敏。数据库错误日志不会记录绑定参数值，原生 SQL 字符串字面量、PostgreSQL dollar quote、行注释与块注释内容也会被替换为脱敏标记：

```text
password passwd token secret authorization cookie session api_key refresh_token
```

生产环境中的 HTTP/业务 5xx 异常只返回通用消息和空数据；包装在 `errors.Join`/`fmt.Errorf("%w")` 中的框架异常仍按原类型处理。异常状态码只允许 4xx/5xx，响应写失败会返回给 HTTP 内核记录。

## 日志安全

数据库错误日志只记录字段名、脱敏 SQL 模板和参数数量，不记录参数值。业务日志也不要写入密码、token、Cookie、Authorization 或个人隐私数据。结构化上下文会递归快照并脱敏，控制字符会被转义；访问日志使用 URL 转义后的路径，编码换行不会被解码为新日志行。类 Unix 日志目录/文件权限为 `0700/0600`，Windows 使用仅授权当前进程用户的受保护 DACL。

## 静态资源

`public` 中的文件在动态路由和中间件之前处理，不会经过鉴权。只有 GET/HEAD 会进入静态资源和 SPA fallback；需要保护的文件不要放到 `public`。

## 配置与密钥

Cookie/CSRF 密钥和数据库密码优先通过真实系统环境变量 `COOKIE_SECRET`、`CSRF_SECRET`、`DB_PASS` 注入；全局 CSRF 可用 `APP_CSRF_ENABLE=true` 显式开启。`.env` 只作为本地兜底，不应提交。密钥会继续经过长度校验，且不会写入日志或配置转储。

`runtime` 目录包含日志、缓存、会话和证书私钥，不应提交到版本库。

开发证书工具生成 ECDSA P-256 自签名证书，任一目标已存在时拒绝覆盖，防止证书与私钥错配。类 Unix 私钥权限为 `0600`；Windows 使用禁止继承且仅授权当前用户的受保护 DACL。开发证书不得用于生产环境。

`config:dump` 对完整配置和直接点路径查询使用相同脱敏规则，覆盖密码、凭据、令牌、私钥、连接字符串、DSN 和 URI/URL；强类型映射和结构体会先按 JSON 语义归一化，不能绕过字段脱敏。

命令行状态消息会转义控制字符，错误写入 stderr；未知、重复、缺值和数量不匹配的参数会在执行前拒绝。命令、解析或输出失败必须返回非零退出状态。

## 供应链安全

构建和测试必须使用 `go.mod` 指定的 Go 1.26.5 或更高兼容安全补丁版本。提交前运行 `go mod verify`、`go mod tidy -diff` 和固定版本 `govulncheck`；CI 中第三方 Action 固定到完整提交哈希，Go 模块和 Action 升级通过 Dependabot 请求审查。

编译产物只能写入已忽略的 `bin`/`dist` 目录，不得提交可执行文件。`build.bat` 与 `build.sh` 生成的文件名必须包含 `nocgo`，禁止把缺少 SQLite CGO 能力的产物标记为完整构建。
