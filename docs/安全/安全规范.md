# 安全规范

本章集中说明 ThinkGo 当前实现的安全默认值和业务开发必须遵守的边界。

## 路由安全

`url_route_must=true` 是默认安全基线，只允许显式注册的路由。自动路由只有显式配置为 `false` 时启用。

自动路由会把控制器导出方法映射为端点。框架已屏蔽基础控制器内置方法，但业务控制器中不希望暴露的方法不要导出。

## Host 与代理头

配置 Host 白名单：

```json
{
    "server": {
        "allowed_hosts": ["example.com", "*.example.com"]
    }
}
```

未配置白名单时接受所有 Host；配置后不匹配会返回 421。

`X-Forwarded-For` 和 `X-Forwarded-Proto` 只在请求来源命中可信代理网段时生效：

```json
{
    "server": {
        "trusted_proxies": ["127.0.0.1", "10.0.0.0/8"]
    }
}
```

也可以用环境变量覆盖：

```text
SERVER_ALLOWED_HOSTS=example.com,api.example.com
SERVER_TRUSTED_PROXIES=127.0.0.1,10.0.0.0/8
```

## SQL 安全

优先使用安全查询 API：

```go
WhereField
WhereMap
WhereIn
WhereBetween
WhereLike
WhereNull
WhereColumn
WhereExp
```

框架会校验表名、字段名、排序字段、操作符、JOIN 条件和表达式 token。

`WhereRaw`、`HavingRaw`、`DB.Query`、`DB.Execute` 是显式原生入口。使用时必须参数化：

```go
rows, err := app.DB.Query("SELECT * FROM users WHERE id = ?", id)
```

禁止把用户输入拼入 SQL 字符串。

无 WHERE 的 `Update`、`Delete`、`ForceDelete`、`Restore` 会被拒绝。

## NoSQL 安全

MongoDB 条件值必须是标量，普通条件中传入 map、slice、array、struct 会被拒绝，避免运算符注入。

Neo4j 的标签和属性名会独立做标识符校验，条件解析失败会返回错误，不会退化为空条件。

## 文件路径安全

静态文件、模板文件、安全下载都会校验最终路径是否仍在允许根目录内。

用户输入参与下载路径时必须使用：

```go
context.NewResponse().DownloadSafe(baseDir, relativePath, filename)
```

`Download` 的文件路径必须来自受信任来源。下载文件名会被净化，防止 `Content-Disposition` 头注入。

## Cookie 与 Session

Cookie 配置支持前缀、过期时间、路径、域名、Secure、HttpOnly、SameSite 和签名密钥。

配置 `cookie.secret` 后，Cookie 值会带 HMAC 签名，并绑定 Cookie 名称和时间戳。签名默认 7 天过期；`Get` 和 `Has` 都会先验签，签名被篡改时按不存在处理。

HTTPS 请求下框架会强制 Cookie Secure；`SameSite=None` 也会强制 Secure。

Session ID 只允许有限字符集，并且只有后端已知的会话 ID 才会复用，避免会话固定攻击。登录、提权等敏感操作后应调用：

```go
session.Regenerate()
```

## CSRF

内置 CSRF 是双重提交 Cookie 模式：

- GET、HEAD、OPTIONS 下发 token Cookie。
- POST、PUT、PATCH、DELETE 等状态变更方法要求 Cookie token 与请求头或表单 token 一致，表单 token 支持 `application/x-www-form-urlencoded` 和 `multipart/form-data`。

默认请求头：

```text
X-CSRF-Token
```

默认表单字段：

```text
_csrf
```

## CORS

CORS 通配来源 `*` 不会与凭证模式混用。只有白名单命中的 Origin 才会在允许凭证时回显，并设置 `Vary: Origin`。

## 调试信息

`app_debug` 和 `app_trace` 不应在生产环境开启。

即使开启调试，异常调试页、JSON trace 和 Trace 调试条也只对本机回环请求开放；代理头中的客户端地址必须全部是回环地址。

异常页和日志会脱敏常见敏感字段；数据库错误日志不会记录绑定参数值，原生 SQL 字符串字面量也会被替换为脱敏标记：

```text
password passwd token secret authorization cookie session api_key refresh_token
```

## 日志安全

数据库错误日志只记录字段名、SQL 模板和参数数量，不记录参数值。业务日志也不要写入密码、token、Cookie、Authorization 或个人隐私数据。

## 静态资源

`public` 中的文件在动态路由和中间件之前处理，不会经过鉴权。需要保护的文件不要放到 `public`。

## 配置与密钥

密钥和数据库密码优先通过真实系统环境变量注入。`.env` 只作为本地兜底，不应提交。

`runtime` 目录包含日志、缓存、会话和证书私钥，不应提交到版本库。
