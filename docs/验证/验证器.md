# 验证器

验证器位于 `framework/validate`，支持 ThinkPHP 风格的字符串规则、场景、批量错误和多语言消息。

## 快速验证

```go
v := validate.Make(req.All(), map[string]string{
	"email": "required|email",
	"age":   "integer|min:1",
})

if !v.Check() {
	return c.Error(v.Error(), 422)
}
```

## 定义验证器

```go
package validate

import "thinkgo/framework/validate"

type UserValidate struct {
	validate.Validator
}

func NewUserValidate() *UserValidate {
	v := &UserValidate{}
	v.Rule = map[string]string{
		"email": "required|email",
		"name":  "required|length:2,20",
	}
	v.Message = map[string]string{
		"email.required": "validate.email_required",
		"email.email":    "validate.email_format",
	}
	v.Scene = map[string][]string{
		"create": {"email", "name"},
		"update": {"name"},
	}
	return v
}
```

使用：

```go
validator := NewUserValidate().SetLang(c.App.Lang)
if !validator.SetScene("create").Check(req.All()) {
	return c.Error(validator.GetError(), 422)
}
```

## 批量验证

```go
validator.Batch(true)
if !validator.Check(data) {
	errors := validator.GetErrors()
}
```

未开启批量验证时，返回第一条错误。

## 消息优先级

错误消息查找顺序：

1. `field.rule`
2. `field`
3. `rule`
4. 多语言默认键 `validate.default.rule`
5. 框架内置英文默认消息

消息中支持变量：

```text
{:field}
{:rule}
{:param}
```

## 常用规则

| 规则 | 说明 |
|---|---|
| `required` | 必填 |
| `number` | 数字 |
| `integer` | 整数 |
| `float` | 浮点数 |
| `boolean` | 布尔值 |
| `email` | 邮箱 |
| `array` | 数组或 map |
| `accepted` | yes/on/1/true |
| `date` | 可解析的日期或日期时间字符串 |
| `alpha` | 字母 |
| `alphaNum` | 字母数字 |
| `alphaDash` | 字母数字下划线横线 |
| `chs` | 中文 |
| `chsAlpha` | 中文和字母 |
| `chsAlphaNum` | 中文、字母、数字 |
| `chsDash` | 中文、字母、数字、下划线、横线 |
| `ip` | 合法 IPv4 地址 |
| `url` | URL |
| `mobile` | 中国大陆手机号 |
| `idCard` | 中国大陆身份证校验 |

## 参数规则

```text
in:1,2,3
notIn:1,2,3
between:1,10
notBetween:1,10
length:6
length:6,20
max:20
min:2
eq:active
gt:10
lt:100
egt:10
elt:100
regex:^[a-z]+$
confirm:password_confirm
different:old_password
dateFormat:2006-01-02
after:start_at
before:end_at
requireIf:type,email
requireWith:email,phone
```

`regex` 规则会缓存编译结果；非法正则会验证失败。

未知规则会失败关闭并进入错误列表。规则名拼写错误不会静默通过，也不会因为字段缺失而跳过。

## 场景行为

场景只会验证场景字段中声明且存在规则的字段。执行一次 `Check` 后，当前场景会自动清空，避免下一次验证误用旧场景。
