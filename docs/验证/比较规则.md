# 比较规则

比较规则分为字符串等值、数值比较和数值区间。规则参数在计划编译阶段校验，运行时不会把非法参数当作数据失败。

## in 与 notIn

```text
in:red,green,blue
notIn:disabled,deleted
```

值先转换为标量文本，再与逗号列表中的项做精确匹配：`in` 必须命中，`notIn` 必须不命中。候选值不能为空，列表不能包含空项；规则不做大小写折叠。

## between 与 notBetween

```text
between:1,10
notBetween:1,10
```

两个边界使用任意精度数值解析：

- `between` 包含上下界，即 `1` 和 `10` 都通过。
- `notBetween` 要求值位于闭区间之外；边界值不通过。

边界必须是有效十进制数，且下界不能大于上界。

## eq

```text
eq:active
```

`eq` 比较标量文本的精确值。参数可以是空字符串，也可以是其它已解析文本；布尔和数值会按框架的标量文本形式比较。需要比较两个字段的值时使用[字段关系与条件规则](字段关系与条件规则.md)中的 `confirm` 或 `different`。

## gt、lt、egt、elt

这些规则只做数值比较，不把字符串长度当成数值边界：

| 规则 | 条件 |
|---|---|
| `gt:n` | 值大于 `n` |
| `lt:n` | 值小于 `n` |
| `egt:n` | 值大于或等于 `n` |
| `elt:n` | 值小于或等于 `n` |

它们使用任意精度十进制数，拒绝非数值、NaN、Inf、十六进制和分数参数。

## 请求 DTO 的浮点舍入边界

`binding.Bind` 会先按原始输入执行规则，再对最终写入 `float32` 或 `float64` 的
实际二进制数值复查 `gt`、`lt`、`egt`、`elt`、`min`、`max`、`between` 和
`notBetween`。例如 `0.99999999` 绑定为 `float32` 后变为 `1`，因此不能通过
`lt:1`。复查覆盖指针、`Optional`、嵌套对象和集合内的对象；失败时保持调用方
目标对象不变。配置默认值也在启动预编译时按舍入后的数值检查。

这也意味着十进制边界不会自动放宽以容忍二进制表示误差：`float32` 和 `float64`
中的 `0.1` 都略大于精确十进制 `0.1`，所以带 `max:0.1` 的浮点 DTO 会拒绝该输入。
需要精确十进制边界的金额、比例等字段应使用 `json.Number` 或以明确单位表示的整数；
如果业务允许误差，应在字段规则中明确给出容差。`eq`、`in`、正则等依赖原始表示的
规则继续检查输入原文，不用舍入后的字符串替换原文。
