# 验证规则语法

验证器先解析字段定义，再解析规则列表。解析发生在验证执行前，未知规则和畸形参数都会失败关闭。

## 字段与别名

```go
validator.SetRules(map[string]string{
	"email|邮箱地址": "required|email",
})
```

字段定义只使用第一个 `|` 分隔实际字段名和显示别名：

- 实际字段名不能为空。
- 字段定义总长度不超过 512 字节。
- 有别名时别名不能为空，且不能再包含 `|`。
- 多个规则定义解析为同一个实际字段时返回 `ErrInvalidRule`。

实际字段名会用于读取 `data`，别名只用于错误消息和 `Violation.Alias`。

## 规则列表

```text
required|email|length:6,32
```

`|` 分隔规则；空列表、首尾空规则、未完成转义和未闭合引号都会返回配置错误。一个字段不能重复使用完全相同的规则名和参数。

## 参数引号与正则

含有规则分隔符的参数可以用单引号或双引号包裹：

```text
eq:"a|b"
regex:"^(foo|bar):\d+$"
regex:/^(foo|bar)$/
```

双引号和单引号参数会去除外层引号，并只对同类引号的反斜杠转义做还原。斜杠包裹只对 `regex` 识别；参数闭合后如果还有非空尾随内容会失败。

正则使用 Go `regexp` 语法。正则参数最多 4096 字节，编译缓存最多 256 个模式；非法模式不会进入缓存。

## 参数分隔

逗号用于 `in`、`between`、`length` 和条件规则的参数列表：

```text
in:red,green
between:1,10
length:2,20
requireIf:type,staff
requireWith:email,phone
```

列表项会去首尾空白；空项、边界数量不对、长度为负数、数值格式非法或边界倒置都会返回 `ErrInvalidRule`。

## 规则参数分类

无参数规则包括 `required`、`number`、`integer`、`float`、`boolean`、`email`、`array`、`accepted`、`date`、`alpha`、`alphaNum`、`alphaDash`、`chs`、`chsAlpha`、`chsAlphaNum`、`chsDash`、`ip`、`url`、`mobile` 和 `idCard`。给它们附加参数会失败。

需要参数的规则及数量见各规则章节。规则名区分大小写，未知名称返回 `ErrUnknownRule`。
