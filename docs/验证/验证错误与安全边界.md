# 验证错误与安全边界

配置错误在验证计划编译阶段失败，数据违规则作为结果返回。调用方可以使用 `errors.Is` 区分错误类别。

## 错误类型

| 错误 | 典型原因 |
|---|---|
| `ErrUnknownRule` | 规则名称拼写错误或框架未实现该规则 |
| `ErrInvalidRule` | 字段定义、规则分隔、参数数量、数值边界、显式固定日期或正则参数非法 |
| `ErrUnknownScene` | `WithScene` 指向未注册场景 |
| `ErrInvalidScene` | 场景为空、重复字段、字段无规则或名称非法 |
| `ErrInvalidOption` | `nil` option、空/超长场景或同调用冲突选项 |

```go
result, err := validator.Validate(data)
switch {
case errors.Is(err, validate.ErrUnknownRule):
	// 服务端规则配置错误。
case errors.Is(err, validate.ErrInvalidScene):
	// 服务端场景配置错误。
case err != nil:
	// 其它验证调用错误。
case !result.Valid():
	// 用户数据违规。
}
```

## 解析上限

- 字段定义最多 512 字节。
- 单个字段的规则列表最多 16384 字节。
- 正则模式最多 4096 字节。
- 全局正则缓存最多 256 个已编译模式，非法模式不缓存。
- 场景名最多 256 字节。

这些上限在规则配置阶段检查，避免把超长输入或无限增长的动态正则带入运行时。

## 类型和精度

数值比较使用任意精度十进制数，并拒绝 NaN、Inf、十六进制和分数文本。长度只对字符串和集合计算，不能把布尔值或数字格式化后冒充字符串长度。标量转换不会调用不受信对象的 `String` 方法。

## 日期目标与请求字段隔离

`beforeDate`、`afterDate` 只接受固定日期，非法参数在计划编译时返回 `ErrInvalidRule`；`beforeField`、`afterField` 只读取明确命名的字段，目标缺失或值无效时返回数据违规。规则类型不会随请求字段的增删而变化。

兼容规则 `before`、`after` 在编译时将合法日期识别为常量，其余参数识别为字段名。合法日期形式的字段引用应迁移到 `Field` 规则；固定边界推荐使用 `Date` 规则，避免无效日期文本被兼容语法解释为字段名。具体行为与升级步骤见[字段关系与条件规则](字段关系与条件规则.md)。

## 并发安全

验证器配置、计划缓存和正则缓存都有并发保护；setter 复制调用方输入，结果访问器返回副本。业务代码仍不应在 setter 调用后并发修改同一个配置切片，也不应把可变请求 map 写入共享全局状态。
