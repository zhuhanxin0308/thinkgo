# 验证器配置与并发

验证器配置由 `Validator` 持有，并由读写锁保护。setter 在提交时复制调用方 map 或 slice，因此配置完成后修改原始输入不会污染验证器。

## 规则与消息

```go
validator := validate.NewValidator()
validator.SetRules(map[string]string{
	"name": "required|length:2,20",
})
validator.SetMessages(map[string]string{
	"name.required": "姓名不能为空",
})
```

- `SetRules` 原子替换全部规则，并使已缓存的验证计划失效。
- `SetMessages` 原子替换全部自定义消息，不需要重新解析规则。
- 每个字段只能有一个实际字段定义；别名只影响显示，不改变数据 map 的字段名。

## 场景与语言

```go
validator.SetScenes(map[string][]string{
	"create": {"name", "email"},
})
validator.AddScene("update", []string{"name"})
validator.SetLang(languageManager)
```

`SetScenes` 会替换全部场景并复制每个字段切片；`AddScene` 注册或替换一个场景，并使计划失效。`SetLang` 保存验证器默认使用的语言管理器，用于解析消息键和默认规则消息；请求级语言标识应通过 `WithLocale` 传入。

## 配置快照与计划

`SetRules`、`SetScenes` 和 `AddScene` 会增加配置版本并清空计划缓存。验证执行时会在版本稳定后缓存按场景编译的字段计划；并发替换配置时，调用不会读取到半套规则。

消息和语言只在验证调用获取快照，不会改变已编译的规则计划。每次验证返回自己的违规切片，同一个验证器可以被多个请求并发使用。

## 使用边界

setter 返回验证器指针，便于链式配置，但不会校验全部规则直到下一次 `Validate`。因此应在应用启动或测试阶段主动执行一次验证，确保未知规则、非法参数和错误场景尽早暴露。

请求级语言应使用 `WithLang` 和 `WithLocale` 显式传入。验证器只读取语言管理器，不会改变其当前语言；不要在并发请求中反复调用共享 `Lang.SetLang` 改变全局状态。
