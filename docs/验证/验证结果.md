# 验证结果

`Result` 只表示用户数据违规。规则未知、场景非法和调用选项错误通过 `Validate` 的 `error` 返回，不会混入 `Result`。

## Result API

```go
result, err := validator.Validate(data)
if err != nil {
	return err
}
if result.Valid() {
	return nil
}

first := result.FirstError()
messages := result.Errors()
violations := result.Violations()
```

方法语义如下：

| 方法 | 语义 |
|---|---|
| `Valid()` | 没有违规时返回 `true` |
| `FirstError()` | 第一条消息；没有违规时返回空字符串 |
| `Errors()` | 按违规顺序返回消息切片 |
| `Violations()` | 返回结构化违规切片 |

`Errors` 和 `Violations` 都返回防御性副本，调用方修改结果不会污染原始 `Result`。

## Violation

每条 `Violation` 包含：

| 字段 | 含义 |
|---|---|
| `Field` | 实际字段名，用于定位输入数据 |
| `Alias` | 用户可见别名，没有别名时为空 |
| `Rule` | 失败的规则名 |
| `Param` | 规则参数 |
| `Message` | 已完成消息查找和变量替换的文本 |

别名只用于消息展示，`Field` 始终保留实际字段名。

## 错误处理顺序

```go
result, err := validator.Validate(data)
if err != nil {
	// 服务端配置或调用错误。
	return err
}
if !result.Valid() {
	// 用户输入错误。
	return errors.New(result.FirstError())
}
```

不要在 `err != nil` 时读取违规消息来构造用户输入响应，也不要只用 `result.Valid()` 判断规则配置是否成功。
