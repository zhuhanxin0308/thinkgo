# 验证消息与多语言

验证失败时，框架会为字段和规则生成一条 `Violation.Message`。消息可以是直接文本，也可以是框架 `lang` 包中的翻译键。

## 查找顺序

对字段 `email` 和规则 `required`，`SetMessages` 按以下顺序查找：

1. `email.required`
2. `email`
3. `required`
4. 语言包中的 `validate.default.required`
5. 验证器已有的默认规则消息

```go
validator.SetMessages(map[string]string{
	"email.required": "validate.email_required",
	"email.email":    "validate.email_format",
})
validator.SetLang(languageManager)
```

自定义消息存在且设置了语言管理器时，框架先把它作为语言键读取；语言管理器没有对应键时保留原消息文本。未设置语言管理器时，自定义消息直接作为文本使用。没有自定义消息且语言包缺少默认规则键时，验证结果保留已有默认消息，例如 `name is required`。这延续 ThinkPHP 8 的“默认规则消息可翻译，缺失翻译保留消息”风格，不改变既有无语言选项调用的结果。

## 消息变量

自定义消息和语言包默认规则消息都支持：

| 占位符 | 替换值 |
|---|---|
| `{:field}` | 显示别名；没有别名时为实际字段名 |
| `{:rule}` | 规则名 |
| `{:param}` | 规则参数 |

```json
{
    "validate": {
        "default": {
            "required": "{:field}不能为空",
            "length": "{:field}长度必须为{:param}"
        }
    }
}
```

`Violation.Field` 仍然保存实际字段名，消息只使用显示别名。

## 默认规则消息

默认消息优先查找 `validate.default.<rule>`。语言服务先查请求语言，再回退其默认语言；两者均缺失时使用验证器已有的默认规则消息。字段别名与 `{:field}`、`{:rule}`、`{:param}` 占位符在两条路径中保持一致。

## 请求语言

验证器本身不读取 HTTP 请求，但可以通过本次调用的选项显式接收语言上下文：

```go
validator.SetLang(languageManager)
result, err := validator.Validate(
    data,
    validate.WithLocale(requestLocale),
)
```

`WithLang` 可以只为当前调用指定语言管理器，`WithLocale` 只为当前调用指定语言标识；两者都不会修改共享语言服务的当前语言。控制器基础验证辅助会自动传入应用语言服务和当前请求语言，因此控制器不应在请求协程中调用共享语言服务的 `SetLang`。
