# 缓存生命周期

`Cache` 的 store 视图共享同一个内部状态：

```go
applicationCache, err := framework.ResolveServiceAs[*cache.Cache](app, framework.ServiceCache)
if err != nil {
	return err
}
secondary, err := applicationCache.Store("memory")
if err != nil {
	return err
}
// secondary 与 applicationCache 共享关闭状态，但操作的是不同驱动。
```

## 并发操作

缓存管理器用生命周期读写锁阻止关闭与新操作并发冲突，用标签锁保证标签元数据变更的原子顺序。已有操作会在 `Close` 等待；关闭不会在驱动仍被调用时提前释放连接。

同一驱动实例注册到多个 store 时，`Cache.Close` 只调用一次它的 `Close`。不同 store 的普通读写数据仍由各自驱动决定是否隔离。

## 关闭

```go
if err := app.Close(); err != nil {
	return err
}
```

关闭是幂等的，会拒绝后续缓存操作并返回 `ErrCacheClosed`，随后关闭所有具备 `Close() error` 的唯一驱动，并聚合关闭错误。框架托管的缓存必须通过 `App.Close()` 统一关闭；只有独立创建的 `cache.Cache` 才由创建方直接调用 `Close`。

`Flush` 只是清理数据，不是生命周期关闭；它不会释放 Redis/File/Memory 锁。需要结束驱动连接时使用 `Close`。
