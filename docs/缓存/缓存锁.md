# 缓存锁

缓存锁通过 `Lock` 创建：

```go
applicationCache := app.Cache()
lock, err := applicationCache.Lock("job:daily", 30*time.Second)
if err != nil {
	return err
}
acquired, err := lock.Acquire()
if err != nil {
	return err
}
if !acquired {
	return nil
}
defer lock.Release()
```

TTL 为 0 时使用默认 10 秒；负数或超过 24 小时会返回 `ErrInvalidCacheTTL`。每个 Lock 实例生成随机 owner，只有成功获取该锁的实例才能释放它。实现 `LockRenewer` 的驱动支持 `lock.Renew(ttl)`，续租同样需要 owner 匹配且只能作用于仍未过期的锁。`RememberWithLock` 和标签变更会在驱动支持续租时自动按租约周期续期；直接使用 `Lock` 的长任务仍应显式调用 `Renew`。

`Acquire` 在锁已被其它 owner 持有时返回 `false, nil`；同一实例重复获取也返回 false，不会重复覆盖 owner。`Release` 在未获取、锁已过期或 owner 不匹配时不会删除别人的锁。

## 驱动能力

- Memory：进程内锁，只能保护同一进程。
- File：通过独占创建、同一句柄 OS 文件锁和原地载荷更新提供跨进程锁，并支持 owner 续租。
- Redis：使用 `SET NX` 和 TTL 获取锁，使用 owner 校验的 Lua 脚本释放和续租。
- DB：在缓存表内使用 owner/expiry 条件更新实现 `DistributedLocker`，并保留活动锁记录。

`Cache.Flush` 不释放锁。Redis 带前缀清理时会跳过锁键；文件驱动清理只处理 `.cache` 和陈旧临时文件，不处理活动 `.lock`。锁的自动过期不是业务执行成功的保证，长任务应把 TTL 设计为覆盖临界区并处理获取失败。

需要在缓存未命中时合并跨管理器或跨进程加载，请使用 `RememberWithLock`；它会在锁保护下二次检查缓存，并对获取超时和锁丢失返回明确错误。Memory、File、Redis 和 DB 支持自动续租及租约保护提交；自定义驱动必须实现 `DistributedLocker`、`LockRenewer` 和 `LockGuardedUpdater`，缺失能力会在加载回调前返回 `ErrCacheLockUnsupported`。直接使用基础 `Lock` API 的调用方仍应保证租约覆盖临界区并自行处理丢锁。
