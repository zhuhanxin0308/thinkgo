# 缓存基础

最小用法：

```go
applicationCache := app.Cache()
if err := applicationCache.Set("user:1", user, 10*time.Minute); err != nil {
	return err
}

value, found, err := applicationCache.Get("user:1")
if err != nil {
	return err
}
if !found {
	// 未命中。
}
```

## 基础操作

| API | 语义 |
|---|---|
| `Get(key)` | 返回值、命中标志和错误；命中 `nil` 时 `found=true` |
| `Set(key, value, ttl)` | 写入；`ttl=0` 表示永久 |
| `Has(key)` | 判断未过期键是否存在 |
| `Forget(key)` | 删除业务键并清理标签反向关系 |
| `Forever(key, value)` | 等价于 `Set(key, value, 0)` |
| `Flush()` | 清理当前 store 数据和标签元数据，但保留锁 |
| `Inc(key, step)` | 递增严格整数 |
| `Dec(key, step)` | 递减严格整数 |

键不能为空，不能包含控制字符或内部保留前缀。公共缓存键最长 1024 字节；TTL 不能为负数或超过 100 年。

## TTL

TTL 为正数时，驱动保存过期时间；读取和 `Has` 遇到已过期条目会按未命中处理。TTL 为 0 不设置过期时间。

`Inc` 和 `Dec` 在已有条目上会保留其剩余 TTL；对不存在或已经过期的键，会从 0 开始创建计数值。步长不能为负数，计数超出 `int64` 范围时返回溢出错误。

## 调试追踪

应用通过 `app.Cache()` 获取根缓存 facade；请求处理应使用控制器的 `c.RequestCache()`，或调用 `applicationCache.WithDebug(debug.FromRequest(req))` 派生请求级 facade，让 `GET`、`SET`、`HAS`、`FORGET`、`FLUSH`、`INC`、`DEC`、`REMEMBER` 以及标签操作只进入当前请求 collector。业务键会以缓存操作记录的形式出现在 Trace 面板中，collector 达到固定上限后标记截断。未配置 Debug 对象时缓存仍可正常工作。

不要把当前请求、请求 collector 或 `RequestCache` 保存到全局变量、共享单例或跨请求控制器字段；跨请求复用的只能是缓存驱动和不可变配置。`WithDebug` 只创建轻量 facade，共享缓存生命周期，不复制或关闭底层 store。
