# 标签缓存

标签缓存用于按业务标签批量失效缓存键：

```go
applicationCache, err := framework.ResolveServiceAs[*cache.Cache](app, framework.ServiceCache)
if err != nil {
	return err
}
users, err := applicationCache.Tag("users", "tenant:1")
if err != nil {
	return err
}
if err := users.Set("user:1", value, time.Hour); err != nil {
	return err
}
if err := users.Flush(); err != nil {
	return err
}
```

`Tag` 会校验并去重标签。标签不能为空、包含控制字符或首尾空白，最长 128 字节；一个缓存键最多 64 个标签，一个标签最多 10000 个成员。

## 双向元数据

框架同时维护：

- 标签到成员键的正向列表；
- 缓存键到标签的反向列表。

`Set` 会在写业务值前绑定元数据；任一步骤失败会按已写入顺序回滚。`Forget` 会删除业务值并移除两类关系；删除失败时也会尝试恢复元数据。元数据中出现重复、不合法类型、正反向不一致或超出限制时返回 `ErrCorruptTagMetadata`，不会根据可疑成员直接删除任意业务键。

## 读取与刷新

带标签视图的 `Get`/`Has` 发现自然过期时，会调用 `Forget` 清理残留关系。`TaggedCache.Flush` 只删除选定标签关联的业务键和元数据，不清空整个 store；它会先验证正反向关系，再执行删除。

标签和缓存键使用框架保留前缀保存元数据。业务代码不能直接使用这些前缀，普通 `Flush` 会清理标签元数据但保留锁。
