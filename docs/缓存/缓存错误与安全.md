# 缓存错误与安全

常见管理器错误：

| 错误 | 含义 |
|---|---|
| `ErrCacheDriverNotConfigured` | 当前 store 没有驱动 |
| `ErrCacheStoreNotFound` | 具名 store 不存在 |
| `ErrCacheStoreExists` | 同名 store 已绑定其它驱动 |
| `ErrInvalidCacheStore` | store 名称或驱动非法 |
| `ErrInvalidCacheKey` | 键为空、过长、非法 UTF-8 或包含控制字符 |
| `ErrReservedCacheKey` | 使用框架内部元数据或锁前缀 |
| `ErrInvalidCacheTag` | 标签、成员数量或标签数量越界 |
| `ErrInvalidCacheTTL` | TTL 超出范围 |
| `ErrCacheLockUnsupported` | 驱动不支持锁 |
| `ErrCorruptTagMetadata` | 标签元数据损坏或正反向不一致 |
| `ErrCacheClosed` | 管理器已经关闭 |

公共边界：

```text
缓存 TTL 最大 100 年
缓存键最大 1024 字节
标签最大 128 字节
单键最多 64 个标签
单标签最多 10000 个成员
锁默认 TTL 10 秒，最大 TTL 24 小时
```

驱动还可能有更窄的后端限制：DB 键最长 255 字节，File 单项读取最大 16 MiB，Redis 前缀最大 256 字节。管理器错误和驱动错误都应向上返回，不要把后端损坏、Redis 清库未授权或文件路径错误转换成缓存未命中。

应用层 `clear` 命令默认先调用所选应用默认 store 的 `Flush`，后端失败会停止后续本地清理；默认不会删除日志、文件 Session、证书或其它运行时文件。`session.type=cache` 的会话若位于被清理的缓存后端，也会被清理。显式 `--log`、`--path` 按指定目录删除文件。Redis 空前缀的整库清理必须显式授权，避免误删同一 Redis DB 中的非应用键。
