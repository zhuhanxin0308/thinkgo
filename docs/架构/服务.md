# 服务

ThinkGo 的应用服务与 ThinkPHP 使用相同的组织方式。根 `app/service.go` 和 `app/service` 承载所有业务应用共享的项目服务；`app/<name>/service.go` 和 `app/<name>/service` 承载目标应用独占的服务。`service:discover` 会把两层定义编译进应用清单，业务控制器不需要接触 Provider、启动器或框架内部注册表。

## 创建服务

```bash
go run ./cmd/think make:service --app index Billing
```

命令会生成 `app/index/service/billing.go`。服务嵌入 `framework.Service` 后，可以在无参数的 `Register` 和 `Boot` 方法中通过 `App()` 取得当前业务应用：

```go
package service

import "github.com/zhuhanxin0308/thinkgo/framework"

type Billing struct {
	framework.Service
}

func (service *Billing) Register() error {
	return service.App().Instance("service.Billing", service)
}

func (service *Billing) Boot() error {
	return nil
}
```

`Register` 用于容器绑定和服务装配；`Boot` 在所有服务完成注册后执行。两者都可以省略错误返回值，分别写成 `Register()` 和 `Boot()`。

## 服务定义

需要启用的 index 应用服务集中写在 `app/index/service.go`：

```go
package index

import "example.com/project/app/index/service"

func Services() []interface{} {
	return []interface{}{
		&service.Billing{},
	}
}
```

修改 `Services()` 后运行 `go run ./cmd/think service:discover`，生成清单会包含 `Services: Services()`。框架按列表顺序调用各服务的 `Register`，全部注册完成后再按相同顺序调用 `Boot`。同一类型默认只注册一次；需要与 ThinkPHP 的 `register($service, true)` 相同的强制重注册行为时，可调用 `application.Register(service, true)`。

## 默认 AppService

项目已经提供 `app/app_service.go`：

```go
type AppService struct {
	framework.Service
}

func (*AppService) Register() {}

func (*AppService) Boot() {}
```

根 `AppService` 会装配进每个编译应用，只适合跨应用基础能力。普通业务规则应拆分到 `app/<name>/service`，避免把所有业务堆入项目全局服务。

## 业务调用边界

推荐的业务调用顺序是：

```text
Controller -> Validator -> Service -> Model/ORM
```

控制器负责读取请求、选择验证场景、调用服务并生成响应。服务负责业务规则、事务、缓存和外部依赖编排；模型负责表结构映射和数据访问。业务代码不应依赖框架的 Provider 生命周期或 HTTP 监听实现。

## 生命周期

应用启动时，服务位于与 ThinkPHP 一致的阶段：

```text
加载环境变量和项目 config
  -> 加载根 app/event.go、app/service.go
  -> 项目 Service.Register
  -> AppInit
  -> 加载 app/<name>/config、event.go、service.go
  -> 应用 Service.Register
  -> 全部 Service.Boot
  -> HttpRun
  -> RouteLoaded（首次加载路由时）
  -> 请求分发
  -> HttpEnd
```

需要理解依赖绑定时阅读[容器和依赖注入](容器和依赖注入.md)，需要查看完整 HTTP 顺序时阅读[请求流程](请求流程.md)。
