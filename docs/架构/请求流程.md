# 请求流程

每个请求先进入项目 HTTP 宿主，再解析到一个已初始化且路由已冻结的应用处理器。应用身份只存在于请求上下文中。

## 启动阶段

1. 根入口创建项目 `framework.App`，`app.Register` 注册项目全局定义和全部 `ApplicationDefinition`。
2. 项目配置加载后保存完整快照，再为每个应用叠加 `app/<name>/config`。
3. 全部应用初始化、Boot Provider，并解析各自 HTTP 请求配置。
4. 全部应用执行正式路由加载器并冻结索引。
5. 使用项目快照构建域名/路径解析器和宿主监听配置。
6. 校验 TLS/HTTP3 后才开始监听；任一步失败都会整体退出。

## 单次请求

```text
原生 http.Request
      ↓
Host 与路径安全校验
      ↓
domain_bind / app_map / 应用前缀 / default_app
      ↓
写入 ApplicationContext，并按需重写应用内路径
      ↓
项目全局中间件
      ↓
目标应用中间件
      ↓
创建目标应用的 ContainerScope 和 Request
      ↓
HttpRun -> Request.Parse
      ↓
静态文件或目标应用 Route
      ↓
路由中间件 -> 控制器中间件 -> 控制器动作
      ↓
Response -> HttpEnd -> terminate -> 清理
```

全局中间件可观察原始公开路径，应用中间件和路由看到去除应用前缀后的路径。域名绑定应用没有路径前缀；`ApplicationContext` 同时保存原始路径、应用内路径、公开前缀和规范 Host，供 URL 生成使用。

请求体只消费一次。查询、表单、JSON 和 multipart 解析结果保存在当前 Request；超过上限返回 413，非法输入返回 400。上传临时文件和请求作用域资源在结束阶段释放。

## 控制器与结束阶段

字符串路由从目标应用容器创建新的控制器实例，注入该应用 App 和当前 Request，依次执行 `Initialize`、控制器中间件、参数绑定和动作。控制器、验证器及 Scoped 服务不得跨请求共享。

响应发送后由同一应用处理器执行 `Http.End`：触发应用与项目结束事件、运行 terminate、逆序关闭请求资源并保存日志。已经提交响应后发生错误时不会追加第二份错误正文。

路由顺序见[路由匹配](../路由/路由匹配.md)，URL 语义见[URL访问](URL访问.md)。
