# 中间件

中间件是 ThinkGo 的请求横切层，用于在控制器动作前后处理请求编号、语言、Session、CSRF、Trace、认证、审计和响应收尾。中间件可以调用 `next` 继续执行，也可以直接返回响应短路请求。

本章说明中间件在整体架构中的位置；具体中间件 API、配置和安全边界见[中间件章节](../中间件/README.md)。

## 处理器接口

框架统一使用以下处理器签名：

```go
type Handler func(
	request *context.Request,
	next func(*context.Request) *context.Response,
) *context.Response
```

中间件必须返回 `*context.Response`。不调用 `next` 就会阻止后续中间件、路由和控制器动作；短路响应必须设置明确的状态码。下游返回 `nil` 时，调用方不能把它误认为成功响应。

## 请求中的位置

静态资源在动态请求管道之前处理，因此不会经过应用中间件。动态请求的架构顺序为：

```text
请求解析、Host 校验、请求体限制
        ↓
Recovery
        ↓
Session（可选）
        ↓
Trace（可选）
        ↓
CSRF（可选）
        ↓
语言检测
        ↓
应用全局中间件
        ↓
路由匹配
        ↓
路由中间件
        ↓
控制器中间件
        ↓
控制器动作
```

默认全局管道由当前 `framework.App` 初始化阶段装配：Recovery 始终存在；Session、Trace 和全局 CSRF 由配置决定；CSRF 别名可以单独被路由或控制器引用；当前应用 `application.go` 注册的全局中间件最后追加。不同应用的管道互不共享。

## 三种作用域

| 作用域 | 注册方式 | 生效位置 |
|---|---|---|
| 全局中间件 | 当前 `App.RegisterGlobalMiddleware` 或 `Pipeline.Pipe` | 路由匹配前 |
| 路由中间件 | 路由、分组或路由选项 | 路由匹配成功后 |
| 控制器中间件 | 控制器声明别名 | `Init` 后、动作执行前 |

全局中间件适合请求编号、语言和统一异常处理；路由中间件适合一组路由共享的权限或业务前置条件；控制器中间件适合单个控制器或动作的声明式保护。

## 注册和生命周期

应用全局中间件在 `app/<应用名>/application.go` 注册：

```go
func Register(app *framework.App) error {
	return app.RegisterGlobalMiddleware(func(
		request *context.Request,
		next func(*context.Request) *context.Response,
	) *context.Response {
		request.Set("middleware_seen", true)
		return next(request)
	})
}
```

应用中间件包只声明实现，不通过包初始化修改全局中间件表。不要直接维护包级 map 或 slice，也不要假设 `config/middleware.json` 会自动把别名和优先级应用到管道；当前实现要求通过当前 App 的 Pipeline API 显式装配。

中间件拿到下游响应后，如果需要设置响应头，必须先判断响应是否为空。终结逻辑使用 `Lifecycle` 或 `PipeLifecycle`，不要在持有共享锁时回调业务代码。

## 安全边界

- Recovery 负责请求管道中的 panic 转换，业务代码不要依赖 panic 控制正常流程。
- CSRF、认证和授权失败时必须短路，不能继续调用 `next`。
- 需要鉴权的静态资源不能放入 `public/`，因为静态资源不会经过中间件。
- 中间件读取外部输入时必须遵守请求、路径、Cookie、Session 和响应头的安全校验。
- 中间件写入请求上下文使用 `req.Set`，不能把当前请求状态写入单例字段。
