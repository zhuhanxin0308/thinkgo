# 可观测性

ThinkGo 提供默认关闭的进程内 HTTP 指标注册表，不引入 Prometheus、OpenTelemetry 或其它外部依赖。关闭状态不会在请求热路径增加指标计数；只有显式启用后，HTTP 内核才采集请求总数、5xx 数、状态码类别、in-flight 数和固定桶的耗时分布。

## 启用方式

可以在配置中开启：

```json
{
  "metrics_enable": true
}
```

也可以在应用装配阶段显式调用：

```go
metricsRegistry, err := framework.ResolveServiceAs[*metrics.Registry](app, framework.ServiceMetrics)
if err != nil {
	return err
}
metricsRegistry.Enable()
```

环境变量 `APP_METRICS_ENABLE=true` 等价于配置项。指标注册表属于单进程应用实例；多应用模式下每个应用独立统计，不能直接当作整个集群的聚合结果。

## 导出方式

框架不自动占用 `/metrics` 路径，避免破坏现有路由。应用应将导出端点放在认证、内网或网关保护范围内：

```go
router, err := framework.ResolveServiceAs[*route.Router](app, framework.ServiceRoute)
if err != nil {
    return err
}
_, err = router.Get("/metrics", func(*context.Request) *context.Response {
    return context.NewResponse().
        Header("Content-Type", "text/plain; version=0.0.4; charset=utf-8").
        Header("Cache-Control", "no-store").
        Content(metricsRegistry.Prometheus())
})
if err != nil {
    return err
}
```

注册表也实现标准库 `http.Handler`，可在框架外的管理监听器中直接使用：

```go
http.Handle("/metrics", metricsRegistry)
```

指标只使用固定名称和低基数状态类别，不包含 URL、用户 ID、Session ID、IP 或异常文本，避免高基数和敏感信息泄露。生产环境仍应配置采集端认证、网络隔离和保留策略。

## 存活与就绪

每个 `App` 都提供独立的 `Health` 注册表。框架不会自动注册路径，应用可以把存活和就绪处理器挂到受保护的管理路由或独立管理监听器：

```go
import (
    "context"
    "database/sql"
)

var sqlDB *sql.DB

healthRegistry, err := framework.ResolveServiceAs[*health.Registry](app, framework.ServiceHealth)
if err != nil {
    return err
}
if err := healthRegistry.Register("database", func(ctx context.Context) error {
    return sqlDB.PingContext(ctx)
}); err != nil {
    return err
}
_, err = router.Get("/health/live", func(*context.Request) *context.Response {
    report := healthRegistry.Liveness()
    return context.NewResponse().Code(report.HTTPStatus()).Json(report)
})
if err != nil {
    return err
}
```

`Readiness` 使用有界总超时并按名称稳定执行检查；失败响应为 `503`。端点 JSON 只返回 `ok`/`fail` 和耗时，不返回底层错误文本，避免泄露连接串、文件路径和凭据。检查函数必须遵守传入的 `context.Context`，外部依赖不可用时应快速返回。
