# Module 与多应用边界

仓库包含两个 Go Modules，但只发布 `framework`：

```text
根开发宿主 module（不发布）
  ├── app/<name> / config / public / runtime
  ├── main 与 cmd
  └── 本地依赖 framework module

framework module（唯一发布物）
  └── github.com/zhuhanxin0308/thinkgo/framework
```

根模块用于框架开发、生成器、兼容性、端到端和性能测试。根级标签和应用二进制不属于商业发布流程。框架使用 `framework/vX.Y.Z` 仓库标签发布对应 `vX.Y.Z` 模块版本。

## 编译期应用边界

`service:discover` 为每个真实 `app/<name>` 目录生成 `ApplicationDefinition`，并在根清单中稳定排序。每个定义只注册本应用的服务、控制器、模型、验证器、Provider、中间件、事件和路由。

HTTP 内核调用 `BuildApplications` 构造应用实例；存在 `index` 时入口 App 复用为 index，其它应用独立创建并由入口统一关闭。单应用和多应用使用同一 API，不需要额外 Manager 或 Host 类型。

## 请求选择

- `default_app`：无显式前缀时的默认应用。
- `app_map`：把公开路径首段映射到编译期应用。
- `domain_bind`：精确域名、子域名或受控通配域名绑定。
- `deny_app_list`：禁止通过路径访问的应用。
- `app_express`：允许未知首段直接作为默认应用业务路径。
- `Http.Name().Path()`：嵌入式宿主显式绑定已编译应用和自定义真实目录。

解析器拒绝非法类型、未知应用、危险编码、反斜杠、空字节和路径穿越。项目解析规则在应用配置叠加前快照，不能被具体应用污染。

## 模块独立验证

```powershell
$env:GOWORK = "off"

Push-Location framework
try {
    go mod verify
    go build ./...
    go test ./...
} finally {
    Pop-Location
}
```

发布工作流还会从空临时模块通过公开标签获取框架，证明结果不依赖根 `go.work` 或本地 `replace`。
