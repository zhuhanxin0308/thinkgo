# 事件

事件是 ThinkGo 用于解耦生命周期回调和业务扩展的机制。应用通过 `framework.ServiceEvent` 提供 `event.Dispatcher`，Provider、HTTP 内核和业务代码都可以发布事件，监听器和订阅者负责响应事件。

`ServiceEvent` 属于单个应用实例。多应用模式下，`index` 发布的事件不会自动到达 `admin` 的监听器；需要跨应用通知时，应使用明确的消息、服务接口或外部事件通道。

本章说明事件在应用架构中的位置；监听器、订阅者、通配匹配和错误规则见[事件详细用法](../事件/事件.md)。

## 事件生命周期

框架当前提供以下生命周期事件：

| 事件 | 触发时机 |
|---|---|
| `AppInit` | Provider 全部完成 `Register` 后、执行 `Boot` 前 |
| `RouteLoaded` | Provider 全部完成 `Boot` 后 |
| `HttpRun` | 每个 HTTP 请求开始处理时 |
| `HttpEnd` | 每个 HTTP 请求完成收尾时，并携带最终状态码 |

生命周期顺序如下：

```text
应用初始化
  └─ Provider.Register
       └─ AppInit
            └─ Provider.Boot
                 └─ RouteLoaded
                      └─ HTTP 请求
                           ├─ HttpRun
                           └─ HttpEnd
```

Provider 启动、HTTP 请求和关闭过程中的事件错误都会进入对应的启动、响应或关闭错误处理，不应被静默忽略。

## 发布和监听

发布事件：

```go
dispatcher, err := framework.ResolveServiceAs[*event.Dispatcher](app, framework.ServiceEvent)
if err != nil {
	return err
}
if err := dispatcher.Dispatch(event.NewEvent("user.created", userID)); err != nil {
	return err
}
```

注册监听器：

```go
type UserCreatedListener struct{}

func (l *UserCreatedListener) Handle(e event.Event) error {
	// 根据事件数据执行解耦后的扩展逻辑。
	return nil
}

if err := dispatcher.Listen("user.created", &UserCreatedListener{}); err != nil {
	return err
}
```

应用启动时可以在自己的 `application.go` 注册监听器或订阅者：

```go
if err := dispatcher.Listen("user.created", &UserCreatedListener{}); err != nil {
	return err
}
if err := dispatcher.Subscribe(&UserSubscriber{}); err != nil {
	return err
}
```

`Listen`、`Subscribe` 和 `Dispatch` 都返回错误。事件名称、类型化 nil、通配模式、监听器业务错误和回调 panic 都由 Dispatcher 校验或转换为错误；调用方必须处理返回值。

## 订阅和移除

订阅者可以集中注册多个监听器：

```go
type UserSubscriber struct{}

func (s *UserSubscriber) Subscribe(dispatcher *event.Dispatcher) error {
	return dispatcher.Listen("user.created", &UserCreatedListener{})
}

if err := dispatcher.Subscribe(&UserSubscriber{}); err != nil {
	return err
}
```

动态模块卸载时使用 `Forget` 移除事件名或通配模式对应的监听器。事件分发顺序由优先级和注册顺序共同决定，优先级数值越大越先执行。

## 事件与中间件

事件适合广播生命周期或业务事实，中间件适合控制单次请求的前置、后置和短路逻辑：

| 场景 | 推荐机制 |
|---|---|
| 拒绝未认证请求 | 中间件短路 |
| 请求开始和结束观测 | `HttpRun` / `HttpEnd` |
| Provider 启动后的路由扩展 | `RouteLoaded` |
| 用户创建后触发通知 | 业务事件 `user.created` |
| 需要阻止后续请求处理 | 中间件，不使用事件 |

当前 Dispatcher 是同步分发器。监听器中的慢 IO、不可控重试和外部副作用应由业务服务明确编排；不要把事件监听误认为后台队列或事务消息系统。

## 自定义事件

自定义事件只需实现 `Name() string`：

```go
type OrderPaid struct {
	ID int64
}

func (e OrderPaid) Name() string {
	return "order.paid"
}
```

事件数据的生命周期由发布方负责。监听器不能依赖可变的全局事件对象，也不应把请求级对象跨请求保存。完整 API 见[事件详细用法](../事件/事件.md)，应用初始化顺序见[架构总览](架构总览.md)。
