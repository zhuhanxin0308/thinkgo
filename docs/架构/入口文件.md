# 入口文件

入口文件只负责组装应用和宿主，不承担业务路由、控制器动作或中间件实现。ThinkGo 的主要入口包括项目 HTTP 入口、CLI 入口和开发证书工具入口。

## HTTP 入口

项目根目录 `main.go` 导入应用入口包，创建应用管理器和统一 HTTP 宿主：

```go
package main

import (
	"fmt"
	"os"

	_ "thinkgo/app/index" // 登记 index 应用定义
	"thinkgo/framework"
	"thinkgo/framework/http"
)

func main() {
	manager, err := framework.NewApplicationManager("")
	if err != nil {
		fmt.Fprintln(os.Stderr, "application manager initialization failed:", err)
		os.Exit(1)
	}
	host, err := http.NewMultiHttp(manager)
	if err != nil {
		_ = manager.Close()
		fmt.Fprintln(os.Stderr, "HTTP host initialization failed:", err)
		os.Exit(1)
	}
	if err := host.Run(); err != nil {
		fmt.Fprintln(os.Stderr, "HTTP host exited with error:", err)
		os.Exit(1)
	}
}
```

对容器编排或嵌入式宿主，推荐使用可取消的 `RunContext(ctx)`：它会把上下文传递到 HTTP/TLS/HTTP3 监听器，取消后按 `shutdown_timeout_ms` 执行优雅关闭，并继续由 `ApplicationManager` 负责应用逆序回收。原有 `Run()` 仍保留信号驱动的兼容入口。

```go
import (
	"context"
	"errors"
	"os"
	"os/signal"
	"syscall"
)

ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()
if err := host.RunContext(ctx); err != nil && !errors.Is(err, context.Canceled) {
	// 记录启动、监听或优雅关闭错误
}
```

`NewApplicationManager` 会加载所有编译期登记的应用。`NewMultiHttp` 会为每个应用创建内部处理器，但只保留一份监听配置。`host.Run()` 负责启动全部应用、冻结路由、监听 HTTP/TLS/HTTP3 并在退出时关闭管理器。

应用入口包的 `init()` 只登记 `ApplicationDefinition`，组件注册放在应用自己的 `Register(app)` 函数中：

```go
func init() {
	framework.MustRegisterApplication(framework.ApplicationDefinition{
		Name: "index", Path: "app/index", Register: Register,
	})
}
```

不要在根入口中分别导入应用组件包或根级路由包；这些组件必须从 `app/<应用名>/application.go` 进入所属应用实例。

## 增加应用入口包

新增应用时，目录和注册入口保持 ThinkPHP 多应用风格：

```text
app/admin/
├── application.go
├── controller/
├── middleware/
├── model/
├── validate/
├── lang/
└── route/
```

`application.go` 使用传入的 `*framework.App` 注册本应用组件。应用之间不能复用控制器注册表、路由器、中间件管道或事件分发器。

## 命令行入口

`cmd/think/main.go` 创建 `ApplicationManager` 和 `console.NewConsoleWithManager`，内置命令通过 `--app <name>` 选择目标应用：

```text
think run --app admin --port 9000
think route:list --app admin
think config:dump --app admin app
think clear --app admin
think make:controller Account --app admin
think make:model UserProfile --app admin
```

`run` 使用统一 `MultiHttp` 宿主，不能为每个应用分别启动端口。`make:*` 命令把生成文件写入目标应用目录，并更新该应用的 `application.go` 注册入口；未指定 `--app` 时使用 `default_app` 或 `index`。

需要数据库的 `run` 命令使用完整初始化；`version`、`list`、`clear`、`config:dump`、`route:list` 和 `make:*` 使用跳过数据库连接的控制台初始化，但仍会创建全部应用实例以保证配置和目录边界一致。

## 开发证书入口

`cmd/cert/main.go` 只负责生成本地开发证书：

```bash
go run cmd/cert/main.go
```

目标文件为 `runtime/cert.pem` 和 `runtime/key.pem`。它不创建应用实例，也不参与 HTTP 宿主生命周期。

## 入口职责边界

- 入口文件：解析错误、创建管理器、创建宿主、处理退出码。
- `application.go`：注册所属应用组件和 Provider。
- `framework.ApplicationManager`：管理所有应用的初始化、启动和关闭。
- `framework/http.MultiHttp`：统一监听并把请求分发给目标应用。
- 控制器、服务、模型和路由包：只实现业务能力，不读取进程级 `os.Args` 或自行启动监听器。

完整顺序见[请求流程](请求流程.md)，目录边界见[基础目录结构](../基础/目录结构.md)。
