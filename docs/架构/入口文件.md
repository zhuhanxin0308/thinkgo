# 入口文件

入口只负责项目组合、错误、退出码和资源关闭，不承载业务路由或应用选择算法。

## HTTP 入口

根 `main.go` 调用同包 `runHTTP`。必须使用 `go run .` 运行整个根包。装配顺序：

1. 注册宿主需要的数据库连接器。
2. 创建未初始化的项目 `framework.App`。
3. 调用顶层 `app.Register(application)` 注册项目定义和全部编译期应用。
4. 创建唯一 `http.Http`，不创建额外 Manager 或多应用 Host API。
5. 调用 `Http.Listen`；内核负责初始化全部应用、冻结路由和开始监听。
6. 监听退出后关闭项目 App，并合并运行和关闭错误。

构造或启动失败会关闭已创建资源，不返回可继续服务的半成品。

## 自动发现边界

根入口只导入顶层 `app`。`app/autoload_generated.go` 引用每个 `app/<name>.Definition()`；每个应用清单再静态引用自己的控制器、模型、验证器和路由。

```bash
go run ./cmd/think make:app admin
go run ./cmd/think service:discover
```

发现命令扫描真实 `app/<name>`，拒绝遗留扁平业务目录和非法包名。开发者不编辑生成文件。

## CLI 入口

`cmd/think` 使用相同项目清单创建控制台入口 App。代码生成与帮助命令不强制连接数据库；路由、配置、迁移和部署命令通过 `--app` 初始化目标编译期应用。`deploy:check` 默认初始化并审计全部应用。

`framework/cmd/thinkgo` 是框架模块内可安装的独立入口，与项目入口共用 `console/launcher`。`create` 不依赖已有项目配置；`build` 只编译源码与打包资源，不初始化业务服务。需要应用运行时的命令仍由项目 `cmd/think` 的 `thinkgo_runtime` 入口注册实际业务。

## 发布边界

- 根 `main.go`、`cmd/think` 和示例 `app`：开发与验证宿主，不发布。
- `framework/`：唯一公共模块，不导入宿主业务。
- `.github/workflows/framework-release.yml`：唯一 Release 工作流，只响应 `framework/vX.Y.Z`。

完整顺序见[请求流程](请求流程.md)，目录边界见[基础目录结构](../基础/目录结构.md)。
