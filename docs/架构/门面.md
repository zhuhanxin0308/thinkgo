# 应用能力入口

普通业务代码不需要解析容器服务名。`framework.App` 直接提供与 ThinkPHP 常用应用能力同名的访问方法：

| 能力 | 业务 API |
|---|---|
| 配置、环境变量 | `app.Config()`、`app.Env()` |
| 路由、中间件 | `app.Route()`、`app.Middleware()` |
| 日志、事件 | `app.Log()`、`app.Event()` |
| 缓存、文件系统 | `app.Cache()`、`app.Filesystem()` |
| 数据库 | `app.DB()`、`app.DBManager()` |
| 视图、多语言 | `app.View()`、`app.Lang()` |
| Cookie、Session | `app.Cookie()`、`app.Session()` |
| 容器 | `app.Bind()`、`app.Instance()`、`app.Make()` |

这些对象都属于当前应用实例，不能跨应用缓存或复用。项目入口关闭时，框架按逆序释放各应用对象。

## 控制器中使用

嵌入 `BaseController` 后，可以直接通过当前控制器的 `App` 和 `Request` 访问能力：

```go
func (controller *User) Index() *framework.Response {
	users, err := controller.App.DB().Name("users").Select()
	if err != nil {
		return controller.Error("读取用户失败")
	}

	controller.App.Log().Info("读取用户列表")
	return controller.Success(users)
}
```

请求级语言、Cookie 和 Session 必须来自当前请求或控制器，不应保存到包级变量。

## 服务中使用

应用服务嵌入 `framework.Service` 后，通过 `service.App()` 访问当前应用：

```go
type UserService struct {
	framework.Service
}

func (service *UserService) Boot() error {
	service.App().Log().Info("用户服务已启动")
	return nil
}
```

长期业务依赖仍可以通过构造函数注入，方便单元测试；这不要求业务代码理解底层 Provider 或容器实现。

## 配置与数据库

```go
debug := app.Config().GetBool("app.app_debug", false)
database := app.DB()
rows, err := database.Name("users").Where("status = ?", 1).Select()
```

数据库使用 lazy 连接：应用初始化不会要求普通页面立即建立数据库连接，首次调用 `app.DB()` 或数据库查询时才创建默认连接。

## 路由与 URL

业务路由文件直接接收 `*framework.Route`：

```go
func Load(Route *framework.Route) {
	Route.Get("users/:id", "user/read").
		Name("users.read").
		Pattern(map[string]string{"id": `\d+`})
}
```

命名路由路径通过 `app.Route().URL` 生成；完整应用 URL 使用 `app.RouteURL` 或 `app.URL`。传入请求时，框架从 `ApplicationContext` 恢复当前应用的域名绑定或公开路径前缀；跨应用跳转必须显式取得目标应用上下文，不能修改共享“当前应用”。

## 底层扩展

`framework.ResolveServiceAs` 和 `ServiceConfig`、`ServiceDB` 等服务名保留给框架扩展、替换驱动和基础设施测试。普通控制器、服务、模型和命令优先使用上面的直接 API。
