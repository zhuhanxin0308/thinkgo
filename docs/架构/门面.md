# 门面

ThinkPHP 的 Facade 通常用静态入口代理容器服务。ThinkGo 不提供静态 Facade 注册表，也不把容器托管的服务作为 `framework.App` 的公开字段；应用能力通过显式构造入口、服务解析和构造函数依赖注入访问。

## 应用构造边界

应用有两类明确的构造方式：

```go
// 严格构造：初始化失败时只返回 error，不返回半初始化应用。
app, err := framework.BuildApp(basePath)
if err != nil {
	return err
}
defer app.Close()

// 控制台构造：与 BuildApp 相同，但跳过数据库连接初始化。
consoleApp, err := framework.BuildConsoleApp(basePath)
if err != nil {
	return err
}
defer consoleApp.Close()
```

需要在初始化前注册 Provider、控制器或路由时，使用显式未初始化入口，并由调用方检查初始化结果：

```go
app := framework.NewAppUninitialized(basePath)
defer app.Close()

if err := registerApplication(app); err != nil {
	return err
}
if err := app.Initialize(); err != nil {
	return err
}
```

`NewConsoleAppUninitialized` 只适用于需要在初始化前装配控制台应用的场景。旧的自动初始化构造别名不再提供；新代码必须在严格构造和显式未初始化构造之间作出选择。

## 应用能力入口

`framework.App` 是应用组合根，但容器托管的运行时服务保持私有。外部代码通过稳定的服务名称和类型解析获取能力：

| 能力 | 服务名称 |
|---|---|
| 配置和环境 | `framework.ServiceConfig`、`framework.ServiceEnv` |
| 日志 | `framework.ServiceLog` |
| 缓存 | `framework.ServiceCache` |
| 事件 | `framework.ServiceEvent` |
| 数据库 | `framework.ServiceDB`、`framework.ServiceDBManager` |
| 路由和中间件 | `framework.ServiceRoute`、`framework.ServiceMiddleware` |
| 视图和语言 | `framework.ServiceView`、`framework.ServiceLang` |
| Cookie 和 Session | `framework.ServiceCookie`、`framework.ServiceSession` |
| 指标和健康检查 | `framework.ServiceMetrics`、`framework.ServiceHealth` |
| URL | `app.Domain()`、`app.URL()`、`app.AssetURL()`、`app.URLFor()` |
| 容器操作 | `app.Bind()`、`app.BindFactory()`、`app.Instance()`、`app.Make()` |

按类型解析服务：

```go
logger, err := framework.ResolveServiceAs[*log.Log](app, framework.ServiceLog)
if err != nil {
	return err
}
logger.Info("读取用户列表")

database, err := framework.ResolveServiceAs[*db.DB](app, framework.ServiceDB)
if err != nil {
	return err
}
users, err := database.Name("users").Select()
```

`ResolveServiceAs` 会同时检查服务名称和目标类型；解析失败必须向启动层或业务层返回明确错误。需要自定义实现时，应通过 `app.Instance(string(framework.ServiceLog), logger)` 或 Provider 装配，不能重新暴露一个公共字段。

## 控制器和请求级能力

控制器可以访问当前应用的 URL 方法以及请求级便捷能力，但不应把共享服务复制成包级变量：

```go
func (c *User) Index() *context.Response {
	loginURL := c.App.URLFor(c.Request, "/login")
	return context.NewResponse().JSON(map[string]interface{}{
		"login_url": loginURL,
	})
}
```

控制器中的数据库、日志、缓存等长期依赖应通过构造函数或 Provider 注入。请求级语言、缓存调试信息、Session 和 Cookie 应从当前请求或控制器便捷方法读取，不写入应用级共享对象。

多应用请求中，URL 生成应携带当前请求对象，以恢复路径应用前缀或使用域名绑定：

```go
loginURL := c.App.URLFor(c.Request, "/login")
adminURL, err := c.App.URLForApplication(c.Request, "admin", "/dashboard")
```

跨应用 URL 只使用目标应用的解析作用域，不会把目标应用的容器或请求状态暴露给当前应用。

## 服务中的显式依赖

业务服务优先通过构造函数接收需要的能力：

```go
type AuditService struct {
	log *log.Log
}

func NewAuditService(logger *log.Log) *AuditService {
	return &AuditService{log: logger}
}

func (s *AuditService) Record(message string) {
	s.log.Info(message)
}
```

Provider 可以解析服务并把构造函数绑定到容器：

```go
func (p *AuditProvider) Register(app *framework.App) error {
	return app.Bind("audit.service", func() (interface{}, error) {
		logger, err := framework.ResolveServiceAs[*log.Log](app, framework.ServiceLog)
		if err != nil {
			return nil, err
		}
		return NewAuditService(logger), nil
	})
}
```

当服务需要更小的依赖面时，应定义接口并通过工厂注入接口实现，而不是在每个方法里从容器按字符串查找多个全局服务。

## 与 Facade 的边界

以下方式不属于 ThinkGo 的推荐用法：

- 自行创建包级 `var DB`、`var Cache` 或 `var CurrentApp` 作为静态代理。
- 用全局函数隐藏请求级状态或当前应用实例。
- 在业务方法中随意调用 `app.Get()`，让字符串名称取代构造函数契约。
- 为了模仿 ThinkPHP Facade，新增一套静态服务代理而不定义生命周期和并发边界。

容器本身支持 `Bind`、`BindFactory` 和 `Instance`，但它是应用组合机制，不是对外暴露的静态 Facade。应用关闭时由 Provider 负责释放其托管资源；替换缓存、数据库或日志实例后，应用仍会在 `Close` 阶段处理原实例和当前实例的关闭，业务代码不应在请求期间关闭共享服务。

## 从 ThinkPHP 迁移

迁移使用 Facade 的代码时按以下方式转换：

1. 将静态 Facade 依赖列为服务或控制器的构造函数依赖。
2. 由 Provider 在 `Register` 阶段绑定具体实现。
3. 将请求级数据放在请求对象或显式参数中，不放入应用单例。
4. 将全局 Facade 的测试替换为独立依赖的单元测试和应用集成测试。

这种方式保留了应用能力的集中装配，同时让依赖、生命周期和初始化错误保持可见。
